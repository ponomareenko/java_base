# Тема 3: Переменные многопоточной программы

## Разделяемое изменяемое состояние

**Определение:**

Разделяемое изменяемое состояние (shared mutable state) — это данные, к которым обращаются несколько потоков и которые хотя бы один поток может изменить.

Именно такие данные требуют синхронизации. Если объект не изменяется или доступен только одному потоку, защищать его от одновременного изменения не нужно.

**Пример:**

```java
public class Counter {
    private int value;

    public void increment() {
        value++;
    }
}
```

Поле `value` становится разделяемым изменяемым состоянием, если один экземпляр `Counter` используют несколько потоков.

---

## Видимость изменений

**Определение:**

Видимость изменений (memory visibility) — это гарантия того, что результат записи, выполненной одним потоком, станет виден другому потоку.

Без корректной синхронизации один поток может продолжать наблюдать старое значение переменной. Причина не сводится только к кэшу процессора: на результат также влияют оптимизации JVM, компилятора и допустимое переупорядочивание операций.

---

## `volatile`

**Определение:**

`volatile` — модификатор поля, который обеспечивает видимость его изменений между потоками и задаёт необходимые ограничения на переупорядочивание операций.

Запись в `volatile`-поле **happens-before** последующего чтения этого же поля. Поэтому поток, прочитавший новое значение, увидит также изменения, выполненные другим потоком перед записью в это поле.

**Пример:**

```java
public class Worker {
    private volatile boolean stopRequested;

    public void run() {
        while (!stopRequested) {
            // Выполнение работы
        }
    }

    public void stop() {
        stopRequested = true;
    }
}
```

Здесь `volatile` подходит, потому что одна операция записывает флаг, а другая только читает его.

**Важно:**

`volatile` не делает составные операции атомарными:

```java
private volatile int counter;

public void increment() {
    counter++; // Всё ещё небезопасно
}
```

Операция `counter++` состоит из чтения, прибавления единицы и записи. Потоки могут вклиниться между этими действиями и потерять часть обновлений.

---

## Атомарная операция

**Определение:**

Атомарная операция — это операция, которая с точки зрения других потоков выполняется как одно неделимое действие: другой поток не может увидеть её промежуточное состояние.

Простое присваивание и `counter++` — не одно и то же. Например, увеличение счётчика является составной операцией:

```java
int currentValue = counter; // чтение
int newValue = currentValue + 1; // вычисление
counter = newValue; // запись
```

Для атомарного увеличения можно использовать `AtomicInteger`:

```java
private final AtomicInteger counter = new AtomicInteger();

public void increment() {
    counter.incrementAndGet();
}
```

---

## Состояние гонки

**Определение:**

Состояние гонки (race condition) — это ошибка, при которой результат программы зависит от непредсказуемого порядка выполнения потоков.

**Пример:**

Если два потока одновременно выполняют `counter++`, оба могут прочитать значение `10`, вычислить `11` и записать `11`. Одно увеличение будет потеряно, хотя ожидалось значение `12`.

В продакшене такие ошибки особенно опасны: они могут редко проявляться на локальной машине и возникать только под нагрузкой.

---

## Happens-before

**Определение:**

Happens-before — отношение между действиями, которое гарантирует их порядок и видимость результатов в Java Memory Model.

Если действие A happens-before действия B, то изменения, выполненные в A, должны быть видны при выполнении B.

Примеры таких гарантий:

* запись в `volatile`-поле happens-before последующего чтения этого поля;
* вызов `thread.start()` happens-before действия внутри запущенного потока;
* действия потока happens-before успешного завершения `thread.join()` в другом потоке;
* освобождение монитора happens-before последующего захвата того же монитора.

Happens-before — это не утверждение о времени на часах. Это гарантия модели памяти, позволяющая безопасно рассуждать о взаимодействии потоков.

---

## Атомарные классы

**Определение:**

Атомарные классы — это классы пакета `java.util.concurrent.atomic`, которые позволяют потокобезопасно изменять одну переменную без явного использования `synchronized`.

Основные классы:

* `AtomicBoolean` — атомарное значение `boolean`;
* `AtomicInteger` — атомарное значение `int`;
* `AtomicLong` — атомарное значение `long`;
* `AtomicReference<T>` — атомарная ссылка на объект.

**Пример:**

```java
public class RequestCounter {
    private final AtomicLong requestCount = new AtomicLong();

    public long incrementAndGet() {
        return requestCount.incrementAndGet();
    }

    public long getCurrentValue() {
        return requestCount.get();
    }
}
```

`AtomicLong` защищает отдельные операции со значением. Он не делает автоматически потокобезопасной всю бизнес-операцию, если она затрагивает несколько полей или должна проверять несколько условий.

---

## Основные методы атомарных классов

| Метод | Что делает | Что возвращает |
|---|---|---|
| `get()` | Читает текущее значение | Текущее значение |
| `set(value)` | Устанавливает новое значение | Ничего |
| `getAndSet(value)` | Заменяет значение | Старое значение |
| `compareAndSet(expected, update)` | Заменяет значение, только если оно равно ожидаемому | Успешность замены |
| `getAndIncrement()` | Увеличивает на единицу | Старое значение |
| `incrementAndGet()` | Увеличивает на единицу | Новое значение |
| `getAndDecrement()` | Уменьшает на единицу | Старое значение |
| `decrementAndGet()` | Уменьшает на единицу | Новое значение |
| `getAndAdd(delta)` | Прибавляет `delta` | Старое значение |
| `addAndGet(delta)` | Прибавляет `delta` | Новое значение |

**Пример различия между `getAndIncrement()` и `incrementAndGet()`:**

```java
AtomicInteger counter = new AtomicInteger(10);

int oldValue = counter.getAndIncrement(); // 10, внутри уже 11
int newValue = counter.incrementAndGet(); // внутри 12, возвращается 12
```

## Compare-and-set (CAS)

**Определение:**

Compare-and-set, или CAS, — атомарная операция вида: «если текущее значение равно ожидаемому, замени его новым».

Метод `compareAndSet(expectedValue, newValue)` возвращает `true`, если замена произошла, и `false`, если другой поток успел изменить значение.

**Пример:**

```java
AtomicInteger status = new AtomicInteger(0);

boolean started = status.compareAndSet(0, 1);

if (started) {
    System.out.println("Задача запущена");
}
```

CAS часто лежит в основе неблокирующих алгоритмов. При сложном обновлении операцию обычно повторяют в цикле, потому что другой поток может изменить значение между чтением и попыткой записи.

---

## Lock-free алгоритм

**Определение:**

Lock-free алгоритм — алгоритм, в котором потоки координируют изменения без взаимной блокировки через обычный lock или `synchronized`.

Атомарные классы часто используют CAS и позволяют строить lock-free операции. Это не означает, что каждый отдельный поток обязательно завершит действие без повторных попыток, но система в целом продолжает двигаться вперёд.

Lock-free код не всегда лучше блокировок: сложные зависимости между несколькими значениями обычно проще и безопаснее выразить через блокировку или более высокоуровневую структуру данных.

---

## Конкуренция потоков

**Определение:**

Конкуренция потоков (contention) — ситуация, когда несколько потоков одновременно пытаются изменить один ресурс и мешают друг другу.

Например, при частом обновлении одного `AtomicLong` множество потоков конкурируют за одно значение. Неудачные CAS-операции приходится повторять, что снижает производительность.

---

## `LongAdder`

**Определение:**

`LongAdder` — потокобезопасный накопитель суммы, оптимизированный для большого количества конкурентных обновлений.

При высокой конкуренции он распределяет обновления между несколькими внутренними ячейками. Метод `sum()` объединяет их и возвращает результат.

**Пример:**

```java
public class Statistics {
    private final LongAdder requestCount = new LongAdder();

    public void registerRequest() {
        requestCount.increment();
    }

    public long getRequestCount() {
        return requestCount.sum();
    }
}
```

`LongAdder` хорошо подходит для метрик и статистики, когда обновлений много, а чтение выполняется реже.

**Важно:**

`sum()` не является атомарным снимком во время конкурентных обновлений. Поэтому `LongAdder` не подходит для баланса счёта или другого значения, для которого каждое чтение должно быть точным и согласованным.

В стандартной библиотеке нет класса `AtomicAdder`. В презентации под этим названием описан `LongAdder`. Также существует `DoubleAdder`.

---

## `AtomicLong` и `LongAdder`

| Критерий | `AtomicLong` | `LongAdder` |
|---|---|---|
| Хранение | Одно значение | Несколько внутренних значений |
| Точное чтение текущего значения | Да | Не гарантируется как атомарный снимок при обновлениях |
| CAS | Поддерживается | Не предназначен для CAS |
| Производительность при частых конкурентных обновлениях | Может снижаться из-за конкуренции | Обычно выше |
| Типичное применение | Последовательность, состояние, точный счётчик | Метрики и статистика |

## Задание 1

Объясни, почему следующий код может вывести значение меньше `2_000_000`, даже несмотря на `volatile`:

```java
private static volatile int counter;

public static void main(String[] args) throws InterruptedException {
    Thread first = new Thread(() -> {
        for (int i = 0; i < 1_000_000; i++) {
            counter++;
        }
    });

    Thread second = new Thread(() -> {
        for (int i = 0; i < 1_000_000; i++) {
            counter++;
        }
    });

    first.start();
    second.start();
    first.join();
    second.join();

    System.out.println(counter);
}
```

Исправь программу с помощью `AtomicInteger`.
