# Знакомство с Git

## 1. Система контроля версий

**Определение**
Система контроля версий — это инструмент, который хранит историю изменений проекта и позволяет вернуться к предыдущему состоянию файлов.

**Пример**

```text
Ты написал код, потом сломал программу.
Система контроля версий позволяет откатиться к рабочей версии.
```

---

## 2. СКВ

**Определение**
СКВ — сокращение от «система контроля версий».

**Пример**

```text
Git — это СКВ.
То есть программа для отслеживания изменений в проекте.
```

---

## 3. Git

**Определение**
Git — это самая популярная система контроля версий, которая используется для хранения истории изменений, командной работы и управления версиями проекта.

**Пример**

```bash
git --version
```

Эта команда показывает установленную версию Git.

---

## 4. Версия файла

**Определение**
Версия файла — это конкретное состояние файла в определённый момент времени.

**Пример**

```text
index.html утром содержал один код.
Вечером ты добавил новую секцию.
Это уже новая версия файла.
```

---

## 5. Актуальная версия файла

**Определение**
Актуальная версия файла — это последняя, самая свежая версия файла, с которой сейчас работает команда или разработчик.

**Пример**

```text
В проекте есть файл Main.java.
Если другой разработчик внёс изменения, тебе нужно получить актуальную версию.
```

---

## 6. История изменений

**Определение**
История изменений — это список всех изменений, которые происходили с файлами проекта: кто, когда и что изменил.

**Пример**

```text
Разработчик удалил метод.
Через историю изменений можно увидеть, кто это сделал и когда.
```

---

## 7. Командная работа

**Определение**
Командная работа — это процесс, когда несколько разработчиков одновременно работают над одним проектом.

**Пример**

```text
Один разработчик делает авторизацию.
Второй — личный кабинет.
Третий — оплату.
Git помогает объединять их изменения.
```

---

## 8. Параллельное развитие проекта

**Определение**
Параллельное развитие проекта — это ситуация, когда разные части проекта разрабатываются одновременно и независимо друг от друга.

**Пример**

```text
Одна версия проекта остаётся стабильной.
Во второй версии разработчик пробует новую функцию.
Если функция работает — её добавляют в основной проект.
```

---

## 9. Копирование проекта

**Определение**
Копирование проекта — это создание своей копии проекта, чтобы работать с ней отдельно от основной версии.

**Пример**

```text
Ты копируешь проект с GitHub себе на компьютер
и работаешь с ним локально.
```

---

## 10. Публичный проект

**Определение**
Публичный проект — это проект, доступный другим пользователям для просмотра.

**Пример**

```text
Ты выкладываешь учебные Java-задачи на GitHub.
Работодатель может открыть репозиторий и посмотреть твой код.
```

---

## 11. Приватный проект

**Определение**
Приватный проект — это проект, доступ к которому есть только у выбранных людей.

**Пример**

```text
Коммерческий проект компании обычно закрыт от посторонних.
Доступ имеют только сотрудники команды.
```

---

## 12. GitHub

**Определение**
GitHub — это онлайн-платформа для хранения Git-проектов, командной работы и демонстрации кода.

**Пример**

```text
Git работает на компьютере.
GitHub хранит проект в интернете.
```

---

## 13. Портфолио разработчика

**Определение**
Портфолио разработчика — это набор проектов, по которым можно оценить навыки программиста.

**Пример**

```text
На GitHub можно хранить учебные проекты,
Java-задачи, pet-проекты и конспекты.
```

---

## 14. Репозиторий

**Определение**
Репозиторий — это хранилище проекта, в котором находятся файлы и история их изменений.

**Пример**

```text
Проект learning-java на GitHub — это репозиторий.
Внутри него могут быть папки, файлы и история изменений.
```

---

## 15. Файл

**Определение**
Файл — это единица хранения информации на компьютере: код, текст, изображение, настройки и так далее.

**Пример**

```text
Main.java — файл с Java-кодом.
README.md — файл с описанием проекта.
```

---

## 16. Папка

**Определение**
Папка — это контейнер для хранения файлов и других папок.

**Пример**

```text
src — папка, где обычно лежит исходный код Java-проекта.
```

---

## 17. Скрытые файлы и папки

**Определение**
Скрытые файлы и папки — это элементы файловой системы, которые не отображаются по умолчанию.

**Пример**

```text
.git — скрытая папка Git.
В ней хранится служебная информация репозитория.
```

---

## 18. Расширение файла

**Определение**
Расширение файла — это часть имени файла после точки, которая показывает тип файла.

**Пример**

```text
Main.java
README.md
image.png
```

Здесь `.java`, `.md`, `.png` — расширения файлов.

---

## 19. Visual Studio Code

**Определение**
Visual Studio Code, или VS Code, — это редактор кода, в котором можно писать программы и работать с файлами проекта.

**Пример**

```text
В VS Code можно открыть папку проекта
и редактировать Java-файлы, Markdown-файлы и настройки.
```

---

## 20. Редактор кода

**Определение**
Редактор кода — это программа для написания и редактирования исходного кода.

**Пример**

```text
VS Code, IntelliJ IDEA, Eclipse — это редакторы или IDE для работы с кодом.
```

---

## 21. Markdown

**Определение**
Markdown — это простой язык разметки для оформления текстовых документов.

**Пример**

```markdown
# Заголовок

Это обычный текст.

- Первый пункт
- Второй пункт
```

---

## 22. `.md`

**Определение**
`.md` — это расширение файлов Markdown.

**Пример**

```text
README.md
git_dictionary.md
java_terms.md
```

---

## 23. Заголовок в Markdown

**Определение**
Заголовок в Markdown создаётся с помощью символа `#`. Чем больше символов `#`, тем ниже уровень заголовка.

**Пример**

```markdown
# Главный заголовок

## Подзаголовок

### Заголовок третьего уровня
```

---

## 24. Ссылка в Markdown

**Определение**
Ссылка в Markdown — это текст, который ведёт на другой ресурс.

**Пример**

```markdown
[GitHub](https://github.com)
```

---

## 25. Картинка в Markdown

**Определение**
Картинка в Markdown вставляется почти как ссылка, но перед квадратными скобками ставится `!`.

**Пример**

```markdown
![Описание картинки](image.png)
```

---

## 26. Список в Markdown

**Определение**
Список в Markdown — это способ оформить перечисление элементов.

**Пример**

Маркированный список:

```markdown
- Git
- Java
- GitHub
```

Нумерованный список:

```markdown
1. Установить Git
2. Настроить имя
3. Настроить email
```

---

## 27. Плагин

**Определение**
Плагин — это дополнение к программе, которое расширяет её возможности.

**Пример**

```text
Markdown All in One — плагин для VS Code,
который помогает удобнее работать с Markdown.
```

---

## 28. Extension

**Определение**
Extension — это расширение или плагин в редакторе кода.

**Пример**

```text
В VS Code раздел Extensions используется для установки плагинов.
```

---

## 29. Командная строка

**Определение**
Командная строка — это интерфейс для управления компьютером с помощью текстовых команд.

**Пример**

```bash
git --version
```

Команда вводится текстом, а компьютер выполняет действие.

---

## 30. Терминал

**Определение**
Терминал — это программа, через которую пользователь работает с командной строкой.

**Пример**

```text
На macOS используется Terminal.
На Windows часто используют Git Bash.
На Linux терминал можно открыть через Ctrl + Alt + T.
```

---

## 31. Git Bash

**Определение**
Git Bash — это терминал для Windows, который устанавливается вместе с Git и позволяет выполнять Git-команды.

**Пример**

```bash
git --version
```

---

## 32. Команда

**Определение**
Команда — это текстовая инструкция, которую пользователь вводит в терминал.

**Пример**

```bash
git --version
```

Эта команда просит Git показать его версию.

---

## 33. `git --version`

**Определение**
`git --version` — команда для проверки установленной версии Git.

**Пример**

```bash
git --version
```

Пример результата:

```bash
git version 2.54.0
```

---

## 34. Глобальные настройки Git

**Определение**
Глобальные настройки Git — это настройки, которые применяются ко всем Git-проектам пользователя на компьютере.

**Пример**

```bash
git config --global user.name "Danil Ponomarenko"
git config --global user.email "el.pochtadp@gmail.com"
```

---

## 35. `git config`

**Определение**
`git config` — команда для настройки параметров Git.

**Пример**

```bash
git config --global user.name "Danil Ponomarenko"
```

Эта команда задаёт имя пользователя в Git.

---

## 36. `--global`

**Определение**
`--global` — параметр команды Git, который означает, что настройка применяется ко всем репозиториям пользователя.

**Пример**

```bash
git config --global user.email "el.pochtadp@gmail.com"
```

Email будет использоваться во всех Git-проектах на этом компьютере.

---

## 37. `user.name`

**Определение**
`user.name` — настройка Git, в которой хранится имя автора изменений.

**Пример**

```bash
git config --global user.name "Danil Ponomarenko"
```

---

## 38. `user.email`

**Определение**
`user.email` — настройка Git, в которой хранится email автора изменений.

**Пример**

```bash
git config --global user.email "el.pochtadp@gmail.com"
```

---

## 39. Автор изменений

**Определение**
Автор изменений — это пользователь, чьим именем и email подписываются изменения в Git.

**Пример**

```text
Если ты сделал изменение в проекте,
Git запомнит, что автор — Danil Ponomarenko.
```

---

## 40. `git config --global --list`

**Определение**
`git config --global --list` — команда, которая показывает список глобальных настроек Git.

**Пример**

```bash
git config --global --list
```

Пример результата:

```bash
user.name=Danil Ponomarenko
user.email=el.pochtadp@gmail.com
init.defaultbranch=main
```

---

## 41. Окончание строк

**Определение**
Окончание строк — это невидимые символы, которые обозначают конец строки в файле.

**Пример**

```text
Windows и macOS/Linux могут по-разному хранить окончания строк.
Из-за этого в Git иногда появляются лишние изменения.
```

---

## 42. `core.autocrlf`

**Определение**
`core.autocrlf` — настройка Git, которая управляет преобразованием окончаний строк между Windows, macOS и Linux.

**Пример для macOS/Linux**

```bash
git config --global core.autocrlf input
```

**Пример для Windows**

```bash
git config --global core.autocrlf true
```

---

## 43. `core.safecrlf`

**Определение**
`core.safecrlf` — настройка Git, которая предупреждает о возможных проблемах с окончаниями строк.

**Пример**

```bash
git config --global core.safecrlf warn
```

---

## 44. `core.quotepath`

**Определение**
`core.quotepath` — настройка Git, которая влияет на отображение путей к файлам, особенно если в названиях есть кириллица.

**Пример**

```bash
git config --global core.quotepath off
```

Эта настройка помогает избежать нечитаемых названий файлов в неправильной кодировке.

---

## 45. Ветка

**Определение**
Ветка — это отдельная линия разработки проекта.

**Пример**

```text
main — основная ветка проекта.
feature-login — ветка для разработки авторизации.
```

---

## 46. Основная ветка

**Определение**
Основная ветка — это главная ветка репозитория, где обычно хранится стабильная версия проекта.

**Пример**

```text
main — общепринятое название основной ветки.
```

---

## 47. `main`

**Определение**
`main` — современное стандартное название основной ветки в Git-репозитории.

**Пример**

```bash
git config --global init.defaultBranch main
```

---

## 48. `init.defaultBranch`

**Определение**
`init.defaultBranch` — настройка Git, которая задаёт имя основной ветки при создании нового репозитория.

**Пример**

```bash
git config --global init.defaultBranch main
```

---

## 49. Справка Git

**Определение**
Справка Git — это встроенная документация, которая помогает узнать доступные команды и их использование.

**Пример**

```bash
git help -g
```

Показывает список доступных руководств Git.

---

## 50. `git help`

**Определение**
`git help` — команда для открытия справки по Git.

**Пример**

```bash
git help config
```

Откроет справку по команде `config`.

---

# Коротко: что нужно запомнить

```text
Git — это система контроля версий.
Система контроля версий хранит историю изменений проекта.
GitHub — это платформа для хранения Git-проектов в интернете.
Терминал — место, где вводят команды.
Markdown — удобный формат для конспектов и README-файлов.
Глобальные настройки Git задаются через git config --global.
Основная ветка современного репозитория обычно называется main.
```
