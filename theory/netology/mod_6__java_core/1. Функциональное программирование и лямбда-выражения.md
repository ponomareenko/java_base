# Тема 1: Функциональное программирование и лямбда-выражения

## Функциональное программирование

**Определение:**

Функциональное программирование — это подход к написанию кода, при котором программа строится вокруг функций, а не вокруг изменения состояния объектов.

В Java функциональное программирование используется частично: через лямбда-выражения, функциональные интерфейсы, Stream API и ссылки на методы.

**Пример:**

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

List<Integer> squares = numbers.stream()
        .map(number -> number * number)
        .toList();

System.out.println(squares); // [1, 4, 9, 16, 25]
```

---

## Императивное программирование

**Определение:**

Императивное программирование — это стиль программирования, при котором разработчик подробно описывает, какие команды и в каком порядке должна выполнить программа.

Главная идея: мы говорим программе, **как именно** получить результат.

**Пример:**

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);
List<Integer> result = new ArrayList<>();

for (Integer number : numbers) {
    if (number % 2 == 0) {
        result.add(number * 2);
    }
}

System.out.println(result); // [4, 8]
```

---

## Декларативное программирование

**Определение:**

Декларативное программирование — это стиль программирования, при котором разработчик описывает, **что нужно получить**, а не расписывает каждый шаг выполнения.

В Java декларативный стиль часто встречается при работе со Stream API.

**Пример:**

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

List<Integer> result = numbers.stream()
        .filter(number -> number % 2 == 0)
        .map(number -> number * 2)
        .toList();

System.out.println(result); // [4, 8]
```

---

## Побочный эффект

**Определение:**

Побочный эффект — это любое действие функции или метода, которое изменяет что-то за пределами самой функции.

К побочным эффектам относятся:

* изменение состояния объекта;
* изменение глобальных или внешних переменных;
* вывод в консоль;
* запись в файл;
* работа с базой данных;
* отправка HTTP-запросов;
* выбрасывание или обработка исключений.

В продакшене побочные эффекты не являются чем-то запрещённым. Без них программа была бы как кассир без кассы: вроде всё понимает, но ничего не делает. Но их нужно контролировать.

**Пример:**

```java
public class Counter {
    private int count = 0;

    public void increment() {
        count++; // побочный эффект: изменяется состояние объекта
    }
}
```

---

## Детерминированная функция

**Определение:**

Детерминированная функция — это функция, которая при одинаковых входных данных всегда возвращает одинаковый результат.

Она не зависит от времени, случайности, состояния объекта, базы данных или количества вызовов.

**Пример:**

```java
public static int sum(int a, int b) {
    return a + b;
}

System.out.println(sum(2, 3)); // 5
System.out.println(sum(2, 3)); // 5
System.out.println(sum(2, 3)); // 5
```

---

## Недетерминированная функция

**Определение:**

Недетерминированная функция — это функция, которая при одинаковых входных данных может возвращать разные результаты.

Обычно это происходит, если функция зависит от времени, случайных чисел, внешнего состояния или данных из внешних источников.

**Пример:**

```java
public static int getRandomNumber() {
    return new Random().nextInt(100);
}

System.out.println(getRandomNumber()); // например, 42
System.out.println(getRandomNumber()); // например, 17
```

---

## Чистая функция

**Определение:**

Чистая функция — это функция, которая:

1. всегда возвращает одинаковый результат при одинаковых аргументах;
2. не имеет побочных эффектов.

Такие функции проще тестировать, читать и безопаснее использовать в многопоточном коде.

**Пример:**

```java
public static int multiply(int a, int b) {
    return a * b;
}
```

---

## Грязная функция

**Определение:**

Грязная функция — это функция, которая имеет побочные эффекты или зависит от внешнего состояния.

Такую функцию сложнее тестировать, потому что её результат зависит не только от аргументов.

**Пример:**

```java
public class OrderService {
    private int totalOrders = 0;

    public void createOrder() {
        totalOrders++; // изменяется состояние объекта
        System.out.println("Order created"); // вывод в консоль
    }
}
```

---

## Состояние объекта

**Определение:**

Состояние объекта — это значения его полей в конкретный момент времени.

В функциональном стиле стараются меньше изменять состояние, потому что изменяемое состояние усложняет код.

**Пример:**

```java
public class User {
    private String name;

    public User(String name) {
        this.name = name;
    }

    public void rename(String newName) {
        this.name = newName; // изменение состояния объекта
    }
}
```

---

## Immutable-объект

**Определение:**

Immutable-объект — это объект, состояние которого нельзя изменить после создания.

Обычно для этого:

* поля делают `private final`;
* не добавляют сеттеры;
* значения задают через конструктор.

**Пример:**

```java
public final class User {
    private final String name;
    private final int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }
}
```

---

## Функция высшего порядка

**Определение:**

Функция высшего порядка — это функция, которая принимает другую функцию как аргумент или возвращает функцию как результат.

В Java это реализуется через функциональные интерфейсы.

**Пример:**

```java
public static int calculate(int value, Function<Integer, Integer> operation) {
    return operation.apply(value);
}

int result = calculate(5, number -> number * number);

System.out.println(result); // 25
```

---

## Монада

**Определение:**

Монада — это абстракция, которая позволяет выстраивать цепочку вычислений в определённом порядке.

В Java похожую роль часто выполняет Stream API: мы берём данные, последовательно применяем к ним операции и получаем результат.

**Пример:**

```java
List<Integer> result = List.of(1, 2, 3, 4, 5).stream()
        .filter(number -> number % 2 == 0)
        .map(number -> number * 10)
        .toList();

System.out.println(result); // [20, 40]
```

---

## Stream API

**Определение:**

Stream API — это инструмент Java для обработки коллекций в функциональном стиле.

С его помощью можно фильтровать, преобразовывать, сортировать и собирать данные без ручного написания циклов.

**Пример:**

```java
List<String> names = List.of("Anna", "Bob", "Alex");

List<String> result = names.stream()
        .filter(name -> name.startsWith("A"))
        .toList();

System.out.println(result); // [Anna, Alex]
```

## Функциональный интерфейс

**Определение:**

Функциональный интерфейс — это интерфейс, который содержит только один абстрактный метод.

Он нужен для того, чтобы в него можно было передать лямбда-выражение или ссылку на метод.

**Пример:**

```java
@FunctionalInterface
public interface Calculator {
    int calculate(int a, int b);
}
```

Использование:

```java
Calculator sum = (a, b) -> a + b;

System.out.println(sum.calculate(3, 5)); // 8
```

---

## Аннотация @FunctionalInterface

**Определение:**

`@FunctionalInterface` — это аннотация, которая показывает, что интерфейс должен быть функциональным.

Если в интерфейсе окажется больше одного абстрактного метода, компилятор выдаст ошибку.

**Пример:**

```java
@FunctionalInterface
public interface Checker {
    boolean check(String value);
}
```

---

## Лямбда-выражение

**Определение:**

Лямбда-выражение — это компактная запись реализации метода функционального интерфейса.

Проще говоря, это способ передать поведение как значение.

**Пример:**

```java
Predicate<Integer> isEven = number -> number % 2 == 0;

System.out.println(isEven.test(10)); // true
System.out.println(isEven.test(7));  // false
```

---

## Лямбда-оператор

**Определение:**

Лямбда-оператор `->` разделяет лямбда-выражение на две части:

* слева находятся параметры;
* справа находится тело лямбды.

**Пример:**

```java
BinaryOperator<Integer> sum = (a, b) -> a + b;

System.out.println(sum.apply(2, 3)); // 5
```

---

## Тело лямбда-выражения

**Определение:**

Тело лямбда-выражения — это код, который выполняется при вызове метода функционального интерфейса.

Тело может быть:

* однострочным;
* блочным.

**Пример однострочной лямбды:**

```java
Function<Integer, Integer> square = number -> number * number;
```

**Пример блочной лямбды:**

```java
Function<Integer, Integer> square = number -> {
    int result = number * number;
    return result;
};
```

---

## Однострочное лямбда-выражение

**Определение:**

Однострочное лямбда-выражение — это лямбда, тело которой состоит из одного выражения.

В таком случае фигурные скобки и `return` обычно не пишутся.

**Пример:**

```java
Function<String, Integer> getLength = text -> text.length();

System.out.println(getLength.apply("Java")); // 4
```

---

## Блочное лямбда-выражение

**Определение:**

Блочное лямбда-выражение — это лямбда, тело которой содержит несколько инструкций.

В такой лямбде используются фигурные скобки. Если нужно вернуть значение, `return` пишется явно.

**Пример:**

```java
Function<String, String> normalizeName = name -> {
    String trimmed = name.trim();
    return trimmed.toLowerCase();
};

System.out.println(normalizeName.apply("  JAVA  ")); // java
```

---

## Отложенное выполнение

**Определение:**

Отложенное выполнение означает, что лямбда-выражение не выполняется в момент создания.

Оно выполнится только тогда, когда будет вызван метод функционального интерфейса.

**Пример:**

```java
Runnable task = () -> System.out.println("Task started");

System.out.println("Before");

// лямбда выполняется только здесь
task.run();

System.out.println("After");
```

---

## Лямбда-выражение как аргумент

**Определение:**

Лямбда-выражение можно передавать в метод как аргумент, если этот метод принимает функциональный интерфейс.

Это позволяет передавать в метод не только данные, но и поведение.

**Пример:**

```java
public static List<Integer> filterNumbers(
        List<Integer> numbers,
        Predicate<Integer> condition
) {
    List<Integer> result = new ArrayList<>();

    for (Integer number : numbers) {
        if (condition.test(number)) {
            result.add(number);
        }
    }

    return result;
}

List<Integer> numbers = List.of(1, 2, 3, 4, 5);

List<Integer> evenNumbers = filterNumbers(numbers, number -> number % 2 == 0);

System.out.println(evenNumbers); // [2, 4]
```

## Predicate<T>

**Определение:**

`Predicate<T>` — это встроенный функциональный интерфейс, который принимает объект типа `T` и возвращает `boolean`.

Используется для проверок и условий.

Главный метод:

```java
boolean test(T value);
```

**Пример:**

```java
Predicate<Integer> isPositive = number -> number > 0;

System.out.println(isPositive.test(10));  // true
System.out.println(isPositive.test(-5));  // false
```

---

## Function<T, R>

**Определение:**

`Function<T, R>` — это встроенный функциональный интерфейс, который принимает объект типа `T` и возвращает объект типа `R`.

Используется для преобразования одного значения в другое.

Главный метод:

```java
R apply(T value);
```

**Пример:**

```java
Function<Integer, String> convertToText = number -> number + " рублей";

System.out.println(convertToText.apply(500)); // 500 рублей
```

---

## Consumer<T>

**Определение:**

`Consumer<T>` — это встроенный функциональный интерфейс, который принимает объект типа `T`, выполняет действие и ничего не возвращает.

Используется, когда нужно что-то сделать с объектом: вывести, сохранить, отправить, обработать.

Главный метод:

```java
void accept(T value);
```

**Пример:**

```java
Consumer<String> printer = text -> System.out.println(text);

printer.accept("Hello Java");
```

---

## Supplier<T>

**Определение:**

`Supplier<T>` — это встроенный функциональный интерфейс, который ничего не принимает, но возвращает объект типа `T`.

Используется для поставки или генерации значений.

Главный метод:

```java
T get();
```

**Пример:**

```java
Supplier<String> messageSupplier = () -> "Hello";

System.out.println(messageSupplier.get()); // Hello
```

---

## UnaryOperator<T>

**Определение:**

`UnaryOperator<T>` — это функциональный интерфейс, который принимает объект типа `T` и возвращает объект того же типа `T`.

Это частный случай `Function<T, T>`.

Главный метод:

```java
T apply(T value);
```

**Пример:**

```java
UnaryOperator<Integer> square = number -> number * number;

System.out.println(square.apply(5)); // 25
```

---

## BinaryOperator<T>

**Определение:**

`BinaryOperator<T>` — это функциональный интерфейс, который принимает два объекта типа `T` и возвращает объект того же типа `T`.

Это частный случай `BiFunction<T, T, T>`.

Главный метод:

```java
T apply(T first, T second);
```

**Пример:**

```java
BinaryOperator<Integer> multiply = (a, b) -> a * b;

System.out.println(multiply.apply(3, 5)); // 15
```

## Callback

**Определение:**

Callback — это функция или объект с функцией, который передают в другой код, чтобы этот код вызвал его позже.

В Java callback часто реализуют через функциональный интерфейс.

**Пример:**

```java
@FunctionalInterface
public interface OnDoneListener {
    void onDone(String result);
}

public static void loadData(OnDoneListener listener) {
    String data = "Data loaded";
    listener.onDone(data);
}

loadData(result -> System.out.println(result));
```

## Ссылка на метод

**Определение:**

Ссылка на метод — это компактная форма лямбда-выражения, которая используется, когда лямбда просто вызывает уже существующий метод.

Синтаксис использует оператор `::`.

**Пример с лямбдой:**

```java
Consumer<String> printer = text -> System.out.println(text);
```

**То же самое через ссылку на метод:**

```java
Consumer<String> printer = System.out::println;
```

---

## Ссылка на статический метод

**Определение:**

Ссылка на статический метод — это ссылка на метод класса, который можно вызвать без создания объекта.

Синтаксис:

```java
ClassName::staticMethodName
```

**Пример:**

```java
public class Main {
    public static void print(String text) {
        System.out.println(text);
    }

    public static void main(String[] args) {
        Consumer<String> printer = Main::print;

        printer.accept("Hello");
    }
}
```

---

## Ссылка на метод объекта

**Определение:**

Ссылка на метод объекта — это ссылка на нестатический метод конкретного объекта.

Синтаксис:

```java
objectName::methodName
```

**Пример:**

```java
public class Printer {
    public void print(String text) {
        System.out.println(text);
    }
}

Printer printer = new Printer();

Consumer<String> consumer = printer::print;

consumer.accept("Hello Java");
```

---

## Ссылка на конструктор

**Определение:**

Ссылка на конструктор — это способ передать создание объекта как функцию.

Синтаксис:

```java
ClassName::new
```

**Пример:**

```java
class User {
    private final String name;

    public User(String name) {
        this.name = name;
    }
}

Function<String, User> userFactory = User::new;

User user = userFactory.apply("Alex");
```

## Comparator с лямбда-выражением

**Определение:**

`Comparator` можно реализовать через лямбда-выражение, потому что это функциональный интерфейс.

Он используется для задания правил сортировки объектов.

**Пример:**

```java
List<String> cities = new ArrayList<>(List.of("Москва", "Париж", "Токио"));

cities.sort((a, b) -> a.compareTo(b));

System.out.println(cities); // [Москва, Париж, Токио]
```

Сортировка в обратном порядке:

```java
cities.sort((a, b) -> b.compareTo(a));
```

# Дополнение к словарю разработчика Java

## Анонимный класс

**Определение:**

Анонимный класс — это класс без имени, который создаётся прямо в месте использования.

До появления лямбда-выражений анонимные классы часто использовали, чтобы передать поведение в метод.

Анонимный класс может:

* реализовать интерфейс;
* переопределить метод;
* иметь собственные поля;
* иметь собственные методы;
* использовать `this` как ссылку на самого себя.

**Пример:**

```java
Comparator<String> comparator = new Comparator<String>() {
    @Override
    public int compare(String first, String second) {
        return first.compareTo(second);
    }
};

List<String> names = new ArrayList<>(List.of("Bob", "Alex", "John"));
names.sort(comparator);

System.out.println(names); // [Alex, Bob, John]
```

---

## Лямбда-выражение вместо анонимного класса

**Определение:**

Лямбда-выражение может заменить анонимный класс, если нужно реализовать функциональный интерфейс, то есть интерфейс с одним абстрактным методом.

Лямбда делает код короче и убирает технический шум.

**Пример с анонимным классом:**

```java
Comparator<String> comparator = new Comparator<String>() {
    @Override
    public int compare(String first, String second) {
        return first.compareTo(second);
    }
};
```

**То же самое через лямбду:**

```java
Comparator<String> comparator = (first, second) -> first.compareTo(second);
```

---

## Отличие лямбда-выражения от анонимного класса

**Определение:**

Лямбда-выражение и анонимный класс могут решать похожую задачу, но работают по-разному.

Анонимный класс создаёт отдельный объект со своим контекстом. Лямбда — это более компактная форма передачи поведения.

Главные отличия:

| Критерий                                           | Анонимный класс      | Лямбда         |
| -------------------------------------------------- | -------------------- | -------------- |
| Может иметь поля                                   | Да                   | Нет            |
| Может иметь дополнительные методы                  | Да                   | Нет            |
| Может реализовать интерфейс с несколькими методами | Да                   | Нет            |
| Работает только с функциональным интерфейсом       | Нет                  | Да             |
| `this` указывает на                                | сам анонимный объект | внешний объект |
| Код                                                | более громоздкий     | более короткий |

**Пример:**

```java
public class Main {
    private final String name = "Main class";

    public void run() {
        Runnable lambda = () -> System.out.println(this.name);

        lambda.run();
    }
}
```

## this в лямбда-выражении

**Определение:**

В лямбда-выражении `this` указывает не на саму лямбду, а на внешний объект, внутри которого эта лямбда была создана.

Это важное отличие от анонимного класса.

**Пример:**

```java
public class Example {
    private final String name = "Outer object";

    public void print() {
        Runnable task = () -> System.out.println(this.name);

        task.run();
    }
}
```

Здесь `this.name` обращается к полю класса `Example`.

---

## this в анонимном классе

**Определение:**

Внутри анонимного класса `this` указывает на сам анонимный объект.

Поэтому поведение `this` в анонимном классе и в лямбде отличается.

**Пример:**

```java
public class Example {
    private final String name = "Outer object";

    public void print() {
        Runnable task = new Runnable() {
            private final String name = "Anonymous object";

            @Override
            public void run() {
                System.out.println(this.name);
            }
        };

        task.run();
    }
}
```

Результат:

```java
Anonymous object
```

---

## Захват переменных

**Определение:**

Захват переменных — это ситуация, когда лямбда-выражение использует переменную, объявленную снаружи лямбды.

Лямбда может использовать локальные переменные из внешнего метода только в том случае, если они являются `final` или `effectively final`.

**Пример:**

```java
public static void main(String[] args) {
    String prefix = "Hello, ";

    Consumer<String> greeter = name -> System.out.println(prefix + name);

    greeter.accept("Java"); // Hello, Java
}
```

---

## Effectively final

**Определение:**

`Effectively final` — это переменная, которую явно не пометили ключевым словом `final`, но после первого присваивания её значение больше не изменяется.

Такие переменные можно использовать внутри лямбда-выражений.

**Пример:**

```java
String message = "Hello";

Runnable task = () -> System.out.println(message);

task.run();
```

Переменная `message` не объявлена как `final`, но она не изменяется после присваивания. Значит, она `effectively final`.

---

## Ошибка изменения переменной из лямбды

**Определение:**

Лямбда не может использовать локальную переменную, если после создания эта переменная изменяется.

Java запрещает это, чтобы не возникало непредсказуемого поведения.

**Пример с ошибкой:**

```java
int counter = 0;

Runnable task = () -> System.out.println(counter);

counter++; // ошибка: переменная уже не effectively final
```

Правильнее использовать отдельный объект, но делать это нужно осторожно:

```java
AtomicInteger counter = new AtomicInteger(0);

Runnable task = () -> System.out.println(counter.get());

counter.incrementAndGet();

task.run();
```

---

## Изменяемое внешнее состояние в лямбде

**Определение:**

Изменяемое внешнее состояние — это объект или переменная за пределами лямбды, которые лямбда изменяет во время выполнения.

Это опасно, потому что код становится менее предсказуемым, особенно при параллельной обработке.

**Пример плохого подхода:**

```java
List<Integer> result = new ArrayList<>();

List.of(1, 2, 3, 4).forEach(number -> {
    if (number % 2 == 0) {
        result.add(number);
    }
});

System.out.println(result); // [2, 4]
```

Код работает, но лямбда изменяет внешний список.

Лучше так:

```java
List<Integer> result = List.of(1, 2, 3, 4).stream()
        .filter(number -> number % 2 == 0)
        .toList();

System.out.println(result); // [2, 4]
```

---

## Checked-исключения в лямбдах

**Определение:**

Checked-исключения — это исключения, которые Java требует обработать или указать через `throws`.

Стандартные функциональные интерфейсы вроде `Function`, `Predicate`, `Consumer` не объявляют `throws IOException`, поэтому внутри таких лямбд нельзя просто выбросить checked-исключение без обработки.

**Пример с ошибкой:**

```java
List<String> files = List.of("a.txt", "b.txt");

files.forEach(file -> {
    Files.readString(Path.of(file)); // ошибка: IOException нужно обработать
});
```

Правильный вариант с `try/catch`:

```java
files.forEach(file -> {
    try {
        String content = Files.readString(Path.of(file));
        System.out.println(content);
    } catch (IOException exception) {
        throw new RuntimeException(exception);
    }
});
```

---

## Собственный функциональный интерфейс с throws

**Определение:**

Если лямбда должна выбрасывать checked-исключение, можно создать собственный функциональный интерфейс, в методе которого указан `throws`.

Это полезно, когда стандартные интерфейсы из `java.util.function` не подходят.

**Пример:**

```java
@FunctionalInterface
public interface FileReaderFunction {
    String read(String path) throws IOException;
}
```

Использование:

```java
FileReaderFunction reader = path -> Files.readString(Path.of(path));

try {
    String content = reader.read("data.txt");
    System.out.println(content);
} catch (IOException exception) {
    System.out.println("File reading error");
}
```

---

## Runnable

**Определение:**

`Runnable` — это функциональный интерфейс, который описывает действие без аргументов и без возвращаемого значения.

Главный метод:

```java
void run();
```

Часто используется для задач, которые нужно выполнить позже или в отдельном потоке.

**Пример:**

```java
Runnable task = () -> System.out.println("Task is running");

task.run();
```

Пример с потоком:

```java
Thread thread = new Thread(() -> System.out.println("Hello from thread"));

thread.start();
```

---

## Ленивые вычисления

**Определение:**

Ленивые вычисления — это подход, при котором операция не выполняется сразу, а откладывается до момента, когда результат действительно понадобится.

В Java ленивость часто встречается в Stream API: промежуточные операции вроде `filter()` и `map()` не выполняются, пока не будет вызвана терминальная операция.

**Пример:**

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

Stream<Integer> stream = numbers.stream()
        .filter(number -> {
            System.out.println("filter: " + number);
            return number > 2;
        });

System.out.println("Stream created");

List<Integer> result = stream.toList();

System.out.println(result);
```

До вызова `toList()` фильтрация не начнётся.

---

## Промежуточная операция Stream

**Определение:**

Промежуточная операция Stream — это операция, которая возвращает новый Stream и не запускает обработку данных сама по себе.

Промежуточные операции ленивые.

Примеры:

* `filter()`;
* `map()`;
* `sorted()`;
* `limit()`;
* `distinct()`.

**Пример:**

```java
Stream<String> stream = List.of("Alex", "Bob", "Anna").stream()
        .filter(name -> name.startsWith("A"))
        .map(String::toUpperCase);
```

Здесь обработка ещё не началась, потому что нет терминальной операции.

---

## Терминальная операция Stream

**Определение:**

Терминальная операция Stream — это операция, которая запускает обработку потока и возвращает итоговый результат.

После терминальной операции Stream считается использованным, и повторно его использовать нельзя.

Примеры:

* `toList()`;
* `collect()`;
* `forEach()`;
* `count()`;
* `anyMatch()`;
* `findFirst()`.

**Пример:**

```java
List<String> result = List.of("Alex", "Bob", "Anna").stream()
        .filter(name -> name.startsWith("A"))
        .map(String::toUpperCase)
        .toList();

System.out.println(result); // [ALEX, ANNA]
```

---

## Повторное использование Stream

**Определение:**

Stream нельзя использовать повторно после терминальной операции.

Если нужно выполнить ещё одну цепочку операций, нужно создать новый Stream.

**Пример с ошибкой:**

```java
Stream<String> stream = List.of("Alex", "Bob", "Anna").stream();

long count = stream.count();

List<String> result = stream.toList(); // ошибка
```

Правильно:

```java
List<String> names = List.of("Alex", "Bob", "Anna");

long count = names.stream().count();

List<String> result = names.stream().toList();
```

---

## Optional

**Определение:**

`Optional<T>` — это контейнер, который может содержать значение типа `T`, а может быть пустым.

Он помогает явно показать, что значения может не быть, и уменьшает количество проверок на `null`.

В функциональном стиле `Optional` позволяет выстраивать цепочку операций над возможным значением.

**Пример:**

```java
Optional<String> name = Optional.of("java");

String result = name
        .map(String::toUpperCase)
        .orElse("UNKNOWN");

System.out.println(result); // JAVA
```

---

## Мемоизация

**Определение:**

Мемоизация — это техника оптимизации, при которой результат функции сохраняется, чтобы при повторном вызове с теми же аргументами не вычислять его заново.

Мемоизация хорошо работает с чистыми функциями, потому что их результат зависит только от входных данных.

**Пример:**

```java
private static final Map<Integer, Integer> cache = new HashMap<>();

public static int square(int number) {
    if (cache.containsKey(number)) {
        return cache.get(number);
    }

    int result = number * number;
    cache.put(number, result);

    return result;
}
```

---

## parallelStream

**Определение:**

`parallelStream()` — это способ создать параллельный Stream, который может обрабатывать элементы коллекции в нескольких потоках.

Его удобно использовать для независимых операций над большим количеством данных.

Но `parallelStream()` не нужно включать везде подряд. Если задача маленькая или внутри есть изменяемое состояние, он может сделать код медленнее или опаснее.

**Пример:**

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

List<Integer> result = numbers.parallelStream()
        .map(number -> number * number)
        .toList();

System.out.println(result);
```

---

## Гонка данных

**Определение:**

Гонка данных — это ошибка, которая возникает, когда несколько потоков одновременно работают с одними и теми же изменяемыми данными, и результат зависит от порядка выполнения потоков.

В функциональном стиле гонок данных меньше, если функции не изменяют внешнее состояние.

**Пример опасного кода:**

```java
List<Integer> result = new ArrayList<>();

List.of(1, 2, 3, 4, 5).parallelStream()
        .forEach(number -> result.add(number)); // опасно

System.out.println(result);
```

Правильнее:

```java
List<Integer> result = List.of(1, 2, 3, 4, 5).parallelStream()
        .toList();

System.out.println(result);
```

---

## Сигнатура функционального интерфейса

**Определение:**

Сигнатура функционального интерфейса — это набор параметров и возвращаемый тип его единственного абстрактного метода.

Лямбда-выражение должно подходить под эту сигнатуру.

**Пример:**

```java
@FunctionalInterface
public interface StringChecker {
    boolean check(String text);
}
```

Сигнатура метода:

```java
boolean check(String text);
```

Значит, лямбда должна принимать `String` и возвращать `boolean`:

```java
StringChecker checker = text -> text.length() > 5;
```

---

## Target type

**Определение:**

`Target type` — это тип, который Java ожидает получить от лямбда-выражения в конкретном месте кода.

Лямбда сама по себе не имеет самостоятельного типа. Её тип определяется функциональным интерфейсом, которому она присваивается или в который передаётся.

**Пример:**

```java
Predicate<String> predicate = text -> text.isEmpty();
Function<String, Boolean> function = text -> text.isEmpty();
```

Лямбда выглядит одинаково, но тип разный:

* в первом случае это `Predicate<String>`;
* во втором случае это `Function<String, Boolean>`.

---

## invokedynamic

**Определение:**

`invokedynamic` — это JVM-инструкция, через которую Java реализует лямбда-выражения на уровне байткода.

Разработчик обычно не работает с ней напрямую, но важно понимать идею: лямбда — это не просто копия анонимного класса.

JVM может создавать реализацию лямбды более гибко и эффективно.

**Пример:**

```java
Runnable task = () -> System.out.println("Hello");

task.run();
```

На уровне исходного кода это обычная лямбда, но внутри JVM её вызов может быть организован через `invokedynamic`.

## Ссылка на метод экземпляра класса

**Определение:**

Ссылка на метод экземпляра класса — это ссылка вида:

```java
ClassName::instanceMethod
```

Она отличается от ссылки на метод конкретного объекта.

В этом случае объект, у которого вызывается метод, передаётся как первый аргумент функционального интерфейса.

**Пример:**

```java
Function<String, Integer> lengthFunction = String::length;

System.out.println(lengthFunction.apply("Java")); // 4
```

Здесь `String::length` означает:

```java
text -> text.length()
```

---

## Ссылка на метод конкретного объекта

**Определение:**

Ссылка на метод конкретного объекта — это ссылка вида:

```java
objectName::methodName
```

Она используется, когда объект уже существует, и нужно передать ссылку на его метод.

**Пример:**

```java
PrintStream printer = System.out;

Consumer<String> consumer = printer::println;

consumer.accept("Hello Java");
```

---

## Ссылка на конструктор как фабрика объектов

**Определение:**

Ссылка на конструктор может использоваться как фабрика объектов.

Фабрика — это код, который создаёт новые объекты.

**Пример:**

```java
Supplier<List<String>> listFactory = ArrayList::new;

List<String> names = listFactory.get();

names.add("Alex");

System.out.println(names); // [Alex]
```

Пример с аргументом конструктора:

```java
class User {
    private final String name;

    public User(String name) {
        this.name = name;
    }
}

Function<String, User> userFactory = User::new;

User user = userFactory.apply("Alex");
```

---

## Метод должен подходить по сигнатуре

**Определение:**

Метод, на который ссылается method reference, должен подходить под сигнатуру метода функционального интерфейса.

Если параметры или возвращаемый тип не совпадают, код не скомпилируется.

**Пример:**

```java
Consumer<String> printer = System.out::println;
```

`Consumer<String>` требует метод:

```java
void accept(String value);
```

`System.out.println(String value)` подходит: принимает `String` и ничего не возвращает.

---

## Злоупотребление лямбдами

**Определение:**

Злоупотребление лямбдами — это ситуация, когда разработчик помещает в лямбду слишком много логики.

Если лямбда становится длинной, сложной, содержит много условий, циклов и обработку ошибок, её лучше вынести в отдельный метод.

**Плохой пример:**

```java
users.stream()
        .filter(user -> {
            if (user == null) {
                return false;
            }

            if (user.getAge() < 18) {
                return false;
            }

            if (user.getEmail() == null || user.getEmail().isBlank()) {
                return false;
            }

            return true;
        })
        .toList();
```

Лучше:

```java
users.stream()
        .filter(UserValidator::isValidAdultUser)
        .toList();
```

---

## Лишнее указание типов в лямбде

**Определение:**

В большинстве случаев Java сама понимает типы параметров лямбды из контекста.

Поэтому типы можно не писать, если это не ухудшает читаемость.

**Пример:**

```java
Predicate<String> isEmpty = (String text) -> text.isEmpty();
```

Лучше:

```java
Predicate<String> isEmpty = text -> text.isEmpty();
```

---

## Лишние фигурные скобки и return в лямбде

**Определение:**

Если лямбда состоит из одного выражения, фигурные скобки и `return` обычно не нужны.

Так код читается проще.

**Пример:**

```java
Function<Integer, Integer> square = number -> {
    return number * number;
};
```

Лучше:

```java
Function<Integer, Integer> square = number -> number * number;
```
