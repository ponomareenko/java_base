# Тема 3: Формы и форматы передачи данных

## HTML Form

**Определение:**

HTML Form — элемент HTML, предназначенный для сбора данных пользователя и их отправки на сервер.

Форма создаётся тегом:

```html
<form>
    ...
</form>
```

Внутри формы обычно находятся элементы ввода:

```html
<input>
<select></select>
<textarea></textarea>
```

---

## Form Submission

**Определение:**

Form Submission — процесс отправки данных HTML-формы на сервер.

При отправке браузер:

1. собирает значения полей формы;
2. определяет адрес из `action`;
3. определяет HTTP-метод из `method`;
4. кодирует данные согласно правилам формы;
5. отправляет HTTP-запрос серверу.

---

## `action`

**Определение:**

`action` — атрибут HTML-формы, определяющий URL, на который браузер отправит данные формы.

Пример:

```html
<form action="http://localhost:9999">
```

Если `action` не указан, форма отправляется на адрес текущей страницы.

---

## `method`

**Определение:**

`method` — атрибут HTML-формы, определяющий HTTP-метод отправки данных.

Для обычной HTML-формы основными значениями являются:

```html
method="get"
```

или

```html
method="post"
```

Если `method` не указан, используется `GET`.

---

## `name`

**Определение:**

`name` — атрибут элемента формы, определяющий имя параметра, под которым его значение будет отправлено серверу.

Пример:

```html
<input name="username">
```

Если пользователь введёт:

```text
Danil
```

сервер получит пару:

```text
username=Danil
```

Поле без `name` при обычной отправке формы не передаётся серверу.

---

## `enctype`

**Определение:**

`enctype` — атрибут HTML-формы, определяющий формат кодирования данных формы при их отправке.

Основные значения:

```text
application/x-www-form-urlencoded
multipart/form-data
text/plain
```

По умолчанию используется:

```text
application/x-www-form-urlencoded
```

Особенно важен `enctype` при отправке формы методом `POST`.

---

## `application/x-www-form-urlencoded`

**Определение:**

`application/x-www-form-urlencoded` — стандартный формат передачи данных HTML-формы.

Данные передаются в виде пар:

```text
key=value
```

несколько параметров соединяются через:

```text
&
```

Пример:

```text
name=Danil&age=30
```

Специальные символы при этом кодируются.

При `GET` такие данные обычно попадают в URL:

```text
/users?name=Danil&age=30
```

При `POST` они передаются в теле запроса.

---

## Percent Encoding

**Определение:**

Percent Encoding — способ кодирования символов в URL и данных формы.

Символ представляется в виде:

```text
%XX
```

где `XX` — шестнадцатеричное представление байта.

Например, кириллица в URL может выглядеть так:

```text
%D0%94%D0%B0%D0%BD%D0%B8%D0%BB
```

Браузер и сервер должны уметь кодировать и декодировать такие значения.

---

## URL Encoding

**Определение:**

URL Encoding — практическое название механизма кодирования данных для безопасной передачи внутри URL.

В контексте форм он тесно связан с Percent Encoding.

В Java используются классы:

```java
URLEncoder
URLDecoder
```

Пример:

```java
String encoded = URLEncoder.encode(
        "Привет мир",
        StandardCharsets.UTF_8
);
```

Для обратного преобразования:

```java
String decoded = URLDecoder.decode(
        encoded,
        StandardCharsets.UTF_8
);
```

---

## `URLEncoder`

**Определение:**

`URLEncoder` — класс Java для кодирования данных в формат `application/x-www-form-urlencoded`.

Пример:

```java
String value = URLEncoder.encode(
        "Java Developer",
        StandardCharsets.UTF_8
);
```

Результат будет пригоден для передачи как значение параметра формы или query-параметра.

---

## `URLDecoder`

**Определение:**

`URLDecoder` — класс Java для декодирования данных из формата `application/x-www-form-urlencoded`.

Пример:

```java
String value = URLDecoder.decode(
        "Java+Developer",
        StandardCharsets.UTF_8
);
```

Результат:

```text
Java Developer
```

---

## Query String

**Определение:**

Query String — часть URL после символа `?`, содержащая параметры запроса.

Пример:

```text
/users?name=Danil&age=30
```

Query String:

```text
name=Danil&age=30
```

Структура:

```text
?key=value&key=value
```

---

## Key-Value

**Определение:**

Key-Value — способ представления данных в виде пары:

```text
ключ = значение
```

Например:

```text
name=Danil
```

где:

```text
name  — key
Danil — value
```

Формы и query-параметры активно используют такой формат представления данных.

---

## `Content-Length`

**Определение:**

`Content-Length` — HTTP-заголовок, указывающий размер тела сообщения в байтах.

Пример:

```http
Content-Length: 128
```

Сервер может использовать это значение, чтобы понять, сколько байтов нужно прочитать из тела запроса.

В реальном HTTP правила использования `Content-Length` сложнее, поэтому вручную парсить HTTP в production-коде обычно не требуется — этим занимается веб-сервер или framework.

---

## Default Value

**Определение:**

Default Value — значение по умолчанию, которое используется, если пользователь или разработчик не указал другое допустимое значение.

Например, для HTML-формы:

```html
<form>
```

эквивалентно использованию метода:

```text
GET
```

поскольку `GET` является методом формы по умолчанию.

---

## `text/plain`

**Определение:**

`text/plain` — простой текстовый формат передачи данных формы.

Например:

```text
name=Danil
age=30
city=Nicosia
```

Каждая пара `key=value` передаётся отдельной строкой.

Для обычных веб-форм используется редко.

---

## `multipart/form-data`

**Определение:**

`multipart/form-data` — формат передачи данных, при котором тело запроса делится на отдельные части.

Каждая часть может содержать собственные заголовки и данные.

Используется прежде всего для передачи файлов вместе с другими полями формы.

Пример формы:

```html
<form method="post"
      enctype="multipart/form-data">

    <input name="title">
    <input type="file" name="image">

    <button type="submit">Send</button>
</form>
```

---

## Multipart

**Определение:**

Multipart — формат сообщения, состоящего из нескольких независимых частей.

Условно:

```text
Part 1
Part 2
Part 3
```

В `multipart/form-data` одна часть может содержать текстовое поле:

```text
name=Danil
```

а другая — бинарные данные файла:

```text
photo.jpg
```

---

## Boundary

**Определение:**

Boundary — специальная последовательность символов, разделяющая части `multipart/form-data`.

Она указывается в `Content-Type`.

Например:

```http
Content-Type: multipart/form-data; boundary=----12345
```

Тело:

```text
------12345
данные первого поля

------12345
данные второго поля

------12345
данные файла
```

Сервер использует `boundary`, чтобы понять, где заканчивается одна часть и начинается другая.

---

## Multipart Part

**Определение:**

Multipart Part — отдельная часть multipart-запроса.

Каждая часть обычно содержит:

```text
headers

body
```

Например, текстовое поле:

```text
Content-Disposition: form-data; name="title"

Java
```

или файл:

```text
Content-Disposition: form-data; name="image"; filename="photo.jpg"
Content-Type: image/jpeg

<байты файла>
```

---

## `Content-Disposition`

**Определение:**

`Content-Disposition` — заголовок, используемый внутри multipart-части для описания передаваемого элемента.

Пример:

```http
Content-Disposition: form-data; name="title"
```

Для файла:

```http
Content-Disposition: form-data;
                     name="image";
                     filename="photo.jpg"
```

Он позволяет серверу понять:

* имя поля;
* является ли часть файлом;
* имя загружаемого файла.

---

## File Upload

**Определение:**

File Upload — передача файла от клиента серверу.

В обычной HTML-форме используется поле:

```html
<input type="file" name="image">
```

и формат:

```html
enctype="multipart/form-data"
```

Пример:

```html
<form method="post"
      enctype="multipart/form-data">

    <input type="file" name="image">
    <button>Upload</button>
</form>
```

Сервер получает не только имя файла, но и его содержимое.

---

## Form Data

**Определение:**

Form Data — данные, собранные из полей HTML-формы для отправки серверу.

Например:

```html
<input name="name" value="Danil">
<input name="age" value="30">
```

логически превращаются в:

```text
name=Danil
age=30
```

Физический формат передачи зависит от `method` и `enctype`.

---

## Request Payload

**Определение:**

Request Payload — фактические данные, передаваемые в теле HTTP-запроса.

Например, при `POST`:

```http
POST /users HTTP/1.1
Content-Type: application/x-www-form-urlencoded

name=Danil&age=30
```

Payload здесь:

```text
name=Danil&age=30
```

В Developer Tools браузера тело запроса часто отображается как `Payload`, `Form Data` или `Request Payload`.

---

## GET-форма

**Определение:**

GET-форма — HTML-форма, которая отправляет значения полей через query-параметры URL.

Пример:

```html
<form action="/search" method="get">
    <input name="query">
</form>
```

Если пользователь введёт:

```text
java
```

браузер сформирует URL:

```text
/search?query=java
```

GET удобно использовать для:

* поиска;
* фильтрации;
* сортировки;
* пагинации.

Такой URL можно сохранить или отправить другому человеку.

---

## POST-форма

**Определение:**

POST-форма — HTML-форма, данные которой передаются преимущественно в теле HTTP-запроса.

Пример:

```html
<form action="/users" method="post">
    <input name="name">
</form>
```

При стандартном `enctype` тело может выглядеть так:

```text
name=Danil
```

При этом POST-запрос может одновременно иметь и query-параметры:

```text
POST /users?source=registration
```

и данные в теле:

```text
name=Danil
```

---

## GET vs POST при отправке формы

**GET:**

```text
данные формы
     ↓
Query String
     ↓
URL
```

Пример:

```text
/search?query=java&page=2
```

**POST:**

```text
данные формы
     ↓
Request Body
```

Пример:

```http
POST /users

name=Danil&age=30
```

При этом наличие метода POST не запрещает наличие Query String.

Например:

```text
POST /users?notify=true
```

---

## Кодирование данных формы

**Определение:**

Кодирование данных формы — преобразование значений полей в формат, пригодный для передачи серверу.

Выбранный формат зависит от `enctype`.

Основные варианты:

```text
application/x-www-form-urlencoded
        ↓
name=Danil&age=30
```

```text
text/plain
        ↓
name=Danil
age=30
```

```text
multipart/form-data
        ↓
несколько частей + boundary
```

---

# Главное из темы

Схему стоит запомнить именно так:

```text
HTML Form
    ↓
action
    ↓
куда отправлять
```

```text
method
    ↓
GET / POST
    ↓
где в основном будут данные
```

```text
enctype
    ↓
в каком формате будут данные
```

При `GET`:

```text
Form
 ↓
key=value
 ↓
Percent Encoding
 ↓
Query String
 ↓
URL
```

При обычном `POST`:

```text
Form
 ↓
application/x-www-form-urlencoded
 ↓
Request Body
```

При загрузке файла:

```text
Form
 ↓
POST
 ↓
multipart/form-data
 ↓
boundary
 ↓
text fields + file
```

Для backend-разработчика особенно важно понимать:

```text
Content-Type
        ↓
сообщает серверу формат данных
        ↓
сервер выбирает способ их разбора
```

Именно поэтому один и тот же набор байтов нельзя без контекста правильно преобразовать в Java-объекты.
