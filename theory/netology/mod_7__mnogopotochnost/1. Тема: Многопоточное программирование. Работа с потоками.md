# Тема 1: Многопоточное программирование. Работа с потоками

## Программа

**Определение:**

Программа — это набор инструкций и данных, записанных в виде исполняемого кода.

Пока программа просто хранится на диске, она не выполняется. После запуска операционная система создаёт для неё один или несколько процессов.

Например, файл Java-приложения сам по себе является программой, а запущенная JVM с этим приложением — процессом.

---

## Процесс

**Определение:**

Процесс — это выполняющийся экземпляр программы, которому операционная система выделяет ресурсы:

* область памяти;
* процессорное время;
* файловые дескрипторы;
* сетевые соединения;
* системные ресурсы.

Каждый процесс имеет собственное адресное пространство памяти. Один процесс обычно не может напрямую обращаться к памяти другого процесса.

При запуске Java-приложения операционная система создаёт процесс JVM.

**Пример:**

Если одновременно два раза запустить одну Java-программу, появятся два отдельных процесса JVM:

```text
Java-программа
├── JVM-процесс №1
└── JVM-процесс №2
```

У каждого процесса будет собственная память и собственные потоки.

---

## Поток выполнения

**Определение:**

Поток выполнения, или thread, — это последовательность инструкций, выполняемая внутри процесса.

Каждый процесс содержит как минимум один поток. В Java таким потоком первоначально является `main`.

Потоки одного процесса:

* выполняют разные последовательности инструкций;
* используют общую память процесса;
* могут работать одновременно или попеременно;
* могут влиять друг на друга через общие данные.

**Пример:**

```java
public class Main {

    public static void main(String[] args) {
        System.out.println(Thread.currentThread().getName());
    }
}
```

Результат:

```text
main
```

Метод `main()` выполняется в потоке с именем `main`.

---

## Главный поток

**Определение:**

Главный поток — это поток, в котором JVM начинает выполнение Java-программы.

Обычно он имеет имя `main` и вызывает метод:

```java
public static void main(String[] args)
```

Главный поток ничем принципиально не отличается от других потоков. Он просто создаётся JVM первым и служит точкой входа в приложение.

**Пример:**

```java
public class Main {

    public static void main(String[] args) {
        Thread currentThread = Thread.currentThread();

        System.out.println(currentThread.getName()); // main
    }
}
```

---

## Многопоточное программирование

**Определение:**

Многопоточное программирование — это организация программы, при которой внутри одного процесса работают несколько потоков выполнения.

Потоки могут выполнять разные задачи, используя общую память процесса.

Многопоточность применяется, чтобы:

* одновременно обрабатывать несколько запросов;
* не блокировать всю программу во время длительных операций;
* использовать несколько ядер процессора;
* выполнять фоновые задачи;
* повышать отзывчивость приложения.

**Пример:**

```java
public class Main {

    public static void main(String[] args) {
        Thread firstThread = new Thread(
                () -> System.out.println("Первая задача")
        );

        Thread secondThread = new Thread(
                () -> System.out.println("Вторая задача")
        );

        firstThread.start();
        secondThread.start();
    }
}
```

Порядок вывода заранее не гарантирован:

```text
Первая задача
Вторая задача
```

или:

```text
Вторая задача
Первая задача
```

Планированием потоков занимается JVM совместно с операционной системой.

---

## Конкурентность

**Определение:**

Конкурентность — это способность программы работать с несколькими задачами в течение одного промежутка времени.

На одном ядре процессора задачи могут выполняться попеременно: процессор быстро переключается между потоками, создавая ощущение одновременной работы.

```text
Поток A: ███     ███
Поток B:    █████
```

Конкурентность не обязательно означает физическое одновременное выполнение.

---

## Параллелизм

**Определение:**

Параллелизм — это физически одновременное выполнение нескольких задач на разных ядрах процессора.

```text
Ядро 1: Поток A ███████
Ядро 2: Поток B ███████
```

Для настоящего параллелизма требуется несколько вычислительных ядер.

**Разница:**

* конкурентность — несколько задач находятся в работе;
* параллелизм — несколько задач выполняются физически одновременно.

Многопоточная программа может быть конкурентной, но не обязательно параллельной.

---

## Общая память потоков

**Определение:**

Потоки одного процесса используют общую память процесса.

Это означает, что несколько потоков могут обращаться к одним и тем же объектам.

**Пример:**

```java
public class Counter {
    private int value;

    public void increment() {
        value++;
    }

    public int getValue() {
        return value;
    }
}
```

Если один экземпляр `Counter` передать нескольким потокам, все они будут изменять одно поле `value`.

Именно общая память делает взаимодействие потоков удобным, но одновременно создаёт риск гонок данных и других ошибок многопоточности.

---

## Закон Мура

**Определение:**

Закон Мура — эмпирическое наблюдение, согласно которому количество транзисторов в интегральных схемах исторически увеличивалось примерно вдвое через определённый промежуток времени.

В презентации используется упрощённая формулировка: вычислительная мощность процессоров примерно удваивается каждые 18 месяцев.

Для многопоточности важен практический вывод: рост производительности процессоров всё чаще достигается не увеличением скорости одного ядра, а увеличением количества ядер.

Поэтому программы должны уметь распределять работу между несколькими ядрами.

---

## Закон Амдала

**Определение:**

Закон Амдала описывает ограничение ускорения программы при распараллеливании.

Даже если часть программы можно выполнить параллельно, последовательная часть всё равно ограничивает максимальное ускорение.

Например, если половина программы всегда выполняется последовательно, добавление любого количества потоков не позволит ускорить всю программу больше чем примерно в два раза.

**Практический смысл:**

```text
Общее время =
последовательная часть +
параллельная часть
```

Если последовательная часть занимает много времени, простое добавление потоков почти не поможет.

В продакшене «добавить ещё потоков» — не универсальная кнопка ускорения. Иногда это кнопка «получить ещё больше проблем, но быстрее».

# Работа с `Thread`

## Класс `Thread`

**Определение:**

`Thread` — класс стандартной библиотеки Java, представляющий поток выполнения.

Объект `Thread` содержит настройки потока и позволяет:

* запустить поток;
* назначить ему имя;
* проверить его состояние;
* отправить запрос на прерывание;
* дождаться его завершения.

**Пример:**

```java
public class WorkerThread extends Thread {

    @Override
    public void run() {
        System.out.println("Работает поток: " + getName());
    }
}
```

Запуск:

```java
public class Main {

    public static void main(String[] args) {
        Thread workerThread = new WorkerThread();
        workerThread.start();
    }
}
```

---

## Метод `run()`

**Определение:**

`run()` — метод, содержащий код задачи, которую должен выполнить поток.

Сам по себе вызов `run()` не создаёт новый поток. Метод выполнится в том потоке, который его вызвал.

**Пример:**

```java
Thread worker = new Thread(() ->
        System.out.println(Thread.currentThread().getName())
);

worker.run();
```

Результат:

```text
main
```

Код выполнился в главном потоке.

---

## Метод `start()`

**Определение:**

`start()` — метод класса `Thread`, который запускает новый поток выполнения.

После вызова `start()` JVM создаёт новый поток и вызывает в нём метод `run()`.

**Пример:**

```java
Thread worker = new Thread(() ->
        System.out.println(Thread.currentThread().getName())
);

worker.start();
```

Возможный результат:

```text
Thread-0
```

### Важное отличие

```java
worker.run();   // обычный вызов метода в текущем потоке
worker.start(); // запуск нового потока
```

Один объект `Thread` можно запустить через `start()` только один раз.

Повторный запуск приведёт к:

```text
IllegalThreadStateException
```

---

## Наследование от `Thread`

**Определение:**

Наследование от `Thread` — способ создания потока, при котором разработчик создаёт класс-наследник и переопределяет метод `run()`.

**Пример:**

```java
public class FileLoaderThread extends Thread {

    @Override
    public void run() {
        System.out.println("Загрузка файла");
    }
}
```

Использование:

```java
Thread fileLoader = new FileLoaderThread();
fileLoader.start();
```

**Недостаток:**

Класс уже наследуется от `Thread`, поэтому не сможет наследоваться от другого класса.

В продакшене обычно предпочитают отделять задачу от механизма её запуска, используя `Runnable`, `Callable` и `ExecutorService`.

---

## Интерфейс `Runnable`

**Определение:**

`Runnable` — функциональный интерфейс, описывающий задачу, которая:

* не принимает аргументов;
* не возвращает результат;
* не может объявлять проверяемые исключения в методе `run()`.

Сигнатура:

```java
public interface Runnable {
    void run();
}
```

**Пример:**

```java
Runnable task = () ->
        System.out.println("Задача выполняется");

Thread worker = new Thread(task);
worker.start();
```

`Runnable` описывает, **что выполнить**, а `Thread` определяет, **где это выполнить**.

Такое разделение считается более гибким.

---

## Интерфейс `Callable`

**Определение:**

`Callable<V>` — функциональный интерфейс, представляющий задачу, которая:

* возвращает результат типа `V`;
* может выбрасывать проверяемые исключения;
* обычно запускается через `ExecutorService`.

Сигнатура:

```java
public interface Callable<V> {
    V call() throws Exception;
}
```

**Пример:**

```java
Callable<Integer> task = () -> 10 + 20;
```

В отличие от `Runnable`, результат выполнения `Callable` можно получить через `Future`.

---

## Разница между `Runnable` и `Callable`

**Определение:**

`Runnable` используется для задачи без возвращаемого результата, а `Callable` — для задачи, результат которой нужно получить.

```java
Runnable runnableTask = () ->
        System.out.println("Готово");

Callable<String> callableTask = () ->
        "Результат";
```

| Характеристика         | `Runnable`          | `Callable<V>`     |
| ---------------------- | ------------------- | ----------------- |
| Метод                  | `run()`             | `call()`          |
| Возвращаемое значение  | Нет                 | Есть              |
| Проверяемые исключения | Нельзя объявить     | Можно объявить    |
| Получение результата   | Обычно не требуется | Через `Future<V>` |

---

## Имя потока

**Определение:**

Имя потока — текстовый идентификатор, который помогает различать потоки в логах и при отладке.

Для работы с именем используются:

```java
setName(String name)
getName()
```

**Пример:**

```java
Thread worker = new Thread(
        () -> System.out.println("Загрузка"),
        "file-loader"
);

worker.start();
```

Имя лучше задавать при создании потока, а не отдельным вызовом `setName()`:

```java
new Thread(task, "file-loader");
```

Осмысленные имена упрощают анализ логов:

```text
file-loader
payment-worker
notification-sender
```

---

## Идентификатор потока

**Определение:**

Идентификатор потока — числовой идентификатор конкретного объекта `Thread`.

В презентации `getId()` назван идентификатором процесса, но это неточно: метод возвращает идентификатор **потока**, а не процесса.

```java
Thread currentThread = Thread.currentThread();

System.out.println(currentThread.getId());
```

В современных версиях Java также существует метод:

```java
currentThread.threadId();
```

Не следует использовать идентификатор потока как бизнес-идентификатор или сохранять его в базе данных.

---

## Приоритет потока

**Определение:**

Приоритет потока — числовая подсказка планировщику о желательном порядке предоставления процессорного времени.

Диапазон:

```java
Thread.MIN_PRIORITY  // 1
Thread.NORM_PRIORITY // 5
Thread.MAX_PRIORITY  // 10
```

**Пример:**

```java
Thread worker = new Thread(() -> {
});

worker.setPriority(Thread.MAX_PRIORITY);
```

Приоритет не гарантирует, что поток будет выполнен раньше другого потока.

Поведение зависит от JVM и операционной системы. Поэтому бизнес-логику нельзя строить на приоритетах потоков.

---

## Состояние потока

**Определение:**

Состояние потока показывает, на каком этапе жизненного цикла находится поток.

Получить состояние можно методом:

```java
thread.getState();
```

Основные состояния `Thread.State`:

* `NEW` — поток создан, но ещё не запущен;
* `RUNNABLE` — готов к выполнению или выполняется;
* `BLOCKED` — ожидает освобождения монитора;
* `WAITING` — ожидает без ограничения времени;
* `TIMED_WAITING` — ожидает ограниченное время;
* `TERMINATED` — завершил работу.

**Пример:**

```java
Thread worker = new Thread(() ->
        System.out.println("Работа")
);

System.out.println(worker.getState()); // NEW

worker.start();

System.out.println(worker.getState());
```

Состояние после `start()` может быстро измениться, поэтому конкретный результат второго вызова не гарантирован.

---

## Метод `isAlive()`

**Определение:**

`isAlive()` возвращает `true`, если поток уже был запущен, но ещё не завершился.

```java
Thread worker = new Thread(() -> {
});

System.out.println(worker.isAlive()); // false

worker.start();

System.out.println(worker.isAlive());
```

Значение после `start()` зависит от того, успел ли поток завершить работу.

---

## Прерывание потока

**Определение:**

Прерывание потока — механизм кооперативной отмены задачи.

Метод `interrupt()` не останавливает поток принудительно. Он отправляет потоку сигнал: «тебя просят завершиться».

Поток должен самостоятельно:

* проверить флаг прерывания;
* корректно завершить работу;
* освободить ресурсы.

**Пример:**

```java
Thread worker = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        System.out.println("Работаю");
    }

    System.out.println("Завершаюсь");
});

worker.start();
worker.interrupt();
```

В презентации `interrupt()` описан как остановка потока, но точнее говорить: **запрос на прерывание**.

---

## Метод `interrupt()`

**Определение:**

`interrupt()` устанавливает флаг прерывания у потока.

Если поток находится в методе, чувствительном к прерыванию, например:

```java
Thread.sleep(...)
Thread.join(...)
Object.wait(...)
```

то поток получает `InterruptedException`.

**Пример:**

```java
Thread worker = new Thread(() -> {
    try {
        Thread.sleep(10_000);
    } catch (InterruptedException exception) {
        System.out.println("Сон был прерван");

        Thread.currentThread().interrupt();
    }
});

worker.start();
worker.interrupt();
```

Повторная установка флага:

```java
Thread.currentThread().interrupt();
```

нужна, потому что при выбрасывании `InterruptedException` флаг прерывания сбрасывается.

---

## Метод `isInterrupted()`

**Определение:**

`isInterrupted()` проверяет, установлен ли у конкретного потока флаг прерывания.

Метод не очищает этот флаг.

```java
if (Thread.currentThread().isInterrupted()) {
    return;
}
```

В презентации сказано, что метод возвращает `true`, если поток был остановлен. Точнее: он возвращает `true`, если у потока установлен флаг прерывания.

---

## Метод `Thread.interrupted()`

**Определение:**

`Thread.interrupted()` — статический метод, который проверяет флаг прерывания текущего потока и одновременно сбрасывает его.

```java
boolean interrupted = Thread.interrupted();
```

Разница:

```java
thread.isInterrupted();   // проверяет указанный поток, флаг не сбрасывает
Thread.interrupted();     // проверяет текущий поток, флаг сбрасывает
```

---

## Кооперативная отмена

**Определение:**

Кооперативная отмена — подход, при котором задача сама периодически проверяет, не запрошено ли её завершение.

Поток нельзя безопасно «убить» снаружи в произвольной точке: он может оставить данные в некорректном состоянии или не освободить ресурсы.

**Пример:**

```java
Runnable task = () -> {
    while (!Thread.currentThread().isInterrupted()) {
        performWork();
    }

    releaseResources();
};
```

---

## Поток-демон

**Определение:**

Поток-демон — фоновый поток, который не препятствует завершению JVM.

Когда все обычные пользовательские потоки завершились, JVM может остановиться, даже если daemon-потоки ещё работают.

**Пример:**

```java
Thread backgroundThread = new Thread(() -> {
    while (true) {
        System.out.println("Фоновая работа");
    }
});

backgroundThread.setDaemon(true);
backgroundThread.start();
```

Метод `setDaemon(true)` нужно вызвать до `start()`.

Daemon-поток нельзя использовать для критически важной работы, которая обязательно должна завершиться:

* сохранение данных;
* проведение платежа;
* запись важного файла.

JVM может завершить такой поток без выполнения завершающей логики.

---

## `ThreadGroup`

**Определение:**

`ThreadGroup` — класс, позволяющий логически объединять потоки в иерархические группы.

Группа может содержать:

* потоки;
* вложенные группы потоков.

**Пример:**

```java
ThreadGroup workerGroup = new ThreadGroup("workers");

Thread firstWorker = new Thread(
        workerGroup,
        () -> System.out.println("Первая задача")
);

Thread secondWorker = new Thread(
        workerGroup,
        () -> System.out.println("Вторая задача")
);

firstWorker.start();
secondWorker.start();
```

Можно отправить прерывание всей группе:

```java
workerGroup.interrupt();
```

`ThreadGroup` считается устаревшим подходом для управления прикладными задачами. В современном продакшен-коде обычно применяют `ExecutorService` и структурированные механизмы управления задачами.

---

## Метод `join()`

**Определение:**

`join()` заставляет текущий поток ждать, пока другой поток завершит работу.

**Пример:**

```java
Thread worker = new Thread(() ->
        System.out.println("Работа завершена")
);

worker.start();
worker.join();

System.out.println("Основной поток продолжил работу");
```

Гарантированный порядок:

```text
Работа завершена
Основной поток продолжил работу
```

Без `join()` главный поток может продолжить выполнение раньше рабочего.

# `Future` и выполнение задач

## Интерфейс `Future`

**Определение:**

`Future<V>` — объект, представляющий результат задачи, которая выполняется или будет выполнена в будущем.

Через `Future` можно:

* проверить завершение задачи;
* получить результат;
* отменить задачу;
* проверить, была ли она отменена.

**Пример:**

```java
Future<Integer> future = executorService.submit(() -> 10 + 20);
```

Объект `future` является не потоком, а средством управления отправленной задачей.

---

## Метод `Future.get()`

**Определение:**

`get()` возвращает результат выполнения задачи.

Если задача ещё не завершилась, текущий поток блокируется и ждёт её завершения.

```java
Integer result = future.get();
```

Возможные исключения:

* `InterruptedException` — ожидающий поток был прерван;
* `ExecutionException` — задача завершилась с исключением;
* `CancellationException` — задача была отменена.

**Продакшен-замечание:**

Бесконтрольный `get()` может заблокировать поток на неопределённое время.

Безопаснее использовать таймаут:

```java
Integer result = future.get(2, TimeUnit.SECONDS);
```

---

## Блокирующая операция

**Определение:**

Блокирующая операция — операция, во время которой поток не может продолжать выполнение, пока не наступит определённое событие.

Примеры:

```java
future.get();
thread.join();
Thread.sleep(...);
queue.take();
```

Во время блокировки поток существует, но не выполняет полезную работу.

---

## Метод `Future.isDone()`

**Определение:**

`isDone()` возвращает `true`, если задача завершена.

Задача считается завершённой, если она:

* успешно вернула результат;
* завершилась с исключением;
* была отменена.

```java
if (future.isDone()) {
    System.out.println("Задача завершена");
}
```

`isDone()` не означает, что задача завершилась успешно.

---

## Метод `Future.cancel()`

**Определение:**

`cancel(boolean mayInterruptIfRunning)` пытается отменить выполнение задачи.

```java
future.cancel(true);
```

Параметр:

```java
true
```

означает, что выполняющему задачу потоку разрешено отправить сигнал прерывания.

```java
false
```

означает, что уже начавшаяся задача не должна прерываться этим вызовом.

Даже `cancel(true)` не гарантирует мгновенную остановку. Задача должна корректно реагировать на прерывание.

---

## Метод `Future.isCancelled()`

**Определение:**

`isCancelled()` возвращает `true`, если задача была отменена до её нормального завершения.

```java
if (future.isCancelled()) {
    System.out.println("Задача отменена");
}
```

---

## `FutureTask`

**Определение:**

`FutureTask<V>` — класс, который одновременно реализует `Runnable` и `Future<V>`.

Он:

* содержит задачу;
* может быть передан потоку;
* хранит результат выполнения;
* позволяет получить результат через `get()`.

**Пример:**

```java
Callable<String> task = () -> "Готово";

FutureTask<String> futureTask = new FutureTask<>(task);

Thread worker = new Thread(futureTask);
worker.start();

String result = futureTask.get();

System.out.println(result);
```

В продакшене вручную создавать `FutureTask` обычно не требуется. Чаще задачу передают в `ExecutorService`.

---

# Исполнители и пулы потоков

## `Executor`

**Определение:**

`Executor` — базовый интерфейс, отделяющий задачу от способа её выполнения.

Сигнатура:

```java
public interface Executor {
    void execute(Runnable command);
}
```

Разработчик передаёт задачу:

```java
executor.execute(task);
```

А конкретная реализация решает:

* создать новый поток;
* использовать существующий поток;
* поставить задачу в очередь;
* выполнить её другим способом.

---

## `ExecutorService`

**Определение:**

`ExecutorService` — расширение интерфейса `Executor`, предназначенное для запуска задач и управления их жизненным циклом.

Он позволяет:

* выполнять `Runnable`;
* выполнять `Callable`;
* получать `Future`;
* запускать несколько задач;
* корректно завершать работу исполнителя.

**Пример:**

```java
ExecutorService executorService =
        Executors.newFixedThreadPool(4);

Future<Integer> future =
        executorService.submit(() -> 10 + 20);

Integer result = future.get();

executorService.shutdown();
```

---

## Метод `execute()`

**Определение:**

`execute()` принимает `Runnable` и запускает его выполнение.

Метод не возвращает `Future`.

```java
executorService.execute(() ->
        System.out.println("Задача выполнена")
);
```

Используется, когда результат задачи не требуется.

---

## Метод `submit()`

**Определение:**

`submit()` отправляет задачу на выполнение и возвращает объект `Future`.

Для `Callable`:

```java
Future<Integer> future =
        executorService.submit(() -> 42);
```

Для `Runnable`:

```java
Future<?> future =
        executorService.submit(() ->
                System.out.println("Готово")
        );
```

Даже если задача ничего не возвращает, через `Future` можно:

* проверить завершение;
* отменить задачу;
* получить возникшее исключение через `get()`.

---

## Разница между `execute()` и `submit()`

**Определение:**

`execute()` запускает `Runnable` без возвращаемого объекта управления.

`submit()` возвращает `Future`, через который можно следить за задачей.

```java
executorService.execute(task);
```

```java
Future<?> future = executorService.submit(task);
```

Практическая разница проявляется и при исключениях: исключение задачи, отправленной через `submit()`, сохраняется внутри `Future` и проявится при вызове `get()`.

---

## Пул потоков

**Определение:**

Пул потоков — заранее созданный набор рабочих потоков, которые многократно используются для выполнения задач.

Задачи передаются в очередь, после чего свободный поток забирает очередную задачу.

```text
Задачи → Очередь → Поток 1
                  Поток 2
                  Поток 3
                  Поток 4
```

Пул предотвращает постоянное создание новых потоков для каждой задачи.

Создание потока требует ресурсов, поэтому повторное использование потоков эффективнее.

---

## Класс `Executors`

**Определение:**

`Executors` — вспомогательный класс-фабрика, содержащий статические методы для создания исполнителей и пулов потоков.

**Пример:**

```java
ExecutorService threadPool =
        Executors.newFixedThreadPool(4);
```

Название класса пишется во множественном числе:

```java
Executors
```

а объект обычно имеет тип:

```java
ExecutorService
```

---

## Фиксированный пул потоков

**Определение:**

Фиксированный пул потоков содержит постоянное максимальное количество рабочих потоков.

Создаётся методом:

```java
Executors.newFixedThreadPool(int numberOfThreads)
```

**Пример:**

```java
ExecutorService threadPool =
        Executors.newFixedThreadPool(4);
```

Одновременно могут выполняться до четырёх задач. Остальные будут ждать в очереди.

**Продакшен-замечание:**

`newFixedThreadPool()` использует неограниченную очередь задач. Если задачи поступают быстрее, чем обрабатываются, очередь может расти и занимать слишком много памяти.

В нагруженных системах часто создают `ThreadPoolExecutor` вручную с ограниченной очередью.

---

## Метод `invokeAll()`

**Определение:**

`invokeAll()` запускает коллекцию `Callable`-задач и ожидает завершения всех задач.

Метод возвращает список `Future` в том же порядке, в котором задачи находились в исходной коллекции.

**Пример:**

```java
List<Callable<Integer>> tasks = List.of(
        () -> 10,
        () -> 20,
        () -> 30
);

List<Future<Integer>> futures =
        executorService.invokeAll(tasks);
```

Версия с таймаутом:

```java
executorService.invokeAll(
        tasks,
        2,
        TimeUnit.SECONDS
);
```

Незавершённые к моменту истечения таймаута задачи отменяются.

---

## Метод `invokeAny()`

**Определение:**

`invokeAny()` запускает несколько `Callable`-задач и возвращает результат одной успешно завершившейся задачи.

Остальные задачи отменяются.

**Пример:**

```java
String result = executorService.invokeAny(
        List.of(
                () -> requestFirstServer(),
                () -> requestSecondServer()
        )
);
```

Метод полезен, когда один и тот же результат можно получить из нескольких источников и нужен первый успешный ответ.

---

# Завершение `ExecutorService`

## Метод `shutdown()`

**Определение:**

`shutdown()` начинает корректное завершение `ExecutorService`.

После вызова:

* новые задачи больше не принимаются;
* уже отправленные задачи продолжают выполняться;
* задачи из очереди не отменяются автоматически.

```java
executorService.shutdown();
```

В презентации указано, что `shutdown()` отменяет запущенные задачи. Это неточно: обычный `shutdown()` позволяет ранее отправленным задачам завершиться.

---

## Метод `shutdownNow()`

**Определение:**

`shutdownNow()` пытается немедленно остановить выполнение задач.

Метод:

* отправляет прерывание работающим потокам;
* прекращает запуск задач из очереди;
* возвращает список задач, которые не начали выполняться.

```java
List<Runnable> notStartedTasks =
        executorService.shutdownNow();
```

Метод не гарантирует мгновенной остановки уже выполняемых задач. Они должны реагировать на прерывание.

---

## Метод `awaitTermination()`

**Определение:**

`awaitTermination()` блокирует текущий поток до одного из событий:

* все задачи завершились после вызова `shutdown()` или `shutdownNow()`;
* истёк таймаут;
* ожидающий поток был прерван.

```java
executorService.shutdown();

boolean terminated = executorService.awaitTermination(
        10,
        TimeUnit.SECONDS
);
```

Метод сам по себе не выключает `ExecutorService`. Сначала нужно вызвать `shutdown()` или `shutdownNow()`.

---

## Метод `isShutdown()`

**Определение:**

`isShutdown()` возвращает `true`, если у `ExecutorService` уже был вызван `shutdown()` или `shutdownNow()`.

```java
executorService.shutdown();

System.out.println(executorService.isShutdown()); // true
```

Это не означает, что все задачи уже завершились.

---

## Метод `isTerminated()`

**Определение:**

`isTerminated()` возвращает `true`, если:

* был запущен процесс завершения исполнителя;
* все задачи полностью завершились.

```java
executorService.shutdown();

System.out.println(executorService.isTerminated());
```

Сразу после `shutdown()` результат может быть `false`, потому что старые задачи ещё выполняются.

---

## Корректное завершение пула потоков

**Определение:**

Корректное завершение пула — последовательность действий, при которой приложению сначала дают закончить уже принятые задачи, а затем при необходимости принудительно запрашивают их прерывание.

**Пример:**

```java
executorService.shutdown();

try {
    if (!executorService.awaitTermination(10, TimeUnit.SECONDS)) {
        executorService.shutdownNow();

        if (!executorService.awaitTermination(10, TimeUnit.SECONDS)) {
            System.err.println("Пул потоков не завершился");
        }
    }
} catch (InterruptedException exception) {
    executorService.shutdownNow();
    Thread.currentThread().interrupt();
}
```

Это более надёжный продакшен-вариант, чем один вызов:

```java
executorService.shutdown();
```
