# Тема 2: Синхронизация потоков

Презентация рассматривает стандартные средства синхронизации, критические секции и взаимные блокировки. Методы `wait()` и `notify()` указаны в плане занятия, но подробно на слайдах не раскрыты, поэтому их определения дополнены. 

---

## Синхронизация потоков

**Определение:**

Синхронизация потоков — это управление доступом нескольких потоков к общим данным и ресурсам.

Она нужна, чтобы потоки:

* не изменяли одни и те же данные одновременно;
* видели актуальные изменения, сделанные другими потоками;
* выполняли зависимые операции в правильном порядке.

**Пример проблемы без синхронизации:**

```java
public class Counter {
    private int value;

    public void increment() {
        value++;
    }

    public int getValue() {
        return value;
    }
}
```

Операция `value++` не является одной неделимой операцией. Упрощённо она состоит из трёх действий:

```text
1. Прочитать текущее значение.
2. Увеличить значение.
3. Записать результат.
```

Если два потока выполняют эти действия одновременно, часть увеличений может потеряться.

---

## Общий ресурс

**Определение:**

Общий ресурс — это объект, переменная, файл, соединение или другой ресурс, к которому обращаются несколько потоков.

**Пример:**

```java
List<String> messages = new ArrayList<>();
```

Если несколько потоков одновременно изменяют этот список, он становится общим изменяемым ресурсом.

---

## Критическая секция

**Определение:**

Критическая секция — это участок кода, в котором поток работает с общим ресурсом и который не должен одновременно выполняться несколькими потоками.

В презентации подчёркивается, что критическая секция должна быть как можно меньше: пока один поток находится внутри неё, остальные потоки ждут. 

**Пример:**

```java
public class Counter {
    private int value;
    private final Object lock = new Object();

    public void increment() {
        synchronized (lock) {
            value++;
        }
    }
}
```

Критической секцией здесь является:

```java
synchronized (lock) {
    value++;
}
```

---

## `synchronized`

**Определение:**

`synchronized` — ключевое слово Java, которое разрешает только одному потоку одновременно выполнять защищённый участок кода для конкретного объекта-монитора.

Пока один поток удерживает монитор, другие потоки, которым нужен тот же монитор, будут ожидать.

### Синхронизированный блок

```java
public class Counter {
    private int value;
    private final Object lock = new Object();

    public void increment() {
        synchronized (lock) {
            value++;
        }
    }
}
```

### Синхронизированный метод

```java
public class Counter {
    private int value;

    public synchronized void increment() {
        value++;
    }
}
```

Для обычного синхронизированного метода монитором является текущий объект:

```java
this
```

То есть этот код:

```java
public synchronized void increment() {
    value++;
}
```

приблизительно соответствует:

```java
public void increment() {
    synchronized (this) {
        value++;
    }
}
```

---

## Монитор объекта

**Определение:**

Монитор — это встроенный в каждый объект Java механизм блокировки, который используется оператором `synchronized`.

Поток должен захватить монитор объекта перед входом в синхронизированный блок.

**Пример:**

```java
private final Object lock = new Object();

public void process() {
    synchronized (lock) {
        System.out.println("Монитор объекта lock захвачен");
    }
}
```

После выхода из блока монитор освобождается автоматически, даже если внутри возникло исключение.

---

## Объект синхронизации

**Определение:**

Объект синхронизации — это объект, монитор которого захватывается потоком при входе в блок `synchronized`.

```java
private final Object lock = new Object();

synchronized (lock) {
    // критическая секция
}
```

В данном случае объектом синхронизации является `lock`.

В презентации рекомендуется использовать для этого `final`-поля. Если ссылку заменить другим объектом, разные потоки могут начать синхронизироваться на разных мониторах, и защита перестанет работать. 

**Правильно:**

```java
private final Object lock = new Object();
```

**Опасно:**

```java
private Object lock = new Object();

public void replaceLock() {
    lock = new Object();
}
```

---

## Взаимное исключение

**Определение:**

Взаимное исключение — это правило, при котором только один поток может находиться в конкретной критической секции в определённый момент времени.

`synchronized` обеспечивает взаимное исключение для потоков, использующих один и тот же монитор.

```java
synchronized (lock) {
    // одновременно сюда попадёт только один поток,
    // синхронизирующийся на объекте lock
}
```

Важно: два блока, синхронизированных на разных объектах, не блокируют друг друга.

```java
private final Object firstLock = new Object();
private final Object secondLock = new Object();
```

```java
synchronized (firstLock) {
    // один монитор
}

synchronized (secondLock) {
    // другой монитор
}
```

## Гонка потоков — Race condition

**Определение:**

Гонка потоков — это ситуация, при которой результат программы зависит от порядка выполнения потоков.

При каждом запуске порядок выполнения может отличаться, поэтому ошибка может проявляться нестабильно.

**Пример:**

```java
public class Counter {
    private int value;

    public void increment() {
        value++;
    }
}
```

Если два потока одновременно вызывают `increment()`, итоговое значение может оказаться меньше ожидаемого.

**Исправление:**

```java
public synchronized void increment() {
    value++;
}
```

## `Thread.sleep()`

**Определение:**

`Thread.sleep()` приостанавливает выполнение текущего потока на указанное время.

```java
Thread.sleep(3000);
```

Здесь текущий поток будет приостановлен примерно на три секунды.

Метод принимает время в миллисекундах и выбрасывает `InterruptedException`.

```java
try {
    Thread.sleep(3000);
} catch (InterruptedException exception) {
    Thread.currentThread().interrupt();
}
```

### Важная особенность

`Thread.sleep()` **не освобождает захваченный монитор**.

```java
synchronized (lock) {
    Thread.sleep(3000);
}
```

Пока поток спит, монитор `lock` остаётся занятым. Другие потоки не смогут войти в блок, использующий тот же объект.

Поэтому помещать долгий `sleep()` внутрь `synchronized` обычно плохая идея.

---

## `Thread.join()`

**Определение:**

`join()` заставляет текущий поток ждать завершения другого потока.

**Пример:**

```java
Thread worker = new Thread(() -> {
    System.out.println("Начало работы");

    try {
        Thread.sleep(1000);
    } catch (InterruptedException exception) {
        Thread.currentThread().interrupt();
    }

    System.out.println("Работа завершена");
});

worker.start();
worker.join();

System.out.println("Основной поток продолжил работу");
```

Сначала завершится `worker`, и только после этого основной поток выведет последнее сообщение.

Важно различать:

```java
worker.join();
```

Означает:

> текущий поток ждёт завершения `worker`.

Это не значит, что сам `worker` кого-то ждёт.

---

## `wait()`

**Определение:**

`wait()` временно приостанавливает текущий поток до получения уведомления от другого потока.

Метод вызывается у объекта-монитора:

```java
lock.wait();
```

`wait()` можно вызвать только тогда, когда поток уже владеет монитором этого объекта.

```java
synchronized (lock) {
    lock.wait();
}
```

### Важная особенность

В отличие от `Thread.sleep()`, метод `wait()` освобождает монитор.

Это позволяет другому потоку войти в синхронизированный блок и изменить состояние программы.

---

## `notify()`

**Определение:**

`notify()` пробуждает один из потоков, ожидающих на мониторе данного объекта с помощью `wait()`.

```java
synchronized (lock) {
    lock.notify();
}
```

Какой именно поток будет пробуждён, заранее не гарантируется.

`notify()` также можно вызывать только при владении монитором соответствующего объекта.

---

## `notifyAll()`

**Определение:**

`notifyAll()` пробуждает все потоки, ожидающие на мониторе данного объекта.

```java
synchronized (lock) {
    lock.notifyAll();
}
```

После пробуждения потоки не начинают выполняться одновременно внутри критической секции. Они конкурируют за монитор, и захватить его сможет только один поток.

В продакшене `notifyAll()` часто безопаснее `notify()`, когда одно состояние ожидают разные потоки. Цена безопасности — больше пробуждений и конкуренции за монитор.

---

## Ожидание условия

**Определение:**

Ожидание условия — это приостановка потока до тех пор, пока состояние программы не станет подходящим для продолжения работы.

`wait()` обычно вызывают внутри цикла `while`, а не внутри `if`.

**Правильно:**

```java
synchronized (lock) {
    while (!dataReady) {
        lock.wait();
    }

    processData();
}
```

**Нежелательно:**

```java
synchronized (lock) {
    if (!dataReady) {
        lock.wait();
    }

    processData();
}
```

После пробуждения поток должен повторно проверить условие: другой поток мог уже изменить состояние, а пробуждение теоретически может произойти без ожидаемого уведомления.

## Producer–Consumer

**Определение:**

Producer–Consumer — модель взаимодействия потоков, в которой один поток создаёт данные, а другой их обрабатывает.

* Producer — производитель данных.
* Consumer — потребитель данных.

**Упрощённый пример:**

```java
public class MessageBox {
    private String message;
    private boolean hasMessage;

    public synchronized void put(String newMessage)
            throws InterruptedException {

        while (hasMessage) {
            wait();
        }

        message = newMessage;
        hasMessage = true;

        notifyAll();
    }

    public synchronized String take()
            throws InterruptedException {

        while (!hasMessage) {
            wait();
        }

        String result = message;
        hasMessage = false;

        notifyAll();

        return result;
    }
}
```

В современном продакшен-коде вместо ручной реализации через `wait()` и `notifyAll()` обычно используют готовые классы, например:

```java
BlockingQueue<String>
```

Готовая коллекция уменьшает вероятность написать собственный небольшой генератор взаимных блокировок.

---

## Взаимная блокировка — Deadlock

**Определение:**

Взаимная блокировка, или `deadlock`, — это ситуация, при которой несколько потоков бесконечно ожидают ресурсы, захваченные друг другом, и ни один поток не может продолжить выполнение.

Такое определение приводится в презентации на странице 8. 

**Пример:**

```java
public class DeadlockExample {
    private static final Object firstLock = new Object();
    private static final Object secondLock = new Object();

    public static void main(String[] args) {
        Thread firstThread = new Thread(() -> {
            synchronized (firstLock) {
                System.out.println("Первый поток захватил firstLock");

                synchronized (secondLock) {
                    System.out.println("Первый поток захватил secondLock");
                }
            }
        });

        Thread secondThread = new Thread(() -> {
            synchronized (secondLock) {
                System.out.println("Второй поток захватил secondLock");

                synchronized (firstLock) {
                    System.out.println("Второй поток захватил firstLock");
                }
            }
        });

        firstThread.start();
        secondThread.start();
    }
}
```

Возможная ситуация:

```text
Первый поток удерживает firstLock и ждёт secondLock.
Второй поток удерживает secondLock и ждёт firstLock.
```

Оба ждут. Никто не уступает. Корпоративная классика, только без совещания.

---

## Порядок захвата блокировок

**Определение:**

Порядок захвата блокировок — это установленное правило, согласно которому все потоки получают несколько блокировок в одинаковой последовательности.

Это один из основных способов предотвращения `deadlock`, указанных в презентации. 

**Опасно:**

```java
// Первый поток
synchronized (firstLock) {
    synchronized (secondLock) {
        // работа
    }
}

// Второй поток
synchronized (secondLock) {
    synchronized (firstLock) {
        // работа
    }
}
```

Порядок разный.

**Безопаснее:**

```java
// Все потоки сначала захватывают firstLock,
// а затем secondLock

synchronized (firstLock) {
    synchronized (secondLock) {
        // работа
    }
}
```

Главное правило:

```text
Если блокировок несколько, их порядок должен быть единым во всей программе.
```

---

## Неудачный захват блокировки

**Определение:**

Неудачный захват блокировки — ситуация, когда поток не может получить необходимую блокировку, потому что она уже занята.

Обычный `synchronized` будет ждать монитор без возможности самостоятельно отказаться от ожидания.

Для более гибкого поведения можно использовать `Lock` и метод `tryLock()`:

```java
Lock firstLock = new ReentrantLock();
Lock secondLock = new ReentrantLock();

if (firstLock.tryLock()) {
    try {
        if (secondLock.tryLock()) {
            try {
                System.out.println("Обе блокировки получены");
            } finally {
                secondLock.unlock();
            }
        }
    } finally {
        firstLock.unlock();
    }
}
```

Так поток может освободить уже полученный ресурс, если вторую блокировку захватить не удалось. Этот подход соответствует второму способу предотвращения взаимной блокировки из презентации: изменить поведение при неудачном захвате ресурса. 

---

## Конкуренция за блокировку — Lock contention

**Определение:**

Конкуренция за блокировку — это ситуация, когда несколько потоков часто пытаются захватить один и тот же монитор.

Пока один поток выполняет критическую секцию, остальные ждут.

Чем больше синхронизированный участок, тем:

* дольше удерживается монитор;
* больше потоков простаивает;
* ниже производительность многопоточной программы.

**Плохо:**

```java
public synchronized void process() {
    loadData();
    calculate();
    saveToDatabase();
    sendNotification();
}
```

Под блокировкой выполняется слишком много работы.

**Лучше:**

```java
public void process() {
    Data data = loadData();
    Result result = calculate(data);

    synchronized (lock) {
        state = result;
    }

    saveToDatabase(result);
    sendNotification(result);
}
```

Под блокировкой осталось только изменение общего состояния.

---

## Гранулярность блокировки

**Определение:**

Гранулярность блокировки — это размер участка программы или объём данных, защищённых одной блокировкой.

* Крупная гранулярность — один большой блок защищает много операций.
* Мелкая гранулярность — используются небольшие критические секции или несколько отдельных блокировок.

Крупная блокировка проще, но сильнее ограничивает параллельность. Мелкая повышает параллельность, но усложняет код и увеличивает риск взаимных блокировок.
