# Тема 4: Исключения и Stacktrace

## Исключение

**Определение:**

Исключение — это объект, который описывает ошибочную или нестандартную ситуацию, возникшую во время работы программы.

В Java исключения используются для того, чтобы программа могла сообщить об ошибке и, при необходимости, обработать её.

Например, исключение может возникнуть, если программа пытается обратиться к несуществующему символу строки, разделить число на ноль или открыть файл, которого нет.

**Пример:**

```java id="r7s2dk"
public class Main {
    public static void main(String[] args) {
        String text = "Hello";

        char symbol = text.charAt(10);

        System.out.println(symbol);
    }
}
```

Здесь возникнет исключение, потому что в строке `"Hello"` нет символа с индексом `10`.

---

## Exception

**Определение:**

`Exception` — это базовый класс для большинства ошибок, связанных с работой приложения.

Исключения типа `Exception` обычно описывают ситуации, которые могут возникнуть в нормальной работе программы: ошибка ввода, проблема с файлом, ошибка подключения и так далее.

`Exception` наследуется от класса `Throwable`.

**Пример:**

```java id="s3edng"
try {
    int result = 10 / 0;
} catch (Exception exception) {
    System.out.println("Произошла ошибка");
}
```

---

## Выброс исключения

**Определение:**

Выброс исключения — это момент, когда программа создаёт исключительную ситуацию и передаёт её дальше по цепочке вызовов.

Исключение может быть выброшено самой Java, например при делении на ноль, или вручную программистом через `throw`.

Когда исключение выброшено и не обработано, программа обычно завершает работу с ошибкой.

**Пример:**

```java id="6s2l15"
public static int divide(int a, int b) {
    if (b == 0) {
        throw new ArithmeticException("Делить на ноль нельзя");
    }

    return a / b;
}
```

---

## Обработка исключения

**Определение:**

Обработка исключения — это код, который выполняется, если в программе возникла ошибка.

В Java исключения обычно обрабатывают с помощью конструкции `try / catch`.

Обработка нужна, чтобы программа не падала сразу, а могла вывести понятное сообщение, запросить новые данные или выполнить запасной сценарий.

**Пример:**

```java id="sfg0j9"
try {
    int result = 10 / 0;
    System.out.println(result);
} catch (ArithmeticException exception) {
    System.out.println("Деление на ноль");
}
```

---

## try

**Определение:**

`try` — это ключевое слово Java, которое начинает блок кода, где может возникнуть исключение.

Внутрь `try` помещают потенциально опасный код.

Если внутри блока `try` возникает исключение, Java прекращает выполнение оставшейся части блока и ищет подходящий `catch`.

**Пример:**

```java id="xs7yms"
try {
    int result = 10 / 0;
    System.out.println(result);
}
```

---

## catch

**Определение:**

`catch` — это ключевое слово Java, которое начинает блок обработки исключения.

В `catch` указывается тип исключения, которое нужно перехватить.

Если в блоке `try` возникло подходящее исключение, Java передаёт управление в соответствующий блок `catch`.

**Пример:**

```java id="5vn4v6"
try {
    int result = 10 / 0;
} catch (ArithmeticException exception) {
    System.out.println("Делить на ноль нельзя");
}
```

---

## finally

**Определение:**

`finally` — это блок кода, который выполняется после `try / catch` независимо от того, возникло исключение или нет.

Обычно `finally` используют для освобождения ресурсов: закрытия файла, сетевого соединения, сканера и других объектов, которые нужно закрывать вручную.

**Пример:**

```java id="oeu8ke"
Scanner scanner = new Scanner(System.in);

try {
    int number = scanner.nextInt();
    System.out.println(number);
} catch (RuntimeException exception) {
    System.out.println("Ошибка ввода");
} finally {
    scanner.close();
}
```

---

## try / catch / finally

**Определение:**

`try / catch / finally` — это конструкция Java для обработки исключений.

Она состоит из трёх частей:

`try` — код, где может возникнуть ошибка.

`catch` — код, который обработает ошибку.

`finally` — код, который выполнится в любом случае.

**Пример:**

```java id="k42h5q"
try {
    int result = 100 / 0;
    System.out.println(result);
} catch (ArithmeticException exception) {
    System.out.println("Деление на ноль");
} finally {
    System.out.println("Блок finally выполнен");
}
```

---

## Throwable

**Определение:**

`Throwable` — это базовый класс для всех объектов, которые можно выбрасывать как ошибочные ситуации в Java.

От `Throwable` наследуются две основные ветки:

`Error` — серьёзные ошибки JVM и окружения.

`Exception` — исключения, связанные с работой приложения.

Обычно в прикладном коде работают с `Exception` и его наследниками, а `Throwable` напрямую почти не используют.

**Пример:**

```java id="evkhzp"
try {
    throw new Exception("Ошибка");
} catch (Throwable throwable) {
    System.out.println("Поймали Throwable");
}
```

---

## Error

**Определение:**

`Error` — это класс для серьёзных ошибок, связанных с работой JVM или её окружения.

Обычно такие ошибки не обрабатывают в обычном коде приложения, потому что программа часто не может корректно восстановиться после них.

Примеры:

`OutOfMemoryError`

`StackOverflowError`

`VirtualMachineError`

**Пример:**

```java id="db5ocg"
public static void recursiveMethod() {
    recursiveMethod();
}
```

Такой код может привести к `StackOverflowError`.

---

## RuntimeException

**Определение:**

`RuntimeException` — это базовый класс для непроверяемых исключений, которые возникают во время выполнения программы.

Такие исключения компилятор не требует обязательно обрабатывать.

Часто `RuntimeException` связан с ошибками логики программы: деление на ноль, неправильный индекс, обращение к `null`, неверное приведение типа.

**Пример:**

```java id="5z93cy"
int result = 10 / 0;
```

Этот код вызовет `ArithmeticException`, который наследуется от `RuntimeException`.

---

## Checked exception

**Определение:**

`Checked exception` — это проверяемое исключение, которое компилятор требует обработать.

Если метод может выбросить checked exception, программист обязан сделать одно из двух:

обработать исключение через `try / catch`;

или указать его в сигнатуре метода через `throws`.

Checked exceptions обычно связаны с внешними обстоятельствами: файлы, сеть, база данных, формат даты.

**Пример:**

```java id="cwp8hh"
public static Date parseDate(String input) throws ParseException {
    SimpleDateFormat format = new SimpleDateFormat("dd MM yyyy");

    return format.parse(input);
}
```

---

## Unchecked exception

**Определение:**

`Unchecked exception` — это непроверяемое исключение, которое компилятор не требует обязательно обрабатывать.

К unchecked exceptions относятся наследники `RuntimeException` и `Error`.

Такие исключения могут возникнуть во время выполнения программы.

В реальной разработке unchecked exceptions часто указывают на ошибку в логике программы или неправильное использование метода.

**Пример:**

```java id="yp6hvx"
String text = null;

System.out.println(text.length());
```

Этот код вызовет `NullPointerException`.

---

## ArithmeticException

**Определение:**

`ArithmeticException` — это unchecked exception, которое возникает при арифметической ошибке.

Самый частый пример — деление целого числа на ноль.

`ArithmeticException` наследуется от `RuntimeException`.

**Пример:**

```java id="v2v3zf"
int result = 100 / 0;
```

---

## StringIndexOutOfBoundsException

**Определение:**

`StringIndexOutOfBoundsException` — это unchecked exception, которое возникает при обращении к символу строки по несуществующему индексу.

Например, если строка содержит 5 символов, а программа пытается получить символ с индексом 10.

**Пример:**

```java id="vuk4yi"
String text = "Hello";

char symbol = text.charAt(10);
```

---

## NumberFormatException

**Определение:**

`NumberFormatException` — это unchecked exception, которое возникает, когда строку невозможно преобразовать в число.

Например, если попытаться преобразовать строку `"abc"` в `int`.

`NumberFormatException` наследуется от `RuntimeException`.

**Пример:**

```java id="4rwu3o"
int number = Integer.parseInt("abc");
```

---

## NullPointerException

**Определение:**

`NullPointerException` — это unchecked exception, которое возникает, когда программа пытается обратиться к объекту, которого нет.

То есть переменная содержит `null`, а программа пытается вызвать у неё метод или обратиться к полю.

**Пример:**

```java id="xw6b8p"
String text = null;

System.out.println(text.length());
```

---

## IndexOutOfBoundsException

**Определение:**

`IndexOutOfBoundsException` — это unchecked exception, которое возникает при обращении к элементу по индексу, которого не существует.

Например, при обращении к элементу списка, массива или строки за пределами допустимого диапазона.

**Пример:**

```java id="evzdaq"
List<String> names = List.of("Ann", "Bob");

System.out.println(names.get(5));
```

---

## ClassCastException

**Определение:**

`ClassCastException` — это unchecked exception, которое возникает при неправильном приведении типа.

Например, если объект фактически является `String`, а программист пытается привести его к `Integer`.

**Пример:**

```java id="m7jfsi"
Object value = "Hello";

Integer number = (Integer) value;
```

---

## IOException

**Определение:**

`IOException` — это checked exception, которое возникает при ошибках ввода-вывода.

Например, при работе с файлами, потоками данных, сетевыми соединениями.

Так как это checked exception, Java требует обработать его или указать через `throws`.

**Пример:**

```java id="5lo4cv"
public static String readFile(String path) throws IOException {
    return Files.readString(Path.of(path));
}
```

---

## FileNotFoundException

**Определение:**

`FileNotFoundException` — это checked exception, которое возникает, если программа пытается открыть файл, который не найден.

Это частный случай `IOException`.

**Пример:**

```java id="ujilhu"
FileInputStream inputStream = new FileInputStream("missing-file.txt");
```

---

## SQLException

**Определение:**

`SQLException` — это checked exception, которое возникает при ошибках работы с базой данных.

Например, при ошибке SQL-запроса, проблемах подключения или нарушении ограничений базы данных.

**Пример:**

```java id="vlo87z"
public void saveUser() throws SQLException {
    // код работы с базой данных
}
```

---

## throws

**Определение:**

`throws` — это ключевое слово Java, которое указывается в сигнатуре метода и сообщает, что метод может выбросить исключение.

`throws` не обрабатывает исключение, а передаёт ответственность выше — тому коду, который будет вызывать этот метод.

Чаще всего `throws` используют с checked exceptions.

**Пример:**

```java id="ii5k7l"
public static Date parseDate(String inputDate) throws ParseException {
    SimpleDateFormat dateFormat = new SimpleDateFormat("dd MM yyyy");

    return dateFormat.parse(inputDate);
}
```

---

## throw

**Определение:**

`throw` — это ключевое слово Java, которое используется для ручного выброса исключения.

Через `throw` программист сам создаёт исключение и останавливает нормальное выполнение метода.

Обычно `throw` используют, когда метод получил некорректные данные и не может продолжать работу.

**Пример:**

```java id="9dy9yy"
public static void validateAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("Возраст не может быть отрицательным");
    }
}
```

---

## throw new Exception

**Определение:**

`throw new Exception` — это создание и выброс нового объекта исключения.

`new Exception(...)` создаёт объект ошибки, а `throw` выбрасывает его.

В реальной разработке обычно лучше выбрасывать не общий `Exception`, а более конкретный тип исключения.

**Пример:**

```java id="mn3zcp"
public static void checkValue(int value) throws Exception {
    if (value <= 0) {
        throw new Exception("Значение должно быть больше нуля");
    }
}
```

---

## Поток ошибок

**Определение:**

Поток ошибок — это специальный поток вывода, куда Java по умолчанию выводит сообщения об ошибках и stacktrace.

Обычно это консоль.

В Java поток ошибок представлен как `System.err`.

**Пример:**

```java id="t1m8lg"
System.err.println("Ошибка");
```

---

## Ресурс

**Определение:**

Ресурс — это внешний объект, с которым работает программа и который нужно закрывать после использования.

Примеры ресурсов:

файл;

сетевое соединение;

соединение с базой данных;

`Scanner`, читающий данные из внешнего источника.

Если ресурс не закрыть, программа может расходовать лишнюю память или блокировать файл.

**Пример:**

```java id="a11vlg"
Scanner scanner = new Scanner(System.in);

// работа со scanner

scanner.close();
```

---

## close()

**Определение:**

`close()` — это метод, который закрывает ресурс и освобождает связанные с ним системные возможности.

Его вызывают после завершения работы с файлом, сканером, сетевым соединением и другими ресурсами.

В современном Java-коде для закрытия ресурсов часто используют `try-with-resources`.

**Пример:**

```java id="860d3v"
Scanner scanner = new Scanner(System.in);

try {
    String text = scanner.nextLine();
    System.out.println(text);
} finally {
    scanner.close();
}
```

---

## try-with-resources

**Определение:**

`try-with-resources` — это специальная форма `try`, которая автоматически закрывает ресурс после завершения работы.

Ресурс должен реализовывать интерфейс `AutoCloseable` или `Closeable`.

Это более безопасный и чистый способ закрывать файлы, сканеры и другие ресурсы.

**Пример:**

```java id="gim63f"
try (Scanner scanner = new Scanner(System.in)) {
    String text = scanner.nextLine();

    System.out.println(text);
}
```

После выхода из блока `try` метод `close()` будет вызван автоматически.

---

## Closeable

**Определение:**

`Closeable` — это интерфейс Java для объектов, которые можно закрывать.

Классы, реализующие `Closeable`, можно использовать в `try-with-resources`.

Например, многие классы для работы с файлами и потоками данных реализуют этот интерфейс.

**Пример:**

```java id="nx5s1x"
try (FileInputStream inputStream = new FileInputStream("data.txt")) {
    int value = inputStream.read();

    System.out.println(value);
}
```

---

## Множественный catch

**Определение:**

Множественный `catch` — это несколько блоков `catch`, расположенных после одного `try`.

Он используется, когда разные исключения нужно обработать по-разному.

Важно: сначала нужно ловить более конкретные исключения, а потом более общие.

**Пример:**

```java id="6dqc8x"
try {
    int value = Integer.parseInt("abc");
    int result = value / 0;
} catch (NumberFormatException exception) {
    System.out.println("Ошибка преобразования строки в число");
} catch (ArithmeticException exception) {
    System.out.println("Деление на ноль");
} catch (RuntimeException exception) {
    System.out.println("Другая ошибка времени выполнения");
}
```

---

## Multi-catch

**Определение:**

`Multi-catch` — это один блок `catch`, который обрабатывает несколько типов исключений одинаковым способом.

Типы исключений перечисляются через оператор `|`.

Такой подход уменьшает дублирование кода.

**Пример:**

```java id="ka5wjj"
try {
    int value = Integer.parseInt("abc");
    int result = value / 0;
} catch (NumberFormatException | ArithmeticException exception) {
    System.out.println("Введённые данные некорректны");
}
```

---

## Порядок catch-блоков

**Определение:**

Порядок `catch`-блоков — это правило, по которому сначала нужно указывать более конкретные исключения, а потом более общие.

Если сначала поймать родительский тип, например `RuntimeException`, то дочерний тип, например `ArithmeticException`, уже никогда не будет достигнут.

Java не позволит написать недостижимый `catch`.

**Пример:**

Правильно:

```java id="kvkzn2"
try {
    int result = 10 / 0;
} catch (ArithmeticException exception) {
    System.out.println("Деление на ноль");
} catch (RuntimeException exception) {
    System.out.println("Ошибка выполнения");
}
```

Неправильно:

```java id="ii4o7c"
try {
    int result = 10 / 0;
} catch (RuntimeException exception) {
    System.out.println("Ошибка выполнения");
} catch (ArithmeticException exception) {
    System.out.println("Деление на ноль");
}
```

---

## Собственное исключение

**Определение:**

Собственное исключение — это класс исключения, который программист создаёт сам под конкретную ошибочную ситуацию в своей программе.

Собственные исключения делают ошибки более понятными.

Например, вместо непонятного `ArrayIndexOutOfBoundsException` можно выбросить `NameInputMismatchException` с нормальным сообщением для разработчика.

**Пример:**

```java id="3vqdvm"
public class NameInputMismatchException extends RuntimeException {

    public NameInputMismatchException(String text) {
        super("В параметре надо указать имя и фамилию, но было указано: " + text);
    }
}
```

---

## Пользовательское checked exception

**Определение:**

Пользовательское checked exception — это собственное исключение, которое наследуется от `Exception`.

Такое исключение компилятор заставит обработать через `try / catch` или указать через `throws`.

Используется, когда ошибка ожидаемая и вызывающий код должен явно решить, что с ней делать.

**Пример:**

```java id="lem875"
public class InvalidDateException extends Exception {

    public InvalidDateException(String message) {
        super(message);
    }
}
```

---

## Пользовательское unchecked exception

**Определение:**

Пользовательское unchecked exception — это собственное исключение, которое наследуется от `RuntimeException`.

Компилятор не требует обязательно его обрабатывать.

Используется, когда ошибка говорит о неправильном использовании метода или нарушении бизнес-правила.

**Пример:**

```java id="l5pesx"
public class NameInputMismatchException extends RuntimeException {

    public NameInputMismatchException(String text) {
        super("Ожидались имя и фамилия, но было указано: " + text);
    }
}
```

---

## Сообщение исключения

**Определение:**

Сообщение исключения — это текстовое описание ошибки, которое передаётся в конструктор исключения.

Хорошее сообщение помогает быстрее понять, что пошло не так.

В продакшене сообщение должно объяснять причину ошибки, но не раскрывать лишние технические или чувствительные данные пользователю.

**Пример:**

```java id="y4ms8e"
throw new IllegalArgumentException("Возраст не может быть отрицательным: " + age);
```

---

## Stack

**Определение:**

`Stack` — это стек вызовов методов, который JVM хранит во время выполнения программы.

Когда один метод вызывает другой, новый вызов помещается сверху стека.

Когда метод завершает работу, он удаляется из стека.

Если во время выполнения возникает исключение, Java использует стек, чтобы показать путь, по которому программа пришла к ошибке.

**Пример:**

```java id="l3pjeq"
public static void main(String[] args) {
    first();
}

public static void first() {
    second();
}

public static void second() {
    int result = 10 / 0;
}
```

---

## Stacktrace

**Определение:**

`Stacktrace` — это список вызовов методов, который показывает, где именно возникла ошибка и через какие методы программа к ней пришла.

Stacktrace читают снизу вверх или сверху вниз в зависимости от задачи:

верхние строки обычно показывают ближайшее место ошибки;

нижние строки показывают, откуда началась цепочка вызовов.

При ошибке первым делом нужно смотреть stacktrace. Он часто сразу показывает класс, метод и строку, где произошла проблема.

**Пример:**

```java id="y8cg67"
Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Main.second(Main.java:12)
    at Main.first(Main.java:8)
    at Main.main(Main.java:4)
```

Здесь ошибка возникла в методе `second()` на строке 12.

---

## printStackTrace()

**Определение:**

`printStackTrace()` — это метод класса `Throwable`, который выводит stacktrace исключения в консоль.

Он полезен при обучении и отладке.

В продакшене вместо прямого `printStackTrace()` обычно используют логирование через logger.

**Пример:**

```java id="afvat7"
try {
    int result = 10 / 0;
} catch (ArithmeticException exception) {
    exception.printStackTrace();
}
```

---

## getStackTrace()

**Определение:**

`getStackTrace()` — это метод класса `Throwable`, который возвращает stacktrace в виде массива элементов `StackTraceElement`.

Его используют, когда stacktrace нужно не просто вывести, а обработать программно.

**Пример:**

```java id="q4y8td"
try {
    int result = 10 / 0;
} catch (ArithmeticException exception) {
    StackTraceElement[] stackTrace = exception.getStackTrace();

    System.out.println(stackTrace[0]);
}
```

---

## Caused by

**Определение:**

`Caused by` — это часть stacktrace, которая показывает исходную причину ошибки.

Одна ошибка может быть обёрнута в другую.

Например, приложение может выбросить своё исключение, причиной которого была ошибка базы данных.

В таких случаях `Caused by` помогает добраться до настоящего источника проблемы.

**Пример:**

```java id="y34pdp"
throw new RuntimeException("Не удалось сохранить пользователя", originalException);
```

В stacktrace может появиться блок:

```java id="no2t14"
Caused by: java.sql.SQLException: duplicate value
```

---

## Scanner

**Определение:**

`Scanner` — это класс Java для считывания данных.

Его часто используют для чтения пользовательского ввода из консоли.

`Scanner` может читать строки, числа и другие типы данных.

Так как `Scanner` работает с источником данных, его желательно закрывать после использования.

**Пример:**

```java id="1eltgp"
Scanner scanner = new Scanner(System.in);

System.out.println("Введите число:");
int number = scanner.nextInt();

scanner.close();
```

---

## Integer.parseInt()

**Определение:**

`Integer.parseInt()` — это статический метод Java, который преобразует строку в число типа `int`.

Если строка не является корректным целым числом, метод выбросит `NumberFormatException`.

**Пример:**

```java id="fl6sca"
int number = Integer.parseInt("123");
```

Ошибка:

```java id="9jdxuw"
int number = Integer.parseInt("abc");
```
