# Тема 2: Полиморфизм

## Полиморфизм

**Определение:**

Полиморфизм — это принцип ООП, при котором объект может использоваться как объект родительского типа, но при этом выполнять методы по-своему.

То есть код работает с общим типом, например `Figure`, но реальное поведение зависит от конкретного объекта: `Triangle`, `Circle`, `Rectangle` и так далее.

Главная идея: один общий интерфейс поведения — разные реализации.

В продакшене полиморфизм нужен, чтобы писать гибкий код без большого количества `if / else` и проверок типа объекта.

**Пример:**

```java
public class Figure {
    public double getArea() {
        throw new RuntimeException("Not implemented");
    }
}

public class Circle extends Figure {
    private double radius;

    public Circle(double radius) {
        this.radius = radius;
    }

    @Override
    public double getArea() {
        return Math.PI * radius * radius;
    }
}

public class Rectangle extends Figure {
    private double width;
    private double height;

    public Rectangle(double width, double height) {
        this.width = width;
        this.height = height;
    }

    @Override
    public double getArea() {
        return width * height;
    }
}
```

## Базовый тип

**Определение:**

Базовый тип — это тип родительского класса, через который можно работать с объектами дочерних классов.

Например, если `Triangle`, `Circle` и `Rectangle` наследуются от `Figure`, то переменная типа `Figure` может хранить объект любого из этих классов.

Это основа полиморфизма: мы пишем код под общий тип, а не под каждый конкретный класс отдельно.

**Пример:**

```java
Figure figure1 = new Circle(10);
Figure figure2 = new Rectangle(5, 7);
```

Здесь переменные имеют тип `Figure`, но реальные объекты разные.

---

## Конкретный тип

**Определение:**

Конкретный тип — это реальный класс объекта, который находится в памяти.

Например, переменная может иметь тип `Figure`, но внутри неё может лежать объект конкретного класса `Circle`.

Компилятор смотрит на тип переменной, а JVM во время выполнения вызывает метод реального объекта.

**Пример:**

```java
Figure figure = new Circle(10);

System.out.println(figure.getArea());
```

Тип переменной — `Figure`.

Конкретный объект — `Circle`.

Будет вызван метод `getArea()` из класса `Circle`.

---

## Поведение объекта

**Определение:**

Поведение объекта — это набор действий, которые объект умеет выполнять через свои методы.

При полиморфизме разные классы могут иметь одинаковые методы, но выполнять их по-разному.

Например, все фигуры умеют считать площадь, но формула для круга, прямоугольника и треугольника разная.

**Пример:**

```java
public class Triangle extends Figure {
    @Override
    public double getArea() {
        return 100.0;
    }
}

public class Circle extends Figure {
    @Override
    public double getArea() {
        return 314.0;
    }
}
```

Метод называется одинаково — `getArea()`.

Поведение разное.

---

## Общий метод

**Определение:**

Общий метод — это метод, который объявлен в родительском классе и есть у всех дочерних классов.

При этом каждый дочерний класс может реализовать этот метод по-своему.

Например, метод `getArea()` есть у всех фигур, но каждая фигура считает площадь по своей формуле.

**Пример:**

```java
public class Figure {
    public double getArea() {
        throw new RuntimeException("Not implemented");
    }
}

public class Circle extends Figure {
    @Override
    public double getArea() {
        return 314.0;
    }
}
```

---

## NotImplementedException

**Определение:**

`NotImplementedException` — это исключение, которое означает, что метод объявлен, но его логика ещё не реализована.

В учебных примерах его используют как временную заглушку.

В обычной Java такого стандартного исключения нет. Часто вместо него используют `UnsupportedOperationException` или создают собственное исключение.

В реальной разработке лучше не оставлять такие методы без необходимости. Если родительский класс не может реализовать метод, чаще используют абстрактный класс или интерфейс.

**Пример:**

```java
public class Figure {
    public double getArea() {
        throw new UnsupportedOperationException("Метод должен быть реализован в дочернем классе");
    }
}
```

---

## Заглушка

**Определение:**

Заглушка — это временная простая реализация класса или метода, которая нужна, чтобы код можно было писать и тестировать дальше.

Заглушка не содержит полноценной логики, но имитирует нужную часть программы.

Например, если в Android уже есть класс `Color`, но в учебном проекте Android не используется, можно временно создать свой простой класс `Color`.

**Пример:**

```java
public class Color {
    private String name;

    public Color(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }
}
```

---

## Иерархия классов

**Определение:**

Иерархия классов — это структура, в которой классы связаны наследованием.

Обычно есть общий родительский класс и несколько дочерних классов, которые уточняют или расширяют его поведение.

Например, `Figure` — общий класс, а `Circle`, `Triangle`, `Rectangle` — конкретные виды фигур.

**Пример:**

```java
public class Figure {
}

public class Circle extends Figure {
}

public class Rectangle extends Figure {
}

public class Triangle extends Figure {
}
```

---

## Процедурный подход

**Определение:**

Процедурный подход — это стиль программирования, при котором логика строится вокруг функций и условий.

Например, чтобы посчитать площадь фигуры, программа проверяет тип фигуры через `if / else` и выбирает нужную формулу.

Такой подход может быстро стать неудобным: при добавлении новой фигуры нужно менять уже существующий код.

**Пример:**

```java
public double getArea(Figure figure) {
    if (figure.getType().equals("CIRCLE")) {
        return Math.PI * 10 * 10;
    } else if (figure.getType().equals("RECTANGLE")) {
        return 5 * 7;
    }

    return 0;
}
```

Минус такого подхода: чем больше типов, тем больше условий.

---

## ООП-подход

**Определение:**

ООП-подход — это стиль программирования, при котором логика распределяется между объектами.

Вместо того чтобы снаружи проверять тип фигуры, каждая фигура сама знает, как считать свою площадь и периметр.

Это делает код расширяемым: чтобы добавить новую фигуру, можно создать новый класс, не переписывая общий код.

**Пример:**

```java
public static void printArea(Figure figure) {
    System.out.println(figure.getArea());
}
```

Метод `printArea()` не знает, какая конкретно фигура пришла.

Он просто вызывает общий метод `getArea()`.

---

## Расширение типа

**Определение:**

Расширение типа — это приведение объекта дочернего класса к типу родительского класса.

В Java такое приведение выполняется автоматически.

Например, объект `Triangle` можно сохранить в переменную типа `Figure`, потому что треугольник является фигурой.

Расширение типа безопасно, потому что дочерний объект всегда является объектом родительского типа.

**Пример:**

```java
Triangle triangle = new Triangle();

Figure figure = triangle;
```

Или сразу:

```java
Figure figure = new Triangle();
```

---

## Сужение типа

**Определение:**

Сужение типа — это приведение объекта родительского типа к дочернему типу.

Такое приведение Java автоматически не делает, потому что оно может быть небезопасным.

Например, переменная типа `Figure` может хранить `Triangle`, а может хранить `Circle`. Поэтому перед приведением нужно быть уверенным, какой объект лежит внутри.

**Пример:**

```java
Figure figure = new Triangle();

Triangle triangle = (Triangle) figure;
```

Этот код сработает, потому что внутри `figure` действительно лежит `Triangle`.

---

## ClassCastException

**Определение:**

`ClassCastException` — это ошибка времени выполнения, которая возникает при неправильном приведении типа.

Например, если внутри переменной типа `Figure` лежит `Triangle`, а программист пытается привести его к `Rectangle`, программа упадёт.

В продакшене такие ошибки стараются предотвращать через правильную архитектуру, полиморфизм и проверку `instanceof`, если она действительно нужна.

**Пример:**

```java
Figure figure = new Triangle();

Rectangle rectangle = (Rectangle) figure;
```

Этот код приведёт к ошибке, потому что реальный объект — `Triangle`, а не `Rectangle`.

---

## instanceof

**Определение:**

`instanceof` — это оператор Java, который проверяет, является ли объект экземпляром определённого класса или его наследника.

Его часто используют перед сужением типа, чтобы избежать `ClassCastException`.

Но если в коде слишком много `instanceof`, это может быть признаком, что полиморфизм используется неправильно.

**Пример:**

```java
Figure figure = new Triangle();

if (figure instanceof Triangle) {
    Triangle triangle = (Triangle) figure;
}
```

---

## Динамическое связывание

**Определение:**

Динамическое связывание — это механизм, при котором Java выбирает, какую версию переопределённого метода вызвать, во время выполнения программы.

Компилятор знает только тип переменной, например `Figure`.

Но во время выполнения JVM смотрит на реальный объект, например `Triangle`, и вызывает метод из него.

**Пример:**

```java
Figure figure = new Triangle();

figure.getArea();
```

Если `Triangle` переопределил метод `getArea()`, будет вызвана версия из `Triangle`, а не из `Figure`.

---

## Тип переменной

**Определение:**

Тип переменной — это тип, который указан слева при объявлении переменной.

Он определяет, какие методы можно вызвать через эту переменную на этапе компиляции.

Если переменная имеет тип `Figure`, то через неё можно вызвать только те методы, которые есть у `Figure`, даже если внутри лежит объект `Triangle`.

**Пример:**

```java
Figure figure = new Triangle();

figure.getArea();
```

Если у `Triangle` есть метод `drawTriangleOnly()`, но у `Figure` такого метода нет, то так вызвать нельзя:

```java
figure.drawTriangleOnly();
```

---

## Реальный объект

**Определение:**

Реальный объект — это объект, который фактически создан через `new`.

Именно реальный объект определяет, какая версия переопределённого метода будет выполнена.

Тип переменной ограничивает доступные методы, а реальный объект определяет поведение этих методов.

**Пример:**

```java
Figure figure = new Circle();
```

Тип переменной:

```java
Figure
```

Реальный объект:

```java
Circle
```

---

## Метод, принимающий базовый класс

**Определение:**

Метод, принимающий базовый класс, — это метод, параметр которого имеет тип родительского класса.

Такой метод может принимать объекты любых дочерних классов.

Это один из самых полезных вариантов применения полиморфизма.

**Пример:**

```java
public static void addFigure(Figure figure) {
    totalPerimeter += figure.getPerimeter();
    totalArea += figure.getArea();
}
```

Такой метод может принять:

```java
addFigure(new Triangle());
addFigure(new Rectangle());
addFigure(new Circle());
```

## Универсальный код

**Определение:**

Универсальный код — это код, который работает не с конкретными классами, а с общим типом.

Например, метод может принимать `Figure`, а не отдельно `Circle`, `Triangle` и `Rectangle`.

Такой код проще расширять: если появится новый класс `Ellipse`, метод не придётся переписывать, если `Ellipse` тоже наследуется от `Figure`.

**Пример:**

```java
public static void printArea(Figure figure) {
    System.out.println(figure.getArea());
}
```

## Площадь фигуры

**Определение:**

Площадь фигуры — это числовая характеристика, которую можно посчитать для разных геометрических фигур.

С точки зрения Java-разработки важно не сама формула, а то, что метод `getArea()` может быть общим для всех фигур, но реализован по-разному.

**Пример:**

```java
public class Rectangle extends Figure {
    private double width;
    private double height;

    @Override
    public double getArea() {
        return width * height;
    }
}
```

---

## Периметр фигуры

**Определение:**

Периметр фигуры — это сумма длин её сторон или длина границы фигуры.

В ООП метод `getPerimeter()` можно объявить в базовом классе `Figure`, а конкретные фигуры будут считать периметр по своим правилам.

**Пример:**

```java
public class Rectangle extends Figure {
    private double width;
    private double height;

    @Override
    public double getPerimeter() {
        return 2 * (width + height);
    }
}
```

## Point

**Определение:**

`Point` — это вспомогательный класс, который описывает точку на плоскости.

Обычно точка содержит координаты `x` и `y`.

Такой класс можно использовать для описания положения фигур: вершин треугольника, концов линии и других геометрических объектов.

**Пример:**

```java
public class Point {
    private int x;
    private int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int getX() {
        return x;
    }

    public int getY() {
        return y;
    }
}
```

## Статический метод

**Определение:**

Статический метод — это метод, который принадлежит классу, а не конкретному объекту.

Он объявляется с помощью ключевого слова `static`.

Такой метод можно вызвать через имя класса.

Например, метод `getDistance()` можно сделать статическим, потому что для расчёта расстояния между двумя точками не нужно создавать отдельный объект-сервис.

**Пример:**

```java
public class Point {
    private int x;
    private int y;

    public static double getDistance(Point p1, Point p2) {
        return Math.sqrt(
                Math.pow(p2.x - p1.x, 2)
                        + Math.pow(p2.y - p1.y, 2)
        );
    }
}
```

---

## Math.sqrt()

**Определение:**

`Math.sqrt()` — это статический метод Java, который возвращает квадратный корень числа.

Он находится в стандартном классе `Math`.

В геометрических задачах его часто используют для расчёта расстояния между точками.

**Пример:**

```java
double result = Math.sqrt(25);

System.out.println(result); // 5.0
```

---

## Math.pow()

**Определение:**

`Math.pow()` — это статический метод Java, который возводит число в степень.

Первый аргумент — число, второй аргумент — степень.

Например, `Math.pow(5, 2)` означает 5 во второй степени.

**Пример:**

```java
double result = Math.pow(5, 2);

System.out.println(result); // 25.0
```

---

## Формула Герона

**Определение:**

Формула Герона — это формула для вычисления площади треугольника по трём сторонам.

В программировании её можно использовать, если треугольник задан тремя точками: сначала считаются длины сторон, затем полупериметр, затем площадь.

**Пример:**

```java
public double getArea() {
    double sideA = Point.getDistance(a, b);
    double sideB = Point.getDistance(b, c);
    double sideC = Point.getDistance(c, a);

    double halfPerimeter = getPerimeter() / 2.0;

    return Math.sqrt(
            halfPerimeter
                    * (halfPerimeter - sideA)
                    * (halfPerimeter - sideB)
                    * (halfPerimeter - sideC)
    );
}
```

---

## Полупериметр

**Определение:**

Полупериметр — это половина периметра фигуры.

В формуле Герона полупериметр используется для вычисления площади треугольника.

**Пример:**

```java
double halfPerimeter = getPerimeter() / 2.0;
```

## Частичное изменение поведения

**Определение:**

Частичное изменение поведения — это ситуация, когда дочерний класс не полностью заменяет метод родителя, а использует родительскую версию и добавляет к ней свою логику.

Для этого внутри переопределённого метода вызывают метод родителя через `super`.

Такой подход удобен, когда базовое поведение правильное, но его нужно немного расширить.

**Пример:**

```java
public class Figure {
    public Color getFillColor() {
        return new Color("красный");
    }
}

public class TransparentTriangle extends Figure {
    @Override
    public Color getFillColor() {
        Color originalColor = super.getFillColor();

        return new Color("полупрозрачный " + originalColor.getName());
    }
}
```
