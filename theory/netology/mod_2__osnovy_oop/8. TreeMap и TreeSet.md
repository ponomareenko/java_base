# Тема 8: Коллекции TreeMap и TreeSet

## TreeMap

**Определение:**

`TreeMap` — это реализация интерфейса `Map`, которая хранит пары «ключ-значение» в отсортированном порядке по ключам.

В отличие от `HashMap`, где порядок элементов не гарантируется, `TreeMap` всегда поддерживает порядок ключей.

Сортировка происходит либо по естественному порядку ключей, либо по правилам, заданным через `Comparator`.

**Пример:**

```java id="xqu42z"
Map<Integer, String> users = new TreeMap<>();

users.put(3, "Alex");
users.put(1, "Ivan");
users.put(2, "Semen");

System.out.println(users);
// {1=Ivan, 2=Semen, 3=Alex}
```

---

## Сортировка по ключу

**Определение:**

Сортировка по ключу — это принцип работы `TreeMap`, при котором порядок элементов определяется не значениями, а ключами.

Если ключи — числа, они сортируются по возрастанию.

Если ключи — строки, они сортируются в естественном строковом порядке.

**Пример:**

```java id="yef827"
Map<String, Integer> ages = new TreeMap<>();

ages.put("Tanya", 15);
ages.put("Petya", 8);
ages.put("Olya", 12);

System.out.println(ages);
// {Olya=12, Petya=8, Tanya=15}
```

---

## Естественный порядок

**Определение:**

Естественный порядок — это порядок сортировки, который уже определён для стандартных типов Java.

Например:

`Integer` сортируется по числовому возрастанию;

`String` сортируется лексикографически, то есть примерно как в словаре;

`LocalDate` сортируется по дате.

Естественный порядок работает через интерфейс `Comparable`.

**Пример:**

```java id="ngfw04"
Set<Integer> numbers = new TreeSet<>();

numbers.add(30);
numbers.add(10);
numbers.add(20);

System.out.println(numbers);
// [10, 20, 30]
```

---

## Лексикографический порядок

**Определение:**

Лексикографический порядок — это порядок сортировки строк, похожий на словарный.

Строки сравниваются символ за символом.

Именно такой порядок используется у `String` по умолчанию.

**Пример:**

```java id="la9nge"
Set<String> words = new TreeSet<>();

words.add("abc");
words.add("bcd");
words.add("amc");

System.out.println(words);
// [abc, amc, bcd]
```

---

## Красно-чёрное дерево

**Определение:**

Красно-чёрное дерево — это самобалансирующееся бинарное дерево поиска.

Именно на такой структуре данных основаны `TreeMap` и `TreeSet`.

Благодаря балансировке дерево не превращается в длинную цепочку, а операции поиска, добавления и удаления остаются достаточно быстрыми.

Для `TreeMap` основные операции `get()`, `put()`, `remove()` и `containsKey()` выполняются за `O(log n)`.

**Пример:**

```java id="ztdp4w"
// Разработчик напрямую не создаёт красно-чёрное дерево.
// Оно используется внутри TreeMap:

Map<Integer, String> map = new TreeMap<>();
```

---

## Дерево

**Определение:**

Дерево — это структура данных, состоящая из узлов и связей между ними.

Один узел является корнем.

Узлы могут иметь дочерние узлы.

Узлы без дочерних элементов называются листьями.

В коллекциях вроде `TreeMap` дерево помогает хранить элементы в отсортированном виде.

**Пример:**

```java id="dozsvd"
// Упрощённо дерево можно представить так:
//
//        10
//       /  \
//      5    20
//     / \
//    3   7
```

---

## Узел

**Определение:**

Узел — это один элемент дерева.

Внутри `TreeMap` узел хранит ключ, значение и ссылки на соседние узлы дерева.

Разработчик обычно не работает с узлами напрямую, но понимание узлов помогает понять, почему `TreeMap` хранит данные отсортированно.

**Пример:**

```java id="lf2zir"
// Упрощённо один узел TreeMap можно представить так:
//
// key = 10
// value = "Ivan"
// left = ссылка на меньший ключ
// right = ссылка на больший ключ
```

---

## Корень дерева

**Определение:**

Корень дерева — это главный узел дерева, с которого начинается поиск.

У корня нет родительского узла.

При поиске в бинарном дереве сравнение начинается именно с корня.

**Пример:**

```java id="s2yrzd"
//        13  <- корень
//       /  \
//      8    17
```

---

## Лист дерева

**Определение:**

Лист дерева — это узел, у которого нет дочерних узлов.

Если поиск дошёл до листа и нужный элемент не найден, значит такого элемента в дереве нет.

**Пример:**

```java id="xutzh1"
//        13
//       /  \
//      8    17
//     /
//    1  <- лист
```

---

## Бинарное дерево

**Определение:**

Бинарное дерево — это дерево, в котором каждый узел может иметь не больше двух дочерних узлов.

Обычно левый потомок содержит меньшее значение, а правый — большее.

Такой принцип позволяет искать элементы быстрее, чем обычным перебором.

**Пример:**

```java id="wx08rj"
//        10
//       /  \
//      5    20
//
// 5 меньше 10, поэтому слева.
// 20 больше 10, поэтому справа.
```

---

## Сбалансированное дерево

**Определение:**

Сбалансированное дерево — это дерево, в котором высота ветвей поддерживается примерно одинаковой.

Это важно для скорости.

Если дерево не балансировать, оно может превратиться почти в обычный список, и поиск станет медленным.

`TreeMap` использует красно-чёрное дерево, чтобы поддерживать баланс автоматически.

**Пример:**

```java id="jvj48r"
// Плохо, похоже на список:
//
// 1
//  \
//   2
//    \
//     3
//      \
//       4
//
// Хорошо:
//
//      2
//     / \
//    1   3
//         \
//          4
```

## O(log n)

**Определение:**

`O(log n)` — это сложность алгоритма, при которой количество действий растёт медленно даже при большом количестве элементов.

В `TreeMap` и `TreeSet` операции поиска, добавления и удаления обычно работают за `O(log n)`.

Это медленнее, чем среднее `O(1)` у `HashMap`, но зато данные всегда хранятся отсортированно.

**Пример:**

```java id="u0bc67"
Map<Integer, String> users = new TreeMap<>();

users.put(1, "Ivan");
users.put(2, "Semen");
users.put(3, "Alex");

System.out.println(users.get(2));
```

## SortedMap

**Определение:**

`SortedMap` — это интерфейс для `Map`, в которой ключи хранятся в отсортированном порядке.

`TreeMap` реализует `SortedMap`.

Через `SortedMap` доступны методы для работы с первым ключом, последним ключом и диапазонами ключей.

**Пример:**

```java id="m2w2oa"
SortedMap<Integer, String> users = new TreeMap<>();

users.put(3, "Alex");
users.put(1, "Ivan");
users.put(2, "Semen");

System.out.println(users.firstKey()); // 1
System.out.println(users.lastKey());  // 3
```

---

## NavigableMap

**Определение:**

`NavigableMap` — это интерфейс, который расширяет возможности `SortedMap`.

Он позволяет не просто хранить ключи отсортированно, но и искать ближайшие ключи:

больше или равно;

меньше или равно;

строго больше;

строго меньше.

`TreeMap` реализует `NavigableMap`.

**Пример:**

```java id="qghqcp"
NavigableMap<Integer, String> users = new TreeMap<>();

users.put(10, "Ivan");
users.put(20, "Semen");
users.put(30, "Alex");

System.out.println(users.ceilingKey(15)); // 20
System.out.println(users.floorKey(15));   // 10
```

## firstKey()

**Определение:**

`firstKey()` — это метод `SortedMap`, который возвращает первый, то есть наименьший ключ.

Если `TreeMap` отсортирована по возрастанию, `firstKey()` вернёт минимальный ключ.

**Пример:**

```java id="ba5j0y"

System.out.println(users.firstKey()); // 1
```


## headMap()

**Определение:**

`headMap()` — это метод `SortedMap` или `NavigableMap`, который возвращает часть `Map` до указанного ключа.

У `NavigableMap` можно дополнительно указать, включать ли граничный ключ в результат.

**Пример:**

```java id="n4yqwz"

map.put(3, "C");

System.out.println(map.headMap(3, true));
// {1=A, 2=B, 3=C}

System.out.println(map.headMap(3, false));
// {1=A, 2=B}
```

## tailMap()

**Определение:**

`tailMap()` — это метод `SortedMap` или `NavigableMap`, который возвращает часть `Map`, начиная с указанного ключа.


**Определение:**

## descendingMap()

**Определение:**

`descendingMap()` — это метод `NavigableMap`, который возвращает представление `Map` в обратном порядке.

Если исходная `TreeMap` идёт от меньшего ключа к большему, `descendingMap()` даст порядок от большего к меньшему.


## null-ключ в TreeMap

**Определение:**

`TreeMap` обычно не позволяет использовать `null` в качестве ключа при естественной сортировке.

Причина: ключи нужно сравнивать между собой, а у `null` нельзя вызвать `compareTo()`.

В отличие от `HashMap`, где один `null`-ключ разрешён, в `TreeMap` с естественным порядком это приведёт к ошибке.

**Пример:**

```java id="bno225"
Map<String, Integer> map = new TreeMap<>();

map.put(null, 100); // ошибка во время выполнения
```

## Comparable

**Определение:**

`Comparable` — это интерфейс, который позволяет объекту самому определить свой естественный порядок сортировки.

Класс реализует `Comparable`, если его объекты можно сравнивать между собой стандартным способом.

Для этого нужно реализовать метод `compareTo()`.

`String`, `Integer`, `Long` и многие другие стандартные классы уже реализуют `Comparable`.

**Пример:**

```java id="wkqlnd"
public class User implements Comparable<User> {
    private final long id;

    public User(long id) {
        this.id = id;
    }

    @Override
    public int compareTo(User other) {
        return Long.compare(this.id, other.id);
    }
}
```

---

## compareTo()

**Определение:**

`compareTo()` — это метод интерфейса `Comparable`.

Он определяет, как один объект сравнивается с другим.

Метод должен вернуть:

отрицательное число, если текущий объект меньше другого;

ноль, если объекты считаются равными для сортировки;

положительное число, если текущий объект больше другого.

**Пример:**

```java id="m4do8w"
@Override
public int compareTo(User other) {
    return Long.compare(this.id, other.id);
}
```

---

## Comparator

**Определение:**

`Comparator` — это интерфейс для создания внешнего правила сравнения объектов.

В отличие от `Comparable`, логика сортировки находится не внутри класса объекта, а в отдельном классе или lambda-выражении.

`Comparator` удобен, когда нужно иметь несколько разных вариантов сортировки одного и того же класса.

**Пример:**

```java id="za7z4c"
Comparator<User> byAge = Comparator.comparing(User::getAge);

Set<User> users = new TreeSet<>(byAge);
```

---

## compare()

**Определение:**

`compare()` — это метод интерфейса `Comparator`.

Он сравнивает два объекта и возвращает:

отрицательное число, если первый объект меньше второго;

ноль, если они равны для сортировки;

положительное число, если первый объект больше второго.

**Пример:**

```java id="snwgax"
public class UserIdComparator implements Comparator<User> {

    @Override
    public int compare(User first, User second) {
        return Long.compare(first.getId(), second.getId());
    }
}
```

## Comparator.comparing()

**Определение:**

`Comparator.comparing()` — это статический метод, который создаёт компаратор по указанному полю или методу объекта.

Появился в Java 8.

Он позволяет не писать отдельный класс-компаратор вручную.

**Пример:**

```java id="f1qavc"
Comparator<Person> byName = Comparator.comparing(Person::getName);
```

## thenComparing()

**Определение:**

`thenComparing()` — это метод `Comparator`, который добавляет следующий критерий сортировки.

Он используется, когда нужно сортировать объекты по нескольким признакам.

Например: сначала по имени, а если имена одинаковые — по возрасту.

**Пример:**

```java id="bql8gn"
Comparator<Person> comparator = Comparator
        .comparing(Person::getName)
        .thenComparing(Person::getAge);
```

---

## Comparator.reverseOrder()

**Определение:**

`Comparator.reverseOrder()` — это метод, который возвращает компаратор для сортировки в обратном естественном порядке.

Его часто используют внутри `thenComparing()`, если один из критериев нужно отсортировать по убыванию.

**Пример:**

```java id="ks3bi7"
Comparator<Person> comparator = Comparator
        .comparing(Person::getName)
        .thenComparing(Person::getAge, Comparator.reverseOrder());
```

## TreeSet

**Определение:**

`TreeSet` — это реализация интерфейса `Set`, которая хранит только уникальные элементы в отсортированном порядке.

Внутри `TreeSet` использует `TreeMap`.

Элементы `TreeSet` фактически становятся ключами внутренней `TreeMap`, а значение заменяется служебным объектом-заглушкой.

**Пример:**

```java id="bt75np"
Set<String> books = new TreeSet<>();

books.add("1984");
books.add("Шантарам");
books.add("Гарри Поттер");

System.out.println(books);
// [1984, Гарри Поттер, Шантарам]
```

---

## SortedSet

**Определение:**

`SortedSet` — это интерфейс для множества, элементы которого хранятся в отсортированном порядке.

`TreeSet` реализует `SortedSet`.

Через `SortedSet` доступны методы `first()`, `last()`, `headSet()`, `tailSet()` и `subSet()`.

**Пример:**

```java id="sf3k9w"
SortedSet<Integer> numbers = new TreeSet<>();

numbers.add(3);
numbers.add(1);
numbers.add(2);

System.out.println(numbers.first()); // 1
System.out.println(numbers.last());  // 3
```

---

## NavigableSet

**Определение:**

`NavigableSet` — это интерфейс, который расширяет возможности `SortedSet`.

Он позволяет искать ближайшие элементы:

больше или равно;

меньше или равно;

строго больше;

строго меньше.

`TreeSet` реализует `NavigableSet`.

**Пример:**

```java id="rymox1"
NavigableSet<Integer> numbers = new TreeSet<>();

numbers.add(10);
numbers.add(20);
numbers.add(30);

System.out.println(numbers.ceiling(15)); // 20
System.out.println(numbers.floor(15));   // 10
```

## headSet()

**Определение:**

## null-элемент в TreeSet

**Определение:**

`TreeSet` обычно не позволяет хранить `null`, если используется естественная сортировка.

Причина такая же, как у `TreeMap`: элементы нужно сравнивать, а `null` нельзя сравнить через `compareTo()`.

**Пример:**

```java id="yxn958"
Set<String> names = new TreeSet<>();

names.add(null); // ошибка во время выполнения
```

## TreeSet vs HashSet

**Определение:**

`TreeSet` и `HashSet` оба хранят уникальные элементы, но решают разные задачи.

`HashSet` быстрее в среднем и не гарантирует порядок.

`TreeSet` немного медленнее, но хранит элементы отсортированно и даёт методы для работы с диапазонами.

`HashSet` использует `equals()` и `hashCode()`.

`TreeSet` использует `compareTo()` или `compare()`.

**Пример:**

```java id="bm2oy3"
Set<Integer> hashSet = new HashSet<>();
hashSet.add(3);
hashSet.add(1);
hashSet.add(2);

Set<Integer> treeSet = new TreeSet<>();
treeSet.add(3);
treeSet.add(1);
treeSet.add(2);

System.out.println(hashSet); // порядок не гарантируется
System.out.println(treeSet); // [1, 2, 3]
```

---

## TreeMap vs HashMap

**Определение:**

`TreeMap` и `HashMap` оба хранят пары «ключ-значение», но отличаются способом хранения и порядком.

`HashMap` быстрее в среднем, но не гарантирует порядок ключей.

`TreeMap` хранит ключи отсортированно, но операции обычно работают за `O(log n)`.

`HashMap` использует `equals()` и `hashCode()`.

`TreeMap` использует `compareTo()` или `Comparator`.

**Пример:**

```java id="lvqukz"
Map<Integer, String> hashMap = new HashMap<>();
hashMap.put(3, "C");
hashMap.put(1, "A");
hashMap.put(2, "B");

Map<Integer, String> treeMap = new TreeMap<>();
treeMap.put(3, "C");
treeMap.put(1, "A");
treeMap.put(2, "B");

System.out.println(hashMap); // порядок не гарантируется
System.out.println(treeMap); // {1=A, 2=B, 3=C}
```

## ClassCastException в TreeSet

**Определение:**

`ClassCastException` в `TreeSet` может возникнуть, если добавить объекты, которые Java не умеет сравнивать.

Например, если класс `Person` не реализует `Comparable`, и при создании `TreeSet` не передан `Comparator`.

`TreeSet` должен понимать, какой объект меньше, а какой больше.

**Пример неправильного кода:**

```java id="votm5t"
Set<Person> people = new TreeSet<>();

people.add(new Person("Tom", "Morris", 29)); // может быть ClassCastException
```

Правильно:

```java id="r0806l"
Set<Person> people = new TreeSet<>(Comparator.comparing(Person::getName));

people.add(new Person("Tom", "Morris", 29));
```

## Сортировка по нескольким критериям

**Определение:**

Сортировка по нескольким критериям — это сортировка, где сначала используется один признак, а при равенстве — следующий.

Например:

сначала сортировать людей по имени;

если имена одинаковые — сортировать по возрасту от старшего к младшему.

В Java это удобно делать через `Comparator.comparing()` и `thenComparing()`.

**Пример:**

```java id="f0q80m"
Set<Person> people = new TreeSet<>(
        Comparator.comparing(Person::getName)
                .thenComparing(Person::getAge, Comparator.reverseOrder())
);
```
