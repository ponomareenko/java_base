# 5. Тема: Централизованное логирование для Spring Boot — ELK-стек

## Централизованное логирование

**Определение:**

Централизованное логирование — подход, при котором логи из разных компонентов системы собираются, хранятся и анализируются в одном месте. Презентация\_-\_Централизованное\_…

Вместо:

```text
Server 1 → смотрим логи вручную
Server 2 → смотрим логи вручную
Server 3 → смотрим логи вручную
```

получаем:

```text
Application 1 ─┐
Application 2 ─┼──→ Central Logging System
Database ──────┤
Containers ────┘
```

Это особенно важно в микросервисной архитектуре, где одновременно логируют десятки или сотни компонентов. Презентация\_-\_Централизованное\_…

---

## Log

**Определение:**

Log — запись о событии, произошедшем во время работы приложения.

Например:

```text
2026-10-10 19:15:32 INFO  UserService - User 15 created
```

или:

```text
2026-10-10 19:16:01 ERROR PaymentService - Payment failed
```

Обычно лог содержит:

```text
timestamp
level
message
class/service
additional data
```

В презентации `timestamp`, `level`, `message` и `host` приводятся как поля, по которым можно работать с логами в Kibana. Презентация\_-\_Централизованное\_…

---

## Log Level

**Определение:**

Log Level — уровень важности сообщения в логах.

Типичные уровни:

```text
TRACE
DEBUG
INFO
WARN
ERROR
```

Например:

```java
log.info("User created");
log.warn("Request took too long");
log.error("Database connection failed");
```

В презентации уровень `ERROR` используется как пример при поиске логов и настройке алертов. Презентация\_-\_Централизованное\_…

## Message Queue

**Определение:**

Message Queue — промежуточная очередь сообщений, которая может использоваться между источниками логов и системой хранения.

В презентации этот компонент обозначен как необязательный, а примерами являются:

```text
Kafka
Redis
```

Презентация\_-\_Централизованное\_…

Схема:

```text
Applications
     ↓
Log Shipper
     ↓
Message Queue
     ↓
Log Storage
```

Очередь может помочь развязать производителей и потребителей логов.

# ELK

## ELK Stack

**Определение:**

ELK Stack — набор инструментов для централизованного сбора, хранения, поиска и анализа логов.

`ELK` расшифровывается как:

```text
E → Elasticsearch
L → Logstash
K → Kibana
```

В презентации роли компонентов определяются так:

```text
Elasticsearch → хранение и поиск
Logstash      → сбор, обработка и доставка
Kibana        → визуализация и анализ
```

Презентация\_-\_Централизованное\_…

Главная цепочка:

```text
Spring Boot
     ↓
Logstash
     ↓
Elasticsearch
     ↓
Kibana
```

## Logstash

**Определение:**

Logstash — компонент ELK-стека, который принимает, обрабатывает и передаёт логи в хранилище.

Он может:

```text
получать данные
парсить их
фильтровать
преобразовывать
обогащать
отправлять дальше
```

В презентации указано, что Logstash получает данные от Beats, `syslog` и других источников, а затем может отправлять их в Elasticsearch. Презентация\_-\_Централизованное\_…

Схема:

```text
Application
    ↓
Logstash
    ↓
parse
filter
transform
    ↓
Elasticsearch
```

## Logstash Pipeline

**Определение:**

Logstash Pipeline — цепочка обработки данных в Logstash.

Конфигурация обычно состоит из частей:

```text

```

В презентации приведён упрощённый пример:

```text
input
   ↓
TCP :5000
   ↓
JSON
   ↓

   ↓
Elasticsearch
```

Презентация\_-\_Централизованное\_…

Пример:

```conf

    tcp {
        port => 5000
        codec => json

        hosts => ["http://elasticsearch:9200"]

}
```

В рамках ELK он принимает обработанные логи, индексирует их и позволяет быстро выполнять поиск и агрегации. Презентация\_-\_Централизованное\_…

## Index

**Определение:**

Index — логическая структура Elasticsearch, в которой хранятся документы.

В презентации индекс сравнивается с таблицей в SQL. Презентация\_-\_Централизованное\_…

Упрощённая аналогия:

```text
SQL                    Elasticsearch

Database/Table   ≈     Index
Row              ≈     Document
Column           ≈     Field
```

Аналогия не абсолютная, но хорошо помогает на начальном этапе.

Пример имени индекса из презентации:

```text

```

## Structured Logging

**Определение:**

Structured Logging — логирование в структурированном формате, например JSON, где данные записываются отдельными полями.

Пример:

```json
{
  "timestamp": "2026-10-10T20:00:00",
  "level": "ERROR",
  "service": "payment-service",
  "userId": 15,
  "message": "Payment failed"
}
```

В презентации для Spring Boot используется `LogstashEncoder`, который позволяет передавать логи в JSON-формате. Презентация\_-\_Централизованное\_…

Преимущество перед обычной строкой:

```text
ERROR Payment failed for user 15
```

в том, что отдельные поля проще искать, фильтровать и агрегировать.

# Что обязательно запомнить из темы

Главная цепочка ELK:

```text
Spring Boot
     ↓
Logback
     ↓
Logstash
     ↓
Elasticsearch
     ↓
Kibana
```

Вариант через Filebeat:

```text
Spring Boot
     ↓
log file
     ↓
Filebeat
     ↓
Logstash
     ↓
Elasticsearch
     ↓
Kibana
```

Роли компонентов:

```text
Logback
→ создаёт логи в приложении

Filebeat
→ читает и пересылает лог-файлы

Logstash
→ принимает, преобразует и маршрутизирует логи

Elasticsearch
→ хранит, индексирует и ищет

Kibana
→ позволяет человеку искать и анализировать данные
```

Самое важное различие:

```text
Logstash      → обработка и доставка

Elasticsearch → хранение и поиск

Kibana        → интерфейс и визуализация
```

И общий смысл централизованного логирования:

```text
Не ищем проблему по логам
на десяти разных серверах.

Собираем все логи
в одной системе
и ищем там.
```
