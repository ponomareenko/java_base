# Основы работы с сетью

## Компьютерная сеть

**Компьютерная сеть** — это группа устройств, которые могут обмениваться данными по проводным или беспроводным каналам связи.

Устройствами сети могут быть:

* компьютеры;
* серверы;
* смартфоны;
* маршрутизаторы;
* принтеры;
* различные умные устройства.

Для передачи данных устройство должно знать:

1. адрес получателя;
2. способ доставки данных;
3. приложение или службу, которой предназначены данные.

---

## Сетевой протокол

**Сетевой протокол** — это набор правил, по которым устройства обмениваются данными.

Протокол определяет:

* формат сообщений;
* порядок отправки и получения данных;
* способ обнаружения ошибок;
* необходимость подтверждения доставки;
* действия при потере данных.

Примеры сетевых протоколов:

| Протокол | Назначение                                         |
| -------- | -------------------------------------------------- |
| HTTP     | Передача веб-страниц и данных веб-приложений       |
| DNS      | Преобразование доменных имён в IP-адреса           |
| TCP      | Надёжная передача потока данных                    |
| UDP      | Передача отдельных сообщений без гарантии доставки |
| IP       | Адресация и маршрутизация пакетов                  |
| ICMP     | Служебные сетевые сообщения, например для `ping`   |

Протокол можно сравнить с правилами разговора: если один человек задаёт вопрос на русском, а другой отвечает случайными сигналами фонариком, общение технически происходит, но практической пользы немного.

---

## Хост

**Хост (host)** — это устройство или программная система, подключённая к сети и имеющая сетевой адрес.

Примеры:

* компьютер пользователя;
* сервер сайта;
* виртуальная машина;
* контейнер;
* смартфон.

**Удалённый хост (remote host)** — это устройство, с которым программа взаимодействует через сеть.

В следующем коде удалённым хостом является `example.com`:

```java
String host = "example.com";
```

---

## Клиент

**Клиент** — это программа или устройство, которое инициирует подключение к серверу и отправляет ему запросы.

Примеры клиентов:

* браузер;
* мобильное приложение;
* Java-программа, использующая `Socket`;
* приложение для работы с базой данных.

---

## Сервер

**Сервер** — это программа или устройство, которое ожидает входящие подключения, принимает запросы клиентов и отправляет ответы.

Один физический компьютер может одновременно запускать несколько серверных приложений:

* веб-сервер;
* сервер базы данных;
* почтовый сервер;
* файловый сервер.

Различать их помогают номера портов.

---

# Сетевые устройства

## Маршрутизатор

**Маршрутизатор (router)** — это сетевое устройство, которое передаёт пакеты между разными сетями.

Маршрутизатор анализирует IP-адрес назначения и выбирает, куда отправить пакет дальше.

Например, домашний маршрутизатор соединяет локальную сеть квартиры с сетью интернет-провайдера.

---

## Коммутатор

**Коммутатор (switch)** — это устройство, которое соединяет устройства внутри одной локальной сети и передаёт кадры на основании MAC-адресов.

Упрощённо:

* маршрутизатор работает преимущественно с IP-адресами;
* коммутатор работает преимущественно с MAC-адресами.

---

## Модем

**Модем** — это устройство, которое преобразует сигналы для передачи данных через канал связи интернет-провайдера.

В бытовых устройствах функции модема, маршрутизатора, коммутатора и Wi-Fi-точки доступа часто объединены в одном корпусе.

---

## Firewall

**Firewall, или межсетевой экран** — это система, которая разрешает или блокирует сетевой трафик на основании заданных правил.

Firewall может проверять:

* IP-адрес отправителя;
* IP-адрес получателя;
* номер порта;
* используемый протокол;
* направление соединения.

Например, firewall может разрешать подключения к порту `443`, но блокировать подключения к порту базы данных.

---

# Модель OSI

## OSI

**OSI — Open Systems Interconnection** — это концептуальная модель, которая описывает сетевое взаимодействие в виде семи уровней.

Модель OSI помогает:

* разделить сложный процесс передачи данных на отдельные задачи;
* понимать назначение сетевых технологий;
* обсуждать сетевые проблемы;
* определять, на каком уровне возникла ошибка.

OSI — не конкретный протокол и не библиотека. Это модель для понимания сетевого взаимодействия.

---

## Уровни модели OSI

|  № | Уровень       | Основная задача                                 | Примеры                          |
| -: | ------------- | ----------------------------------------------- | -------------------------------- |
|  7 | Прикладной    | Взаимодействие приложений с сетью               | HTTP, DNS, FTP                   |
|  6 | Представления | Кодирование, преобразование, сжатие, шифрование | UTF-8, JPEG, TLS                 |
|  5 | Сеансовый     | Создание и поддержание сеансов взаимодействия   | Сессии, восстановление обмена    |
|  4 | Транспортный  | Передача данных между программами               | TCP, UDP, порты                  |
|  3 | Сетевой       | Логическая адресация и маршрутизация            | IP, ICMP                         |
|  2 | Канальный     | Передача кадров внутри локального сегмента сети | Ethernet, Wi-Fi, MAC             |
|  1 | Физический    | Передача сигналов и битов                       | Кабель, радиосигнал, оптоволокно |

---

## Прикладной уровень

**Прикладной уровень** — это верхний уровень OSI, предоставляющий сетевые возможности пользовательским приложениям.

На этом уровне определяются правила общения конкретных программ.

Примеры:

* браузер использует HTTP;
* почтовый клиент использует SMTP и IMAP;
* программа запрашивает IP-адрес через DNS;
* клиент передаёт файл через FTP.

Прикладной уровень — это не само приложение и не пользовательский интерфейс. Это протоколы, с которыми работает приложение.

---

## HTTP

**HTTP — Hypertext Transfer Protocol** — это протокол прикладного уровня для обмена данными между клиентом и веб-сервером.

Клиент отправляет HTTP-запрос:

```text
GET /users HTTP/1.1
Host: example.com
```

Сервер отправляет HTTP-ответ:

```text
HTTP/1.1 200 OK
Content-Type: application/json
```

HTTP не отвечает за физическую передачу данных. Он определяет смысл запросов и ответов, а доставкой обычно занимается TCP.

---

## FTP

**FTP — File Transfer Protocol** — это протокол передачи файлов между клиентом и сервером.

Классический FTP не шифрует данные и учётные данные, поэтому в современных системах чаще используют:

* SFTP;
* FTPS;
* HTTPS;
* облачные хранилища с защищённым API.

---

## Telnet

**Telnet** — это протокол удалённого текстового доступа к другому компьютеру.

Telnet передаёт данные без шифрования, поэтому для администрирования серверов практически вытеснен протоколом SSH.

---

## Уровень представления

**Уровень представления** отвечает за преобразование данных в формат, который может понять принимающая сторона.

Задачи уровня:

* кодирование текста;
* сериализация данных;
* сжатие;
* шифрование;
* преобразование форматов.

Примеры:

* кодировка UTF-8;
* формат изображения JPEG;
* преобразование объекта в JSON;
* шифрование через TLS.

В реальном стеке TCP/IP эти задачи обычно выполняются библиотеками и протоколами прикладного уровня.

---

## TLS

**TLS — Transport Layer Security** — это протокол защиты сетевого соединения.

TLS обеспечивает:

* шифрование передаваемых данных;
* проверку подлинности сервера;
* контроль целостности данных.

HTTPS — это HTTP поверх TLS.

Термин **SSL** часто используется по привычке, но старые версии SSL устарели. В современных системах применяется TLS.

---

## Сеансовый уровень

**Сеансовый уровень** отвечает за создание, поддержание и завершение длительного взаимодействия между приложениями.

Возможные задачи:

* установление сеанса;
* восстановление обмена после временного разрыва;
* синхронизация;
* управление состоянием взаимодействия.

В современных приложениях эти функции часто реализуются непосредственно на прикладном уровне.

Например, веб-приложение может хранить идентификатор пользовательской сессии в cookie или токене.

---

## Транспортный уровень

**Транспортный уровень** отвечает за передачу данных между конкретными программами на разных устройствах.

Основные задачи:

* использование портов;
* разделение данных между приложениями;
* контроль порядка доставки;
* обнаружение потерь;
* повторная передача данных;
* управление скоростью передачи.

Основные протоколы транспортного уровня:

* TCP;
* UDP.

---

## Сетевой уровень

**Сетевой уровень** отвечает за логическую адресацию устройств и передачу пакетов между разными сетями.

Основные задачи:

* использование IP-адресов;
* выбор маршрута;
* передача пакетов через маршрутизаторы;
* определение адреса назначения.

Основной протокол сетевого уровня — IP.

---

## Канальный уровень

**Канальный уровень** отвечает за передачу данных между устройствами внутри одного сетевого сегмента.

Основные задачи:

* формирование кадров;
* использование MAC-адресов;
* обнаружение ошибок передачи;
* управление доступом к среде передачи.

Примеры технологий:

* Ethernet;
* Wi-Fi.

---

## Физический уровень

**Физический уровень** отвечает за передачу отдельных битов в виде физических сигналов.

Сигналы могут передаваться через:

* медный кабель;
* оптоволокно;
* радиоканал;
* Wi-Fi;
* мобильную сеть.

На этом уровне данные представлены последовательностью нулей и единиц.

---

# Инкапсуляция

## Инкапсуляция

**Инкапсуляция данных** — это процесс последовательного добавления служебной информации к данным при движении от верхних уровней сети к нижним.

Например:

1. HTTP создаёт запрос.
2. TCP добавляет свои служебные данные.
3. IP добавляет IP-адреса.
4. Ethernet добавляет MAC-адреса.
5. Физический уровень передаёт результат в виде сигналов.

Упрощённо:

```text
Данные приложения
↓
TCP-сегмент
↓
IP-пакет
↓
Ethernet-кадр
↓
Биты
```

---

## Декапсуляция

**Декапсуляция** — это обратный процесс, при котором принимающая сторона последовательно удаляет служебную информацию каждого уровня и передаёт данные приложению.

---

## PDU

**PDU — Protocol Data Unit** — это единица данных, обрабатываемая определённым уровнем сетевой модели.

| Уровень           | Название PDU |
| ----------------- | ------------ |
| Прикладной        | Данные       |
| Транспортный, TCP | Сегмент      |
| Транспортный, UDP | Датаграмма   |
| Сетевой           | Пакет        |
| Канальный         | Кадр         |
| Физический        | Биты         |

В обычной речи словом «пакет» часто называют почти любые сетевые данные, но технически названия различаются по уровням.

---

# Модель TCP/IP

## TCP/IP

**TCP/IP** — это практическая модель и набор протоколов, на которых построена работа интернета.

Чаще всего модель TCP/IP представляют в виде четырёх уровней:

| Уровень TCP/IP                  | Соответствующие уровни OSI           |
| ------------------------------- | ------------------------------------ |
| Прикладной                      | Прикладной, представления, сеансовый |
| Транспортный                    | Транспортный                         |
| Интернет-уровень                | Сетевой                              |
| Канальный, или сетевого доступа | Канальный и физический               |

В разных источниках названия нижнего уровня могут отличаться:

* канальный уровень;
* уровень сетевого доступа;
* link layer;
* network access layer.

---

## Стек протоколов

**Стек протоколов** — это набор протоколов разных уровней, которые совместно обеспечивают передачу данных.

Пример стека при открытии сайта:

```text
HTTP
TLS
TCP
IP
Ethernet или Wi-Fi
```

Каждый протокол решает собственную задачу и передаёт результат следующему уровню.

---

# DNS

## DNS

**DNS — Domain Name System** — это распределённая система, которая связывает доменные имена с IP-адресами и другими данными.

Например:

```text
example.com → 93.184.216.34
```

Людям удобнее запоминать доменное имя, а сетевым протоколам нужен IP-адрес.

Важно различать:

* **DNS** — вся система доменных имён;
* **DNS-сервер** — сервер, который обрабатывает DNS-запросы.

Выражение `Domain Name Server` иногда встречается, но официальная расшифровка DNS — `Domain Name System`.

---

## DNS-resolving

**DNS-resolving, или разрешение доменного имени** — это процесс получения IP-адреса по доменному имени.

Пример в Java:

```java
import java.net.InetAddress;
import java.net.UnknownHostException;

public class DnsExample {

    public static void main(String[] args) {
        String host = "example.com";

        try {
            InetAddress address = InetAddress.getByName(host);

            System.out.println("Домен: " + host);
            System.out.println("IP-адрес: " + address.getHostAddress());
        } catch (UnknownHostException exception) {
            System.out.println("Не удалось определить IP-адрес");
        }
    }
}
```

Один домен может иметь несколько IP-адресов:

```java
InetAddress[] addresses = InetAddress.getAllByName("example.com");

for (InetAddress address : addresses) {
    System.out.println(address.getHostAddress());
}
```

---

## nslookup

**`nslookup`** — это консольная команда для выполнения DNS-запросов.

Пример:

```bash
nslookup example.com
```

Команда может показать:

* используемый DNS-сервер;
* найденные IPv4-адреса;
* найденные IPv6-адреса;
* дополнительные DNS-записи.

---

## hosts

**`hosts`** — это локальный системный файл, в котором можно вручную связать доменное имя с IP-адресом.

Путь в macOS и Linux:

```text
/etc/hosts
```

Путь в Windows:

```text
C:\Windows\System32\drivers\etc\hosts
```

Пример записи:

```text
127.0.0.1 my-local-app.test
```

После этого имя `my-local-app.test` будет указывать на локальный компьютер.

Файл `hosts` часто используют при локальной разработке и тестировании. Он не изменяет глобальный DNS — запись действует только на конкретном компьютере.

---

# IP и маршрутизация

## IP

**IP — Internet Protocol** — это протокол сетевого уровня, отвечающий за адресацию и передачу пакетов между сетями.

IP выполняет две основные задачи:

1. указывает адрес отправителя и получателя;
2. позволяет маршрутизаторам передавать пакет к сети назначения.

IP сам по себе не гарантирует:

* доставку пакета;
* правильный порядок пакетов;
* отсутствие дубликатов.

Эти задачи при необходимости решает TCP или прикладной протокол.

---

## IP-адрес

**IP-адрес** — это логический сетевой адрес устройства или сетевого интерфейса.

Пример IPv4-адреса:

```text
192.168.1.10
```

IP-адрес нужен для определения устройства или интерфейса в сети.

---

## IPv4

**IPv4 — Internet Protocol version 4** — это четвёртая версия IP-протокола.

IPv4-адрес состоит из 32 бит, то есть четырёх байтов.

Пример:

```text
172.16.254.1
```

Каждая часть адреса называется **октетом** и может иметь значение от `0` до `255`.

```text
172  → 10101100
16   → 00010000
254  → 11111110
1    → 00000001
```

Всего существует:

```text
2³² = 4 294 967 296
```

возможных IPv4-адресов, но часть из них зарезервирована для специальных целей.

---

## Октет

**Октет** — это последовательность из восьми бит.

В IPv4-адресе четыре октета:

```text
192.168.1.10
```

```text
192 | 168 | 1 | 10
```

---

## IPv6

**IPv6 — Internet Protocol version 6** — это версия IP-протокола с 128-битными адресами.

Пример:

```text
2001:db8:85a3::8a2e:370:7334
```

IPv6 появился в том числе из-за недостатка свободных IPv4-адресов.

Количество возможных адресов IPv6:

```text
2¹²⁸
```

Это значительно больше пространства IPv4.

---

## Маршрутизация

**Маршрутизация** — это процесс выбора пути, по которому сетевой пакет будет передан от отправителя к получателю.

Маршрутизаторы используют таблицы маршрутизации, чтобы определить следующий узел на пути пакета.

Пакет не обязан всегда идти по одному и тому же маршруту. Разные пакеты одного соединения теоретически могут пройти разными путями.

---

## Маршрут

**Сетевой маршрут** — это правило, определяющее, куда следует отправить пакет для достижения определённой сети или адреса.

---

## ICMP

**ICMP — Internet Control Message Protocol** — это служебный сетевой протокол для передачи сообщений об ошибках и состоянии сети.

ICMP используется, например, командой `ping`.

---

## ping

**`ping`** — это команда, которая отправляет ICMP-запросы удалённому устройству и измеряет время получения ответа.

Пример:

```bash
ping example.com
```

`ping` помогает проверить:

* разрешается ли доменное имя;
* существует ли сетевой маршрут;
* отвечает ли устройство на ICMP;
* примерную задержку;
* процент потерянных сообщений.

Успешный `ping` не доказывает, что нужное приложение работает.

Например:

* сервер отвечает на `ping`;
* но веб-сервер на порту `443` остановлен;
* сайт всё равно не откроется.

Также firewall может блокировать ICMP, поэтому отсутствие ответа на `ping` не всегда означает, что сервер недоступен.

---

# MAC-адрес и канальный уровень

## MAC-адрес

**MAC-адрес — Media Access Control Address** — это адрес сетевого интерфейса, используемый на канальном уровне.

Типичный MAC-адрес содержит 48 бит:

```text
00:1A:3F:F1:4C:C6
```

Первые байты часто указывают на производителя сетевого оборудования, а остальные идентифицируют интерфейс.

Корректнее говорить, что MAC-адрес принадлежит **сетевому интерфейсу**, а не устройству целиком. У ноутбука могут быть разные MAC-адреса для Ethernet и Wi-Fi.

MAC-адрес также может:

* изменяться программно;
* подменяться;
* случайным образом генерироваться операционной системой для повышения приватности.

Поэтому абсолютная уникальность MAC-адреса не гарантируется.

---

## NIC

**NIC — Network Interface Controller** — это сетевой интерфейс, через который устройство подключается к сети.

Примеры:

* Ethernet-адаптер;
* Wi-Fi-адаптер;
* виртуальный сетевой интерфейс.

---

## Кадр

**Кадр (frame)** — это единица данных канального уровня.

Кадр обычно содержит:

* MAC-адрес отправителя;
* MAC-адрес получателя;
* полезные данные;
* информацию для обнаружения ошибок.

---

# TCP и UDP

## TCP

**TCP — Transmission Control Protocol** — это транспортный протокол, предоставляющий надёжный упорядоченный поток байтов между двумя программами.

TCP обеспечивает:

* установление соединения;
* подтверждение получения данных;
* повторную отправку потерянных данных;
* восстановление правильного порядка;
* обнаружение дубликатов;
* управление скоростью передачи.

Примеры использования:

* HTTP/1.1;
* HTTP/2;
* передача файлов;
* работа с базами данных;
* SSH;
* электронная почта.

Фраза «TCP гарантирует, что пакеты обязательно дойдут» слишком категорична.

TCP пытается обеспечить доставку и сообщает приложению об ошибке, если соединение нарушено. При отключении сети, падении сервера или превышении тайм-аута данные могут не быть доставлены.

---

## TCP-соединение

**TCP-соединение** — это логическое двустороннее соединение между клиентом и сервером.

Перед передачей данных стороны выполняют процедуру установления соединения.

После этого обе стороны могут одновременно отправлять и получать данные.

---

## Поток байтов

**Поток байтов** — это непрерывная последовательность данных без встроенных границ сообщений.

TCP передаёт именно поток байтов.

Если отправитель выполнил:

```java
out.write("Hello");
out.write("World");
```

получатель не обязан получить два отдельных сообщения. Он может прочитать:

```text
HelloWorld
```

или несколько частей:

```text
Hel
loWor
ld
```

Поэтому прикладной протокол должен самостоятельно определять границы сообщений.

---

## UDP

**UDP — User Datagram Protocol** — это транспортный протокол для передачи независимых датаграмм без предварительного установления соединения.

UDP сам не обеспечивает:

* подтверждение доставки;
* повторную отправку;
* правильный порядок;
* защиту от дубликатов.

При этом UDP сохраняет границы сообщений: одна отправленная датаграмма принимается как отдельная датаграмма, если она была доставлена.

Примеры использования:

* DNS-запросы;
* онлайн-игры;
* голосовая связь;
* видеотрансляции;
* телеметрия;
* протоколы реального времени.

UDP не всегда автоматически «быстрее TCP». У него меньше встроенных механизмов, но итоговая скорость зависит от приложения, сети и используемого протокола.

---

## Датаграмма

**Датаграмма** — это отдельное самостоятельное сетевое сообщение.

UDP передаёт данные датаграммами.

Каждая датаграмма может:

* быть доставлена;
* потеряться;
* прийти позже другой;
* прийти повторно.

---

## TCP и UDP: различия

| Характеристика          | TCP            | UDP          |
| ----------------------- | -------------- | ------------ |
| Установление соединения | Требуется      | Не требуется |
| Подтверждение доставки  | Есть           | Нет          |
| Повторная передача      | Есть           | Нет          |
| Сохранение порядка      | Есть           | Нет          |
| Границы сообщений       | Не сохраняются | Сохраняются  |
| Представление данных    | Поток байтов   | Датаграммы   |
| Накладные расходы       | Выше           | Ниже         |

# Порты

## Порт

**Сетевой порт** — это число, которое позволяет операционной системе определить приложение или сетевую службу, которой предназначены данные.

Диапазон портов:

```text
0–65535
```

Примеры:

| Порт | Типичное назначение                                |
| ---: | -------------------------------------------------- |
|   21 | FTP                                                |
|   22 | SSH                                                |
|   23 | Telnet                                             |
|   53 | DNS                                                |
|   80 | HTTP                                               |
|  443 | HTTPS                                              |
| 5432 | PostgreSQL                                         |
| 8080 | Часто используется веб-приложениями при разработке |

IP-адрес указывает на устройство, а порт — на конкретную программу или службу внутри устройства.

Аналогия:

```text
IP-адрес = адрес дома
Порт = номер квартиры
```

---

## Диапазоны портов

| Диапазон      | Назначение                        |
| ------------- | --------------------------------- |
| `0–1023`      | Системные, или well-known ports   |
| `1024–49151`  | Зарегистрированные порты          |
| `49152–65535` | Динамические, или временные порты |

Когда клиент подключается к серверу, операционная система обычно автоматически назначает клиенту временный локальный порт.

---

## Локальный порт

**Локальный порт** — это порт на текущем компьютере.

---

## Удалённый порт

**Удалённый порт** — это порт на компьютере, к которому выполняется подключение.

Например:

```text
Клиент: 192.168.1.20:53124
Сервер: 203.0.113.10:443
```

Здесь:

* `53124` — временный локальный порт клиента;
* `443` — порт HTTPS-сервера.

---

# Сокеты

## Сокет

**Сокет (socket)** — это программный объект, через который приложение взаимодействует с сетью.

Сокет предоставляет программе возможность:

* установить соединение;
* отправлять данные;
* получать данные;
* завершить соединение.

Формула из презентации:

```text
Socket = IP + Port
```

подходит как начальное упрощение.

Точнее, сетевую конечную точку определяют:

* транспортный протокол;
* IP-адрес;
* порт.

Например:

```text
TCP 192.168.1.10:8080
```

TCP-соединение однозначно определяется набором:

```text
протокол
IP отправителя
порт отправителя
IP получателя
порт получателя
```

---

## Клиентский сокет

**Клиентский сокет** — это сокет, который инициирует подключение к удалённому серверу.

В Java используется класс `Socket`:

```java
Socket socket = new Socket("example.com", 80);
```

При создании объекта Java:

1. определяет IP-адрес домена;
2. создаёт локальный сокет;
3. устанавливает TCP-соединение с удалённым портом.

---

## Серверный сокет

**Серверный сокет** — это сокет, который ожидает входящие подключения клиентов.

В Java используется класс `ServerSocket`:

```java
ServerSocket serverSocket = new ServerSocket(8080);
Socket clientSocket = serverSocket.accept();
```

Метод `accept()` блокирует текущий поток до появления нового подключения.

После подключения он возвращает обычный объект `Socket`, через который сервер общается с конкретным клиентом.

---

## InetAddress

**`InetAddress`** — это Java-класс, представляющий IP-адрес и связанное с ним доменное имя.

Получение IP-адреса:

```java
InetAddress address = InetAddress.getByName("example.com");

System.out.println(address.getHostAddress());
```

Получение всех адресов домена:

```java
InetAddress[] addresses =
        InetAddress.getAllByName("example.com");

for (InetAddress address : addresses) {
    System.out.println(address.getHostAddress());
}
```

`InetAddress` не устанавливает сетевое соединение. Он только представляет адрес и позволяет выполнять DNS-разрешение.

---

## InetSocketAddress

**`InetSocketAddress`** — это Java-класс, объединяющий IP-адрес или доменное имя с номером порта.

```java
InetSocketAddress serverAddress =
        new InetSocketAddress("example.com", 80);
```

Его часто используют при создании соединения с тайм-аутом:

```java
Socket socket = new Socket();

socket.connect(
        new InetSocketAddress("example.com", 80),
        3_000
);
```

---

## localhost

**`localhost`** — это имя, обозначающее текущий компьютер.

Обычно оно соответствует адресу:

```text
127.0.0.1
```

для IPv4 или:

```text
::1
```

для IPv6.

`localhost` используют для запуска и тестирования серверов на собственном компьютере:

```java
Socket socket = new Socket("localhost", 8080);
```

---

## Loopback

**Loopback-интерфейс** — это виртуальный сетевой интерфейс, через который компьютер обращается сам к себе.

Трафик loopback не выходит во внешнюю сеть.

---

# HTTP через Socket

Для HTTP/1.1 строки запроса должны разделяться последовательностью:

```text
\r\n
```

После заголовков должна находиться пустая строка.

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class HttpSocketExample {

    public static void main(String[] args) {
        String host = "example.com";
        int port = 80;

        try (
                Socket socket = new Socket(host, port);

                BufferedWriter writer = new BufferedWriter(
                        new OutputStreamWriter(
                                socket.getOutputStream(),
                                StandardCharsets.US_ASCII
                        )
                );

                BufferedReader reader = new BufferedReader(
                        new InputStreamReader(
                                socket.getInputStream(),
                                StandardCharsets.UTF_8
                        )
                )
        ) {
            writer.write("GET / HTTP/1.1\r\n");
            writer.write("Host: " + host + "\r\n");
            writer.write("Connection: close\r\n");
            writer.write("\r\n");
            writer.flush();

            String statusLine = reader.readLine();
            System.out.println(statusLine);

        } catch (IOException exception) {
            System.out.println(
                    "Ошибка сетевого взаимодействия: "
                            + exception.getMessage()
            );
        }
    }
}
```

Ожидаемый результат:

```text
HTTP/1.1 200 OK
```

Для HTTPS недостаточно подключиться обычным `Socket` к порту `443`, потому что перед HTTP-обменом необходимо установить защищённое TLS-соединение.

В реальных Java-приложениях для HTTP обычно используют `HttpClient`, а не формируют запрос вручную через `Socket`.

# Тайм-аут

## Timeout

**Тайм-аут (timeout)** — это максимальное время ожидания сетевой операции.

Основные виды:

* тайм-аут установления соединения;
* тайм-аут чтения ответа;
* тайм-аут всей операции.

Пример:

```java
Socket socket = new Socket();

socket.connect(
        new InetSocketAddress("example.com", 80),
        3_000
);

socket.setSoTimeout(5_000);
```

Здесь:

* соединение ожидается максимум 3 секунды;
* чтение из сокета ожидается максимум 5 секунд.

Без тайм-аутов программа может зависнуть на неопределённое время.

# Границы сообщений

## Message framing

**Message framing** — это способ определения границ отдельных сообщений внутри TCP-потока.

Поскольку TCP не сохраняет границы сообщений, приложение должно договориться, как понимать, где сообщение заканчивается.

Распространённые способы:

1. разделитель:

```text
hello\n
```

2. длина сообщения перед данными:

```text
5hello
```

3. фиксированный размер сообщения;

4. специальный формат протокола;

5. закрытие соединения после сообщения.

В продакшене нельзя рассчитывать, что один вызов `read()` вернёт всё сообщение целиком.
