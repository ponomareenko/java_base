# Тема: Тестирование кода и Unit-тесты

## Тестирование

**Определение:**

Тестирование — это процесс проверки программы, при котором мы убеждаемся, что код работает так, как ожидается.

Тестирование помогает найти:

* где ошибка;
* какая ошибка;
* на каких данных она появляется;
* не сломался ли старый код после изменений.

В продакшене тесты экономят время команды: лучше поймать ошибку до релиза, чем потом чинить «пожар в серверной с чашкой кофе и грустными глазами».

**Пример:**

```java
int result = Calculator.sum(2, 3);

Assertions.assertEquals(5, result);
```

---

## Unit-модуль

**Определение:**

Unit-модуль — это изолированная часть кода, которую можно проверить отдельно.

Unit-модулем может быть:

* метод;
* класс;
* набор методов;
* набор классов.

Чаще всего в начале обучения unit-модулем считают один метод или один класс.

**Пример:**

```java
public class Calculator {
    public int sum(int first, int second) {
        return first + second;
    }
}
```

В этом примере метод `sum()` можно рассматривать как unit-модуль.

---

## Unit-тестирование

**Определение:**

Unit-тестирование — это проверка отдельного модуля программы.

Главная идея: сравнить ожидаемое поведение модуля с реальным поведением.

Если ожидали `5`, а получили `6`, значит тест должен показать ошибку.

Unit-тестирование также называют модульным тестированием.

**Пример:**

```java
@Test
public void sum_twoPositiveNumbers_returnsCorrectResult() {
    Calculator calculator = new Calculator();

    int result = calculator.sum(2, 3);

    Assertions.assertEquals(5, result);
}
```

---

## Unit-тест

**Определение:**

Unit-тест — это автоматическая проверка небольшой части кода.

Обычно unit-тест:

1. подготавливает данные;
2. вызывает тестируемый метод;
3. сравнивает фактический результат с ожидаемым.

**Пример:**

```java
@Test
public void concat_validArgument_returnsJoinedString() {
    String original = "Hello ";
    String argument = "Java";

    String result = original.concat(argument);

    Assertions.assertEquals("Hello Java", result);
}
```

---

## Автотест

**Определение:**

Автотест — это тест, который запускается автоматически и сам проверяет результат.

В отличие от ручной проверки через `System.out.println()`, автотест сам понимает, прошёл он или упал.

**Пример:**

```java
@Test
public void length_stringValue_returnsLength() {
    String text = "Java";

    int result = text.length();

    Assertions.assertEquals(4, result);
}
```

---

## Ручное тестирование через консоль

**Определение:**

Ручное тестирование через консоль — это способ проверки кода, когда разработчик запускает программу и сам смотрит результат в консоли.

Так можно делать на первых этапах обучения, но для больших программ это неудобно.

Минусы:

* нужно каждый раз запускать программу вручную;
* легко пропустить ошибку;
* нет автоматической проверки;
* сложно проверять много сценариев.

**Пример:**

```java
public static void main(String[] args) {
    Calculator calculator = new Calculator();

    System.out.println(calculator.sum(2, 3)); // вручную смотрим: 5 или нет
}
```

---

## Ожидаемый результат

**Определение:**

Ожидаемый результат — это значение, которое мы заранее считаем правильным.

В тестах его часто называют `expected`.

**Пример:**

```java
int expected = 5;
int actual = Calculator.sum(2, 3);

Assertions.assertEquals(expected, actual);
```

---

## Фактический результат

**Определение:**

Фактический результат — это значение, которое реально вернул тестируемый код.

В тестах его часто называют `actual`.

**Пример:**

```java
int expected = 10;

int actual = Calculator.multiply(2, 5);

Assertions.assertEquals(expected, actual);
```

---

## expected

**Определение:**

`expected` — это переменная, в которой обычно хранят ожидаемый результат теста.

Она отвечает на вопрос:

> Что мы хотим получить?

**Пример:**

```java
String expected = "Hello Java";
String actual = "Hello ".concat("Java");

Assertions.assertEquals(expected, actual);
```

---

## actual

**Определение:**

`actual` — это переменная, в которой обычно хранят фактический результат работы метода.

Она отвечает на вопрос:

> Что реально получилось?

**Пример:**

```java
int expected = 4;
int actual = "Java".length();

Assertions.assertEquals(expected, actual);
```

---

## Тестовый сценарий

**Определение:**

Тестовый сценарий — это конкретная ситуация, которую мы проверяем тестом.

Например, для метода деления можно проверить разные сценарии:

* обычное деление;
* деление отрицательных чисел;
* деление на ноль;
* деление нуля на число.

**Пример:**

```java
@Test
public void divide_byZero_throwsException() {
    Calculator calculator = new Calculator();

    Assertions.assertThrows(ArithmeticException.class, () -> {
        calculator.divide(10, 0);
    });
}
```

---

## Тестовые данные

**Определение:**

Тестовые данные — это входные значения, на которых проверяется код.

Хорошие тесты проверяют не только «обычные» данные, но и пограничные случаи.

**Пример:**

```java
@Test
public void isAdult_age18_returnsTrue() {
    UserService service = new UserService();

    boolean result = service.isAdult(18);

    Assertions.assertTrue(result);
}
```

---

## Пограничный случай

**Определение:**

Пограничный случай — это значение на границе допустимого диапазона.

Именно на границах часто появляются ошибки.

Например, если совершеннолетие начинается с 18 лет, то важно проверить:

* `17`;
* `18`;
* `19`.

**Пример:**

```java
@Test
public void isAdult_age17_returnsFalse() {
    UserService service = new UserService();

    boolean result = service.isAdult(17);

    Assertions.assertFalse(result);
}
```

## Модульное тестирование

**Определение:**

Модульное тестирование — это проверка отдельных частей программы в изоляции.

Цель — убедиться, что каждый модуль работает сам по себе.

Если один маленький модуль работает неправильно, большая система тоже может работать неправильно.

**Пример:**

```java
@Test
public void calculateDiscount_price100_returns10() {
    DiscountService service = new DiscountService();

    int discount = service.calculateDiscount(100);

    Assertions.assertEquals(10, discount);
}
```

---

## Интеграционное тестирование

**Определение:**

Интеграционное тестирование — это проверка того, как несколько модулей работают вместе.

Например, можно проверить взаимодействие:

* сервиса и репозитория;
* приложения и базы данных;
* нескольких компонентов системы.

**Пример:**

```java
@Test
public void saveUser_validUser_userCanBeFound() {
    User user = new User("Ivan");

    userRepository.save(user);

    User foundUser = userRepository.findByName("Ivan");

    Assertions.assertNotNull(foundUser);
}
```

---

## Системное тестирование

**Определение:**

Системное тестирование — это проверка всей системы целиком.

На этом уровне проверяют, что приложение работает от начала до конца.

Обычно системное тестирование проводят тестировщики или автотестеры.

**Пример:**

```text
Пользователь открывает сайт
        ↓
Вводит логин и пароль
        ↓
Нажимает "Войти"
        ↓
Попадает в личный кабинет
```

---

## Приёмочное тестирование

**Определение:**

Приёмочное тестирование — это проверка результата с точки зрения заказчика или пользователя.

Цель — убедиться, что продукт действительно делает то, что от него ожидали.

Часто это происходит в формате демонстрации или проверки готовой функциональности.

**Пример:**

```text
Заказчик проверяет:
"Пользователь должен иметь возможность оформить заказ и получить номер заказа."
```

## JUnit

**Определение:**

`JUnit` — это фреймворк для написания и запуска unit-тестов в Java.

Он позволяет:

* помечать методы как тесты;
* запускать тесты автоматически;
* сравнивать ожидаемый и фактический результат;
* проверять исключения;
* запускать подготовительные методы до и после тестов.

**Пример:**

```java
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.Assertions;

public class CalculatorTest {

    @Test
    public void sum_twoNumbers_returnsSum() {
        Calculator calculator = new Calculator();

        int result = calculator.sum(2, 3);

        Assertions.assertEquals(5, result);
    }
}
```

## JUnit 5

**Определение:**

`JUnit 5` — это современная версия JUnit.

В JUnit 5 используются аннотации из пакета:

```java
org.junit.jupiter.api
```

Например:

```java
@Test
@BeforeEach
@AfterEach
@BeforeAll
@AfterAll
```

**Пример:**

```java
import org.junit.jupiter.api.Test;

public class StringTest {
```

## @Test

**Определение:**

`@Test` — это аннотация JUnit, которая показывает, что метод является тестом.

JUnit ищет методы с этой аннотацией и запускает их как тесты.

Тестовый метод обычно:

* ничего не возвращает;
* не принимает параметры;
* содержит проверку через `Assertions`.

**Пример:**

```java
@Test
public void testMethod() {
    Assertions.assertTrue(10 > 5);
}
```

## Тестовый метод

**Определение:**

Тестовый метод — это метод, который проверяет конкретное поведение кода.

В JUnit такой метод помечается аннотацией `@Test`.

Хороший тестовый метод проверяет одну конкретную ситуацию.

**Пример:**

```java
@Test
public void concat_emptyString_returnsOriginalString() {
    String original = "Test string ";
    String argument = "";

    String result = original.concat(argument);

    Assertions.assertEquals(original, result);
}
```

## Тестовый класс

**Определение:**

Тестовый класс — это класс, в котором находятся тестовые методы.

Обычно имя тестового класса заканчивается на `Test`.

Например:

```text
CalculatorTest
UserServiceTest
StringUtilsTest
```

**Пример:**

```java
public class CalculatorTest {

    @Test
    public void sum_twoNumbers_returnsSum() {
        Calculator calculator = new Calculator();

        int result = calculator.sum(2, 3);

        Assertions.assertEquals(5, result);
    }
}
```

## src/test/java

**Определение:**

`src/test/java` — это стандартная папка Maven и Gradle для тестового Java-кода.

Именно там обычно хранятся классы с unit-тестами.

Основной код находится в `src/main/java`, а тесты — в `src/test/java`.

**Пример:**

```text
src
├── main
│   └── java
│       └── ru/netology/Calculator.java
└── test
    └── java
        └── ru/netology/CalculatorTest.java
```

## Production code

**Определение:**

`Production code` — это основной код приложения, который выполняет реальную бизнес-логику.

Это код, который пойдёт в готовую программу.

Тесты не являются production code. Они проверяют production code.

**Пример:**

```java
public class Calculator {
    public int sum(int first, int second) {
        return first + second;
    }
}
```

Это production code.

## Assertions

**Определение:**

`Assertions` — это класс JUnit, который содержит методы для проверки результатов теста.

С помощью `Assertions` мы говорим:

> Я ожидал одно значение, проверь, совпало ли оно с реальным.

Если проверка не проходит, тест падает.

**Пример:**

```java
Assertions.assertEquals(10, 5 + 5);
```

## Assertion

**Определение:**

`Assertion` — это проверка внутри теста.

Она сравнивает ожидание и реальность.

Если условие проверки выполняется, тест проходит.

Если нет — тест падает.

**Пример:**

```java
Assertions.assertTrue("Java".contains("J"));
```

## assertEquals()

**Определение:**

`assertEquals()` — это метод JUnit, который проверяет равенство ожидаемого и фактического значения.

Обычно первым аргументом передают ожидаемое значение, вторым — фактическое.

**Пример:**

```java
@Test
public void sum_twoNumbers_returnsSum() {
    int expected = 7;
    int actual = 3 + 4;

    Assertions.assertEquals(expected, actual);
}
```

## assertArrayEquals()

**Определение:**

`assertArrayEquals()` — это метод JUnit, который проверяет равенство двух массивов.

Обычный `assertEquals()` не подходит для полноценного сравнения содержимого массивов, поэтому для массивов используют отдельный метод.

**Пример:**

```java
@Test
public void sort_unsortedArray_returnsSortedArray() {

    Assertions.assertArrayEquals(expected, actual);
```

## Exception testing

**Определение:**

`Exception testing` — это тестирование ситуаций, когда код должен выбросить исключение.

Такие тесты важны, потому что правильное поведение программы — это не только успешный результат, но и корректная реакция на ошибочные данные.

**Пример:**

```java
@Test
public void divide_byZero_throwsArithmeticException() {
    Calculator calculator = new Calculator();

    Assertions.assertThrows(ArithmeticException.class, () -> {
        calculator.divide(10, 0);
    });
}
```

## Лямбда в assertThrows()

**Определение:**

Лямбда в `assertThrows()` нужна, чтобы передать JUnit код, который должен выбросить исключение.

JUnit сам запускает этот код и проверяет, действительно ли было выброшено нужное исключение.

**Пример:**

```java
Assertions.assertThrows(NullPointerException.class, () -> {
    String text = null;
    text.length();
});
```

## Фикстура теста

**Определение:**

Фикстура теста — это подготовленное окружение для выполнения тестов.

Например:

* создание объекта сервиса;
* подготовка тестовых данных;
* открытие соединения;
* очистка состояния после теста.

Фикстуры помогают не дублировать одинаковую подготовку в каждом тесте.

**Пример:**

```java
private Calculator calculator;

@BeforeEach
public void setUp() {
    calculator = new Calculator();
}
```

## @BeforeEach

**Определение:**

`@BeforeEach` — это аннотация JUnit 5.

Метод с этой аннотацией запускается перед каждым тестовым методом.

Обычно используется для подготовки данных перед тестом.

**Пример:**

```java
private Calculator calculator;

@BeforeEach
public void setUp() {
    calculator = new Calculator();
}

@Test
public void sum_twoNumbers_returnsSum() {
    int result = calculator.sum(2, 3);

    Assertions.assertEquals(5, result);
}
```

---

## @AfterEach

**Определение:**

`@AfterEach` — это аннотация JUnit 5.

Метод с этой аннотацией запускается после каждого тестового метода.

Обычно используется для очистки ресурсов или вывода служебной информации.

**Пример:**

```java
@AfterEach
public void tearDown() {
    System.out.println("Тест завершён");
}
```

---

## @BeforeAll

**Определение:**

`@BeforeAll` — это аннотация JUnit 5.

Метод с этой аннотацией запускается один раз перед всеми тестами в классе.

Такой метод обычно делают `static`.

**Пример:**

```java
@BeforeAll
public static void initAll() {
    System.out.println("Запуск набора тестов");
}
```

## @AfterAll

**Определение:**

`@AfterAll` — это аннотация JUnit 5.

Метод с этой аннотацией запускается один раз после всех тестов в классе.

Такой метод обычно делают `static`.

**Пример:**

```java
@AfterAll
public static void finishAll() {
    System.out.println("Все тесты завершены");

```

## Given-When-Then

**Определение:**

`Given-When-Then` — это стиль оформления теста, при котором тест делится на три логические части.

* `Given` — подготовка данных.
* `When` — вызов тестируемого действия.
* `Then` — проверка результата.

Этот стиль помогает читать тест как маленький сценарий.

**Пример:**

```java
@Test
public void sum_twoNumbers_returnsSum() {
    // given
    Calculator calculator = new Calculator();

    // when
    int result = calculator.sum(2, 3);

    // then
    Assertions.assertEquals(5, result);
}
```

## Параметризованный тест

**Определение:**

Параметризованный тест — это тест, который запускается несколько раз с разными входными данными.

Он полезен, когда одна и та же логика должна быть проверена на нескольких значениях.

**Пример:**

```java
@ParameterizedTest
@ValueSource(strings = {"Hello", "World"})
public void containsLetterO_stringValues_returnsTrue(String text) {
    Assertions.assertTrue(text.contains("o"));
}
```

---

## @ParameterizedTest

**Определение:**

`@ParameterizedTest` — это аннотация JUnit 5 для создания параметризованных тестов.

В отличие от обычного `@Test`, такой тест может принимать параметры.

**Пример:**

```java
@ParameterizedTest
@ValueSource(ints = {2, 4, 6, 8})
public void isEven_evenNumbers_returnsTrue(int number) {
    Assertions.assertTrue(number % 2 == 0);
}
```

## @ValueSource

**Определение:**

`@ValueSource` — это аннотация JUnit 5, которая передаёт набор простых значений в параметризованный тест.

Можно передавать строки, числа и другие простые типы.

**Пример:**

```java
@ParameterizedTest
@ValueSource(strings = {"Java", "JUnit", "Test"})
public void length_notEmptyStrings_greaterThanZero(String text) {
    Assertions.assertTrue(text.length() > 0);
}
```

## TDD

**Определение:**

`TDD`, или `Test-Driven Development`, — это подход к разработке, при котором сначала пишут тесты, а потом код под эти тесты.

Идея такая:

1. написать падающий тест;
2. написать минимальный код, чтобы тест прошёл;
3. улучшить код, не ломая тесты.

**Пример:**

```java
@Test
public void sum_twoNumbers_returnsSum() {
    Calculator calculator = new Calculator();

    Assertions.assertEquals(5, calculator.sum(2, 3));
}
```

Сначала можно написать этот тест, а уже потом реализовать метод `sum()`.

## BDD

**Определение:**

`BDD`, или `Behavior-Driven Development`, — это подход к разработке через описание поведения системы.

В BDD сначала формулируют, как система должна вести себя с точки зрения пользователя или бизнеса.

Часто сценарии описываются словами:

```text
Дано ...
Когда ...
Тогда ...
```

**Пример:**

```text
Дано: пользователь положил товар в корзину
Когда: пользователь оформляет заказ
Тогда: система создаёт заказ и показывает его номер
```

## Hamcrest

**Определение:**

`Hamcrest` — это библиотека для более читаемых проверок в тестах.

Она позволяет писать проверки ближе к обычному человеческому языку.

Например, вместо нескольких `assertTrue()` можно использовать `assertThat()` и matcher.

**Пример:**

```java
@Test
public void list_containsExpectedItems() {
    List<String> list = List.of("hello", "netology", "world");

    assertThat(list, hasItems("hello", "netology"));
}
```

---

## assertThat()

**Определение:**

`assertThat()` — это стиль проверки, который часто используется вместе с Hamcrest.

Он позволяет проверить объект через специальные matcher-методы.

**Пример:**

```java
assertThat("Java", containsString("av"));
```

---

## Matcher

**Определение:**

`Matcher` — это объект или метод, который описывает условие проверки.

Например:

* строка содержит подстроку;
* список содержит элементы;
* число больше другого числа.

В Hamcrest matcher делает проверку более читаемой.

**Пример:**

```java
assertThat(List.of("a", "b", "c"), hasItems("a", "c"));
```

---

## hasItems()

**Определение:**

`hasItems()` — это matcher из Hamcrest, который проверяет, что коллекция содержит указанные элементы.

**Пример:**

```java
@Test
public void list_containsSeveralItems() {
    List<String> names = List.of("Tom", "Alice", "Mark");

    assertThat(names, hasItems("Tom", "Mark"));
}
```

---

## Mockito

**Определение:**

`Mockito` — это библиотека для создания mock-объектов в тестах.

Mock-объекты нужны, когда тестируемый класс зависит от других классов, базы данных, сети или внешних сервисов.

В этой теме Mockito только упоминается, подробно его обычно изучают отдельно.

**Пример:**

```java
UserRepository repository = Mockito.mock(UserRepository.class);
```

---

## Mock-объект

**Определение:**

Mock-объект — это искусственный объект для тестов, который имитирует поведение настоящего объекта.

Он нужен, чтобы изолировать тестируемый код от внешних зависимостей.

Например, вместо настоящей базы данных можно использовать mock-репозиторий.

**Пример:**

```java
UserRepository repository = Mockito.mock(UserRepository.class);

Mockito.when(repository.findNameById(1)).thenReturn("Ivan");
```

## Именование тестов

**Определение:**

Именование тестов — это способ назвать тестовый метод так, чтобы по названию было понятно:

* что тестируем;
* при каких условиях;
* какой результат ожидаем.

Частый шаблон:

```text
methodName_condition_expectedResult
```

**Пример:**

```java
@Test
public void concat_emptyString_returnsOriginalString() {
    String original = "Java";

    String result = original.concat("");

    Assertions.assertEquals(original, result);
}
```
