# Тема: Тестирование программы. Mockito

## Зависимость класса

**Определение:**

Зависимость класса — это другой объект, сервис или модуль, который нужен классу для работы.

Например, если `AdviceService` внутри себя использует `WeatherService`, значит `AdviceService` зависит от `WeatherService`.

В тестах зависимости могут мешать: они могут обращаться к базе данных, сети, файлам или внешним сервисам. Поэтому такие зависимости часто заменяют mock-объектами.

**Пример:**

```java
public class AdviceService {
    private final WeatherService weatherService;

    public AdviceService(WeatherService weatherService) {
        this.weatherService = weatherService;
    }

    public String getAdvice() {
        if (weatherService.currentWeather() == Weather.RAINY) {
            return "Stay home";
        }

        return "Go outside";
    }
}
```

---

## Изолированный unit-тест

**Определение:**

Изолированный unit-тест — это тест, который проверяет один конкретный класс или метод без настоящих внешних зависимостей.

Если класс зависит от другого сервиса, базы данных или API, в изолированном тесте эти зависимости обычно заменяют mock-объектами.

Главная идея: тест должен проверять именно тестируемый класс, а не всё приложение сразу.

**Пример:**

```java
@Test
public void getAdvice_rainyWeather_returnsStayHome() {
    WeatherService weatherService = Mockito.mock(WeatherService.class);
    Mockito.when(weatherService.currentWeather()).thenReturn(Weather.RAINY);

    AdviceService adviceService = new AdviceService(weatherService);

    String result = adviceService.getAdvice();

    Assertions.assertEquals("Stay home", result);
}
```

## Mock

**Определение:**

`Mock` — это объект-заглушка, который имитирует поведение настоящего объекта.

Mock используют, чтобы не подключать в тестах реальные зависимости: базу данных, сеть, внешний сервис или сложный модуль.

Mock возвращает заранее подготовленный результат, который нужен для конкретного теста.

**Пример:**

```java
WeatherService weatherService = Mockito.mock(WeatherService.class);

Mockito.when(weatherService.currentWeather())
        .thenReturn(Weather.RAINY);
```

---

## Заглушка

**Определение:**

Заглушка — это объект, который подменяет настоящую зависимость в тесте.

Например, вместо настоящего сервиса погоды можно использовать заглушку, которая всегда возвращает `RAINY`.

Вручную заглушку можно написать отдельным классом, но чаще для этого используют Mockito.

**Пример:**

```java
public class WeatherServiceMock implements WeatherService {
    @Override
    public Weather currentWeather() {
        return Weather.RAINY;
    }
}
```

---

## Mockito

**Определение:**

`Mockito` — это библиотека для создания mock-объектов в Java-тестах.

Mockito позволяет:

* создавать заглушки;
* задавать поведение mock-объектов;
* проверять, какие методы были вызваны;
* проверять количество вызовов;
* перехватывать аргументы, с которыми вызывались методы.

**Пример:**

```java
UserRepository repository = Mockito.mock(UserRepository.class);

Mockito.when(repository.findNameById(1))
        .thenReturn("Ivan");
```

---

## Mockito.mock()

**Определение:**

`Mockito.mock()` — это метод, который создаёт mock-объект указанного класса или интерфейса.

Такой объект выглядит как настоящий объект нужного типа, но его поведение можно настроить прямо в тесте.

**Пример:**

```java
WeatherService weatherService = Mockito.mock(WeatherService.class);
```

---

## Stubbing

**Определение:**

`Stubbing` — это настройка поведения mock-объекта.

Когда мы говорим mock-объекту:

> Если вызовут этот метод, верни вот такое значение.

В Mockito stubbing обычно пишется через связку:

```java
when(...).thenReturn(...)
```

**Пример:**

```java
Mockito.when(weatherService.currentWeather())
        .thenReturn(Weather.SUNNY);
```

---

## when()

**Определение:**

`when()` — это метод Mockito, который указывает, какой вызов mock-объекта мы хотим настроить.

После `when()` обычно пишут `thenReturn()`.

**Пример:**

```java
Mockito.when(weatherService.currentWeather())
        .thenReturn(Weather.STORMY);
```

---

## thenReturn()

**Определение:**

`thenReturn()` — это метод Mockito, который указывает, что должен вернуть mock-объект при вызове настроенного метода.

**Пример:**

```java
Mockito.when(preferencesService.get("user1"))
        .thenReturn(Set.of(Preference.READING, Preference.FOOTBALL));
```

---

## any()

**Определение:**

`Mockito.any()` — это matcher аргументов.

Он означает: «подойдёт любое значение этого типа».

Используется, когда в тесте не важно, какой именно аргумент передали в метод.

**Пример:**

```java
Mockito.when(preferencesService.get(Mockito.any()))
        .thenReturn(Set.of(Preference.READING));
```

---

## Spy

**Определение:**

`Spy` — это частичная заглушка.

В отличие от обычного mock, spy создаётся на основе реального объекта или класса и по умолчанию вызывает настоящие методы.

Но отдельные методы spy-объекта можно переопределить через Mockito.

Spy используют, когда нужно протестировать объект почти как настоящий, но изменить часть его поведения.

**Пример:**

```java
WeatherServiceImpl realService = new WeatherServiceImpl();

WeatherServiceImpl spyService = Mockito.spy(realService);

Mockito.when(spyService.currentWeather())
        .thenReturn(Weather.STORMY);
```

---

## Mockito.spy()

**Определение:**

`Mockito.spy()` — это метод, который создаёт spy-объект.

Spy по умолчанию вызывает реальные методы объекта, но позволяет переопределять отдельные вызовы.

**Пример:**

```java
WeatherServiceImpl weatherService = Mockito.spy(new WeatherServiceImpl());

Mockito.when(weatherService.currentWeather())
        .thenReturn(Weather.RAINY);
```

---

## verify()

**Определение:**

`verify()` — это метод Mockito, который проверяет, был ли вызван определённый метод mock-объекта.

Он нужен, когда важно проверить не только результат, но и факт взаимодействия с зависимостью.

**Пример:**

```java
Mockito.verify(preferencesService).get("user1");
```

---

## Mockito.verify()

**Определение:**

`Mockito.verify()` проверяет взаимодействие с mock-объектом.

Например, можно проверить:

* был ли вызван метод;
* сколько раз он был вызван;
* с какими аргументами он был вызван.

**Пример:**

```java
Mockito.verify(preferencesService, Mockito.times(1))
        .get("user1");
```

---

## VerificationMode

**Определение:**

`VerificationMode` — это режим проверки вызовов в Mockito.

Он отвечает на вопрос:

> Сколько раз должен был быть вызван метод?

Примеры режимов:

* `times(1)`;
* `never()`;
* `atLeastOnce()`;
* `atMost(2)`.

**Пример:**

```java
Mockito.verify(weatherService, Mockito.times(1))
        .currentWeather();
```

---

## times()

**Определение:**

`times()` — это режим проверки Mockito, который указывает точное количество вызовов метода.

**Пример:**

```java
Mockito.verify(preferencesService, Mockito.times(1))
        .get("user1");
```

---

## never()

**Определение:**

`never()` — это режим проверки Mockito, который проверяет, что метод ни разу не был вызван.

По смыслу это то же самое, что `times(0)`.

**Пример:**

```java
Mockito.verify(preferencesService, Mockito.never())
        .get("user2");
```

---

## only()

**Определение:**

`only()` — это режим проверки Mockito, который проверяет, что на mock-объекте был вызван только один конкретный метод и никаких других взаимодействий не было.

**Пример:**

```java
Mockito.verify(weatherService, Mockito.only())
        .currentWeather();
```

---

## atLeastOnce()

**Определение:**

`atLeastOnce()` — это режим проверки Mockito, который проверяет, что метод был вызван хотя бы один раз.

**Пример:**

```java
Mockito.verify(weatherService, Mockito.atLeastOnce())
        .currentWeather();
```

---

## atLeast()

**Определение:**

`atLeast()` — это режим проверки Mockito, который проверяет, что метод был вызван не меньше указанного количества раз.

**Пример:**

```java
Mockito.verify(weatherService, Mockito.atLeast(2))
        .currentWeather();
```

---

## atMost()

**Определение:**

`atMost()` — это режим проверки Mockito, который проверяет, что метод был вызван не больше указанного количества раз.

**Пример:**

```java
Mockito.verify(weatherService, Mockito.atMost(3))
        .currentWeather();
```

---

## timeout()

**Определение:**

`timeout()` — это режим проверки Mockito, который проверяет, что метод был вызван в течение указанного времени.

Время указывается в миллисекундах.

Чаще применяется в асинхронном коде.

**Пример:**

```java
Mockito.verify(notificationService, Mockito.timeout(1000))
        .send();
```

---

## after()

**Определение:**

`after()` — это режим проверки Mockito, который ждёт указанное количество миллисекунд и затем проверяет вызов метода.

**Пример:**

```java
Mockito.verify(notificationService, Mockito.after(500))
        .send();
```

---

## ArgumentCaptor

**Определение:**

`ArgumentCaptor` — это инструмент Mockito, который позволяет перехватить аргумент, переданный в метод mock-объекта.

Он полезен, когда нужно проверить не просто факт вызова метода, а конкретное значение, с которым метод был вызван.

**Пример:**

```java
ArgumentCaptor<String> captor = ArgumentCaptor.forClass(String.class);

Mockito.verify(preferencesService).get(captor.capture());

Assertions.assertEquals("user1", captor.getValue());
```

---

## capture()

**Определение:**

`capture()` — это метод `ArgumentCaptor`, который перехватывает аргумент во время проверки через `verify()`.

Сам по себе `capture()` обычно используется внутри вызова mock-метода.

**Пример:**

```java
Mockito.verify(preferencesService)
        .get(captor.capture());
```

---

## getValue()

**Определение:**

`getValue()` — это метод `ArgumentCaptor`, который возвращает последнее перехваченное значение.

**Пример:**

```java
String userId = captor.getValue();

Assertions.assertEquals("user1", userId);
```

---

## getValues()

**Определение:**

`getValues()` — это метод `ArgumentCaptor`, который возвращает все перехваченные значения.

Он полезен, если метод mock-объекта вызывался несколько раз.

**Пример:**

```java
List<String> userIds = captor.getAllValues();

Assertions.assertEquals(List.of("user1", "user2"), userIds);
```

---

## Интерфейс как зависимость

**Определение:**

Интерфейс как зависимость — это подход, при котором класс зависит не от конкретной реализации, а от интерфейса.

Это удобно для тестирования, потому что интерфейс легко заменить mock-объектом.

В продакшене это одна из причин, почему зависимости часто проектируют через интерфейсы.

**Пример:**

```java
public class AdviceService {
    private final WeatherService weatherService;

    public AdviceService(WeatherService weatherService) {
        this.weatherService = weatherService;
    }
}
```

---

## Подмена зависимости

**Определение:**

Подмена зависимости — это замена настоящего объекта на тестовый объект.

Например, вместо реального `WeatherService` в тест можно передать mock, который всегда возвращает нужную погоду.

**Пример:**

```java
WeatherService weatherService = Mockito.mock(WeatherService.class);

Mockito.when(weatherService.currentWeather())
        .thenReturn(Weather.STORMY);

AdviceService adviceService = new AdviceService(weatherService);
```

---

## Ограничения Mockito

**Определение:**

Ограничения Mockito — это ситуации, в которых Mockito не может или не должен создавать mock-объекты обычным способом.

В классической конфигурации Mockito есть ограничения при работе с:

* `final`-классами;
* `private`-методами;
* конструкторами;
* методами `equals()` и `hashCode()`.

Обычно Mockito используют для подмены внешних зависимостей, а не для тестирования приватной внутренней логики класса.

**Пример:**

```java
// Плохая идея: пытаться мокать приватный метод.
// Лучше тестировать публичное поведение класса.
```

## PowerMock

**Определение:**

`PowerMock` — это дополнительная библиотека для более сложного создания mock-объектов.

Она может использоваться там, где обычного Mockito недостаточно.

Но в обычных unit-тестах лучше сначала проектировать код так, чтобы его можно было тестировать без тяжёлых инструментов.

**Пример:**

```java
// PowerMock обычно нужен для сложных случаев,
// например при работе со static или private-логикой.
```
