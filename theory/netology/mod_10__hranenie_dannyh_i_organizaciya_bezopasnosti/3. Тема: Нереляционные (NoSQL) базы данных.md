# Тема 3: Нереляционные (NoSQL) базы данных

> Основа: презентация «Нереляционные (NoSQL) базы данных», Виктор Лоскутов (74 слайда). Термин **NoSQL** уже определён в теме 1, поэтому здесь раскрываются его особенности, модели данных и интеграция с Java.
>
> Примеры приведены для знакомства с синтаксисом; библиотеки и конфигурация сервера должны соответствовать используемым версиям.

## RDBMS (Relational Database Management System)

**Определение:**

RDBMS — реляционная система управления базами данных, в которой данные организованы в таблицы со столбцами, типами данных и ограничениями.

**Примеры:** PostgreSQL, MySQL, Oracle Database.

**Важно:** RDBMS и NoSQL различаются прежде всего моделью данных и возможностями конкретных продуктов. Реляционные СУБД тоже могут хранить JSON и масштабироваться горизонтально.

---

## Горизонтальное масштабирование (Horizontal Scaling, Scale Out)

**Определение:**

Горизонтальное масштабирование — увеличение ресурсов системы за счёт добавления новых серверов или узлов.

**Пример:** вместо одного сервера с базой данных используется кластер из нескольких узлов.

**Зачем нужно:** распределять нагрузку и хранить большие объёмы данных. Добавление узлов само по себе не гарантирует линейного ускорения.

---

## Вертикальное масштабирование (Vertical Scaling, Scale Up)

**Определение:**

Вертикальное масштабирование — увеличение ресурсов одного сервера: процессора, оперативной памяти, дисковой подсистемы.

**Пример:** увеличить RAM сервера БД с 16 до 64 ГБ.

**Отличие:** `scale up` — усилить один узел, `scale out` — добавить узлы.

---

## Кластер (Cluster) и узел (Node)

**Определение:**

Кластер — группа серверов, совместно обеспечивающих работу одной системы. Узел — отдельный сервер или экземпляр системы, входящий в кластер.

**Пример:** три узла MongoDB могут хранить копии данных и обеспечивать переключение при сбое.

---

## Высокая доступность (High Availability, HA)

**Определение:**

Высокая доступность — способность системы продолжать обслуживать запросы при отказах отдельных компонентов и минимизировать простой.

**Пример:** если один узел БД выходит из строя, другой принимает его роль.

**Важно:** высокая доступность не означает абсолютного отсутствия сбоев.

---

## Отказоустойчивость (Fault Tolerance)

**Определение:**

Отказоустойчивость — способность системы сохранять работоспособность при неисправности части компонентов.

**Пример:** данные реплицированы на несколько узлов, поэтому выход одного узла не приводит к потере доступа ко всем копиям.

---

## Гибкая схема данных (Flexible Schema)

**Определение:**

Гибкая схема — возможность хранить записи с разными наборами полей без обязательного изменения структуры всей коллекции.

**Пример (два документа MongoDB):**

```json
{"name": "Anna", "age": 25}
{"name": "Ivan", "skills": ["Java", "SQL"]}
```

**Важно:** отсутствие жёсткой схемы не отменяет валидацию данных в приложении или на стороне БД.

---

## Документная база данных (Document Database)

**Определение:**

Документная БД хранит данные в виде документов с полями, вложенными объектами и массивами.

**Примеры:** MongoDB, Couchbase.

**Пример документа:**

```json
{
  "name": "Anna",
  "address": {"city": "Moscow"},
  "skills": ["Java", "Spring"]
}
```

**Где применяется:** каталоги товаров, профили пользователей, контент с изменяющейся структурой.

---

## JSON и BSON

**Определение:**

**JSON (JavaScript Object Notation)** — текстовый формат представления структурированных данных. **BSON (Binary JSON)** — бинарный формат документов, используемый MongoDB; поддерживает дополнительные типы данных.

**Пример JSON:**

```json
{"userId": 10, "active": true}
```

**Важно:** MongoDB сохраняет документы в BSON, хотя при взаимодействии с ними часто используется JSON-подобный синтаксис.

---

## Документ (Document) и коллекция (Collection) в MongoDB

**Определение:**

Документ — отдельная запись MongoDB, состоящая из полей и значений. Коллекция — группа документов в пределах базы данных.

**Аналогия:** документ ≈ строка таблицы, коллекция ≈ таблица. Это приблизительное сравнение: структуры и правила хранения различаются.

**Пример (MongoDB Shell):**

```javascript
db.users.insertOne({name: "Anna", age: 25});
db.users.find({age: {$gte: 18}});
```

---

## Колоночно-семейная база данных (Wide-Column Store)

**Определение:**

Wide-column БД хранит данные в распределённой модели с ключами строк и группами столбцов (семействами колонок); состав доступных колонок может различаться.

**Примеры:** Apache Cassandra, HBase, ScyllaDB.

**Где применяется:** большие потоки событий, телеметрия, распределённые хранилища с высокой нагрузкой.

**Важно:** wide-column (Cassandra, HBase) — не то же самое, что аналитическая столбцовая СУБД вроде ClickHouse. В презентации эти подходы частично смешаны.

---

## Графовая база данных (Graph Database)

**Определение:**

Графовая БД хранит сущности и связи между ними в виде графа. Подходит для запросов, которые проходят через много связанных объектов.

**Пример:** Neo4j.

**Где применяется:** рекомендательные системы, социальные связи, выявление мошеннических цепочек.

---

## Вершина (Node) и ребро (Edge / Relationship)

**Определение:**

Вершина — сущность графа (например, пользователь). Ребро — связь между сущностями (например, «дружит с»).

**Пример (Cypher для Neo4j):**

```cypher
CREATE (anna:Person {name: 'Anna'}),
       (ivan:Person {name: 'Ivan'}),
       (anna)-[:KNOWS]->(ivan);
```

---

## Cypher

**Определение:**

Cypher — декларативный язык запросов к графовым данным, используемый в Neo4j.

**Пример:**

```cypher
MATCH (person:Person)-[:KNOWS]->(friend:Person)
RETURN person.name, friend.name;
```

**Результат:** пары имён людей, соединённых связью `KNOWS`.

---

## База данных «ключ — значение» (Key-Value Store)

**Определение:**

Key-value БД хранит значения по уникальным ключам. Основные действия: записать, получить, удалить значение по ключу.

**Пример:** Redis.

**Пример (Redis CLI):**

```text
SET user:1:name "Anna"
GET user:1:name
DEL user:1:name
```

**Где применяется:** кэш, пользовательские сессии, счётчики, быстрый доступ к состоянию.

---

## Кэширование (Caching)

**Определение:**

Кэширование — временное хранение часто используемых данных для ускорения доступа к ним и снижения нагрузки на основной источник.

**Пример:** Java-сервис получает профиль пользователя из PostgreSQL и временно сохраняет результат в Redis, чтобы повторно не выполнять дорогой запрос.

**Важно:** кэш может устаревать; приложение должно учитывать обновление и удаление кэшированных данных.

---

## TTL (Time To Live)

**Определение:**

TTL — время жизни записи, после истечения которого она может автоматически удаляться или считаться просроченной (поведение зависит от БД).

**Пример (Redis):**

```text
SET session:123 "active" EX 300
```

Значение ключа хранится с временем жизни 300 секунд.

---

## Репликация (Replication)

**Определение:**

Репликация — создание и поддержание копий данных на нескольких узлах.

**Зачем нужна:** повышение доступности и устойчивости к сбоям; в некоторых архитектурах — разгрузка операций чтения.

**Важно:** репликация не всегда означает мгновенную синхронизацию всех копий.

---

## Шардирование (Sharding)

**Определение:**

Шардирование — распределение разных частей набора данных между несколькими узлами (шардами).

**Пример:** пользователи распределяются по шардам на основании значения `userId` или его хеша.

**Отличие:** репликация хранит копии данных, шардирование распределяет данные по частям.

---

## Согласованность данных (Consistency) и Eventual Consistency

**Определение:**

Согласованность — свойство, определяющее, какие результаты чтения допустимы при изменении данных. **Eventual consistency** (согласованность в конечном счёте) означает, что после прекращения обновлений реплики со временем сходятся к согласованному состоянию.

**Пример:** новое значение уже записано на один узел, но другой некоторое время может возвращать старое.

**Важно:** не все NoSQL-БД используют eventual consistency; гарантия согласованности зависит от продукта и настроек.

---

## Драйвер базы данных (Database Driver)

**Определение:**

Драйвер — библиотека, через которую Java-приложение взаимодействует с конкретной БД, используя её протокол и API.

**Примеры из презентации:** MongoDB Java Driver, DataStax Java Driver, Jedis, Lettuce, Neo4j Java Driver.

**Пример:**

```java
try (var client = com.mongodb.client.MongoClients.create("mongodb://localhost:27017")) {
    var database = client.getDatabase("app");
    System.out.println(database.getName());
}
```

**Важно:** `getDatabase()` возвращает объект-представление БД, но сам по себе не создаёт физическую базу на сервере.

---

## MongoDB Java Driver

**Определение:**

Официальный Java-драйвер MongoDB — библиотека для подключения к MongoDB и выполнения операций над документами и коллекциями.

**Пример (синхронный API):**

```java
import com.mongodb.client.MongoClients;
import org.bson.Document;

try (var client = MongoClients.create("mongodb://localhost:27017")) {
    var collection = client.getDatabase("app").getCollection("users");
    collection.insertOne(new Document("name", "Anna").append("age", 25));

    Document user = collection.find(new Document("name", "Anna")).first();
    if (user != null) {
        System.out.println(user.toJson());
    }
}
```

**Важно:** для запуска необходима зависимость актуального синхронного MongoDB Java Driver и доступный сервер MongoDB. В презентации показаны устаревшие координаты зависимости `mongo-java-driver:4.6.0`.

---

## Spring Data MongoDB

**Определение:**

Spring Data MongoDB — модуль Spring Data, который упрощает работу с MongoDB через отображение Java-объектов в документы, репозитории и шаблоны доступа к данным.

**Пример:**

```java
import org.springframework.data.annotation.Id;
import org.springframework.data.mongodb.core.mapping.Document;
import org.springframework.data.mongodb.repository.MongoRepository;

@Document("users")
class User {
    @Id
    private String id;
    private String name;
}

interface UserRepository extends MongoRepository<User, String> {
}
```

**В продакшене:** удобен в Spring Boot-проектах, когда нужны репозитории и единообразный слой доступа к данным.

---

## Spring Data Repository

**Определение:**

Repository — интерфейс абстракции доступа к данным. В Spring Data можно наследовать готовый интерфейс репозитория и получать стандартные операции чтения и записи без ручной реализации каждой из них.

**Пример:**

```java
interface UserRepository extends MongoRepository<User, String> {
    java.util.List<User> findByName(String name);
}
```

Spring Data формирует реализацию метода поиска по соглашению об имени (при корректно настроенной модели).

---

## Jedis и Lettuce

**Определение:**

Jedis и Lettuce — Java-клиенты для Redis. Оба позволяют выполнять команды Redis; Lettuce также поддерживает асинхронный и реактивный подходы.

**Пример (Jedis):**

```java
import redis.clients.jedis.Jedis;

try (Jedis jedis = new Jedis("localhost", 6379)) {
    jedis.set("greeting", "Hello");
    System.out.println(jedis.get("greeting"));
}
```

---

## Spring Data Cassandra и Spring Data Neo4j

**Определение:**

Spring Data Cassandra и Spring Data Neo4j — модули Spring Data для работы соответственно с Apache Cassandra и Neo4j. Предоставляют средства отображения данных и репозиторный подход с учётом конкретной модели БД.

**Важно:** единый стиль Spring Data не означает одинаковые возможности запросов у разных СУБД.

---

# Важные уточнения к презентации

1. **NoSQL не означает отказ от ACID.** Например, Neo4j поддерживает ACID-транзакции; MongoDB поддерживает транзакции, в том числе для нескольких документов. Гарантии зависят от системы.
2. **NoSQL не всегда быстрее SQL.** Выбор зависит от модели данных, запросов, нагрузки, индексов и требований к согласованности.
3. **Wide-column и аналитическое column-oriented хранение — разные подходы.** Cassandra и HBase нельзя автоматически считать аналогами ClickHouse.
4. **Получение объекта `MongoDatabase` или `MongoCollection` не создаёт их немедленно на сервере.** Создание обычно происходит при первой операции записи либо при явной команде создания.
5. **Зависимости и команды из презентации могут устареть.** Для новых проектов выбирай поддерживаемую версию драйвера и актуальную MongoDB Shell (`mongosh` вместо старого `mongo`).
