# Тема 1: Основы баз данных, DDL и DML

> Примеры приведены для **PostgreSQL**. Основа — презентация «Основы работы: DDL, DML»; уточнения и практические рекомендации добавлены отдельно.

## Данные

**Определение:**

Данные — факты или сведения об объектах, событиях и процессах, которые можно хранить и обрабатывать: имя пользователя, возраст, дата заказа, изображение.

---

## База данных (БД, Database)

**Определение:**

База данных — организованная совокупность данных, предназначенная для хранения, поиска и изменения информации.

**Пример:** база интернет-магазина хранит пользователей, товары и заказы.

---

## Система управления базами данных (СУБД, DBMS)

**Определение:**

СУБД — программное обеспечение для создания баз данных, хранения, изменения, поиска и контроля доступа к данным.

**Примеры:** PostgreSQL, MySQL, Oracle Database, Microsoft SQL Server, SQLite.

**Важно:** БД — сами организованные данные, а СУБД — программа, которая ими управляет.

---

## Реляционная база данных

**Определение:**

Реляционная база данных — база данных, основанная на реляционной модели: данные представлены в виде отношений, которые в SQL обычно реализованы таблицами.

Таблица состоит из **столбцов** (полей, атрибутов) и **строк** (записей). Столбцы имеют определённые типы данных.

**Пример:**

| id | name | age |
| --- | --- | --- |
| 1 | Ivan | 23 |
| 2 | Anna | 35 |

**Уточнение:** В математической реляционной модели дубликатов строк нет, но обычная SQL-таблица может содержать повторяющиеся строки, если это не запрещено ограничениями.

---

## NoSQL

**Определение:**

NoSQL — общее название нереляционных подходов к хранению и обработке данных, которые не обязательно используют табличную реляционную модель.

**Основные виды:** ключ–значение (Redis), документоориентированные (MongoDB), ширококолоночные (Cassandra), графовые (Neo4j).

**Важно:** NoSQL не означает полного отсутствия SQL или запрета на структурированные данные.

---

## Таблица, строка и столбец

**Определение:**

- **Таблица (Table)** — структура для хранения записей одного вида.
- **Строка (Row, Record)** — одна запись, например один пользователь.
- **Столбец (Column, Attribute)** — характеристика записи с определённым типом данных, например `email VARCHAR(255)`.

**Пример:**

```sql
CREATE TABLE users (
    id BIGINT,
    name VARCHAR(100),
    age INTEGER
);
```

---

## Схема базы данных (Schema)

**Определение:**

Схема — пространство имён внутри базы данных, в котором объединяются объекты: таблицы, представления, функции и другие объекты.

В PostgreSQL таблицы разных схем могут иметь одинаковые названия.

**Пример:**

```sql
CREATE SCHEMA shop;

CREATE TABLE shop.products (
    id BIGINT PRIMARY KEY,
    name TEXT NOT NULL
);
```

Здесь `shop` — схема, `products` — таблица.

---

## SQL (Structured Query Language)

**Определение:**

SQL — декларативный язык для определения структуры данных и работы с данными в реляционных СУБД.

SQL-команды принято делить на группы, в том числе **DDL**, **DML** и **DCL**.

**Пример:**

```sql
SELECT name FROM users WHERE age >= 18;
```

---

## DDL (Data Definition Language)

**Определение:**

DDL — группа SQL-команд для создания, изменения и удаления структуры объектов базы данных.

**Основные команды:** `CREATE`, `ALTER`, `DROP`.

**Пример:**

```sql
CREATE TABLE departments (
    id BIGINT PRIMARY KEY,
    name TEXT NOT NULL
);
```

---

## DML (Data Manipulation Language)

**Определение:**

DML — группа SQL-команд для добавления, изменения и удаления данных в таблицах.

**Основные команды:** `INSERT`, `UPDATE`, `DELETE`.

**Пример:**

```sql
INSERT INTO departments (id, name)
VALUES (1, 'Development');
```

**Уточнение:** В учебных материалах `SELECT` часто включают в DML. Иногда чтение данных выделяют в отдельную группу **DQL (Data Query Language)**.

---

## DCL (Data Control Language)

**Определение:**

DCL — группа SQL-команд для управления правами доступа к объектам базы данных.

**Основные команды:** `GRANT` — выдать права, `REVOKE` — отозвать права.

**Пример:**

```sql
GRANT SELECT ON TABLE departments TO analyst;
```

Пользователь или роль `analyst` должны существовать.

---

## CREATE TABLE

**Определение:**

`CREATE TABLE` — DDL-команда для создания таблицы с заданными столбцами, типами данных и ограничениями.

**Пример:**

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE,
    age INTEGER CHECK (age >= 0),
    is_active BOOLEAN DEFAULT TRUE
);
```

---

## Ограничение целостности (Constraint)

**Определение:**

Constraint — правило, которое СУБД проверяет при записи или изменении данных, чтобы не допускать некорректные значения и связи.

**Основные ограничения:**

- `PRIMARY KEY` — уникальный идентификатор строки, не допускает `NULL`.
- `FOREIGN KEY` — контроль ссылочной целостности между таблицами.
- `UNIQUE` — запрет повторяющихся значений или сочетаний значений (с особенностями обработки `NULL`).
- `NOT NULL` — запрет отсутствующего значения.
- `CHECK` — проверка заданного условия.

**Важно:** `DEFAULT` задаёт значение по умолчанию, а `INDEX` ускоряет определённые запросы. В PostgreSQL они **не являются ограничениями целостности**, несмотря на то что в презентации перечислены вместе с constraints.

---

## Первичный ключ (PRIMARY KEY)

**Определение:**

Первичный ключ — столбец или набор столбцов, однозначно идентифицирующий строку таблицы. Значения первичного ключа должны быть уникальными и не могут быть `NULL`.

**Пример:**

```sql
CREATE TABLE categories (
    id BIGINT PRIMARY KEY,
    name TEXT NOT NULL
);
```

---

## Составной ключ (Composite Key)

**Определение:**

Составной ключ — ключ, состоящий из двух или более столбцов. Уникальность проверяется для их **комбинации**, а не обязательно для каждого по отдельности.

**Пример:**

```sql
CREATE TABLE enrollments (
    student_id BIGINT NOT NULL,
    course_id BIGINT NOT NULL,
    PRIMARY KEY (student_id, course_id)
);
```

---

## Внешний ключ (FOREIGN KEY)

**Определение:**

Внешний ключ — ограничение, которое требует, чтобы значение столбца (или комбинации столбцов) соответствовало существующему значению в ключе связанной таблицы, если не допускается или не используется `NULL`.

В PostgreSQL внешний ключ может ссылаться на первичный ключ либо на подходящий уникальный ключ.

**Пример:**

```sql
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**Важно:** Для выполнения примера таблица `users` должна существовать, а `users.id` должен быть подходящим ключом.

---

## NULL и NOT NULL

**Определение:**

`NULL` — специальное обозначение отсутствующего или неизвестного значения в SQL. Оно не равно `0` или пустой строке.

`NOT NULL` — ограничение, запрещающее `NULL` в столбце.

**Пример:**

```sql
CREATE TABLE contacts (
    id BIGINT PRIMARY KEY,
    phone TEXT NOT NULL,
    middle_name TEXT
);

SELECT * FROM contacts WHERE middle_name IS NULL;
```

Для проверки используется `IS NULL`, а не `= NULL`.

---

## DEFAULT

**Определение:**

`DEFAULT` — значение по умолчанию, которое СУБД подставляет при вставке строки, если для соответствующего столбца не указано значение (или явно указано `DEFAULT`).

**Пример:**

```sql
CREATE TABLE tasks (
    id BIGINT PRIMARY KEY,
    status TEXT DEFAULT 'NEW'
);

INSERT INTO tasks (id) VALUES (1);
-- Для новой строки status будет 'NEW'.
```

---

## ALTER TABLE

**Определение:**

`ALTER TABLE` — DDL-команда для изменения структуры существующей таблицы: добавления или удаления столбцов, изменения их типов и ограничений.

**Пример (PostgreSQL):**

```sql
ALTER TABLE users ADD COLUMN phone TEXT;

ALTER TABLE users ALTER COLUMN phone SET NOT NULL;

ALTER TABLE users DROP COLUMN phone;
```

**Важно:** Второй запрос сработает, только если в существующих строках нет `NULL` в `phone` (или таблица пуста). В PostgreSQL для изменения типа используется `ALTER COLUMN ... TYPE`, а не `MODIFY COLUMN` из некоторых других СУБД.

---

## DROP TABLE

**Определение:**

`DROP TABLE` — DDL-команда, удаляющая таблицу как объект базы данных вместе с её данными.

**Пример:**

```sql
DROP TABLE IF EXISTS tasks;
```

**Важно:** `DELETE` удаляет строки, а `DROP TABLE` — саму таблицу. Удалению могут препятствовать зависимости других объектов.

---

## CREATE SCHEMA

**Определение:**

`CREATE SCHEMA` — DDL-команда для создания схемы в базе данных.

**Пример:**

```sql
CREATE SCHEMA IF NOT EXISTS academy;
```

---

## INSERT INTO

**Определение:**

`INSERT INTO` — команда добавления одной или нескольких строк в таблицу.

**Пример:**

```sql
INSERT INTO users (id, name, email, age)
VALUES
    (1, 'Ivan', 'ivan@example.com', 23),
    (2, 'Anna', 'anna@example.com', 35);
```

**Практика:** Явно перечисляй столбцы: такой запрос меньше зависит от порядка полей в таблице.

---

## UPDATE

**Определение:**

`UPDATE` — команда изменения значений в существующих строках таблицы.

**Пример:**

```sql
UPDATE users
SET age = 24
WHERE id = 1;
```

**Важно:** Без `WHERE` обновятся **все строки** таблицы.

---

## DELETE FROM

**Определение:**

`DELETE FROM` — команда удаления строк из таблицы без удаления самой таблицы.

**Пример:**

```sql
DELETE FROM users
WHERE id = 2;
```

**Важно:** Без `WHERE` удаляются **все строки** таблицы (если операция не нарушает ограничения и успешно завершена).

---

## SELECT

**Определение:**

`SELECT` — SQL-команда для получения данных из одной или нескольких таблиц либо из других источников данных.

**Пример:**

```sql
SELECT id, name FROM users;

SELECT * FROM users;
```

**Практика:** В прикладных запросах обычно лучше перечислять нужные столбцы, чем постоянно использовать `SELECT *`.

---

## WHERE

**Определение:**

`WHERE` — условие отбора строк для `SELECT`, `UPDATE` и `DELETE`.

Для объединения условий используются `AND` (И), `OR` (ИЛИ), `NOT` (НЕ).

**Пример:**

```sql
SELECT id, name
FROM users
WHERE age >= 18 AND (name = 'Ivan' OR name = 'Anna');
```

**Важно:** `AND` имеет больший приоритет, чем `OR`; скобки делают логику очевидной.

---

## DISTINCT

**Определение:**

`DISTINCT` — ключевое слово `SELECT`, удаляющее повторяющиеся строки **из результата запроса** с учётом всех выбранных столбцов.

**Пример:**

```sql
SELECT DISTINCT age FROM users;
```

Оригинальные данные таблицы при этом не изменяются.

---

## ORDER BY

**Определение:**

`ORDER BY` — часть SQL-запроса, задающая порядок сортировки результата. `ASC` — по возрастанию (по умолчанию), `DESC` — по убыванию.

**Пример:**

```sql
SELECT id, name, age
FROM users
ORDER BY age DESC, name ASC;
```

**Важно:** Без `ORDER BY` порядок строк результата **не гарантируется**.
