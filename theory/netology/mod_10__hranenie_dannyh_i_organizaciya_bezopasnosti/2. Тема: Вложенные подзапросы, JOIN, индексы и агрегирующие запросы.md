# Тема: Вложенные подзапросы, JOIN, индексы и агрегирующие запросы

> Основа — презентация «Вложенные подзапросы, JOIN'ы, агрегирующие запросы». Примеры адаптированы для **PostgreSQL**. Новые нюансы и практические рекомендации помечены как **Уточнение** или **В продакшене**. Термины предыдущего глоссария (SQL, SELECT, WHERE, DDL, DML, ключи и т. д.) здесь повторно не определяются.

## Вложенный запрос (Subquery)

**Определение:**

Вложенный запрос (подзапрос) — SQL-запрос, находящийся внутри другого SQL-запроса. Его результат используется внешним запросом.

**Пример:** получить сотрудников с зарплатой выше средней.

```sql
SELECT name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

**Уточнение:** презентация описывает выполнение «снизу вверх» — это удобная логическая модель для простых подзапросов. В реальности PostgreSQL может перестроить план выполнения, а коррелированные подзапросы могут зависеть от строк внешнего запроса.

---

## Скалярный подзапрос (Scalar Subquery)

**Определение:**

Подзапрос, который возвращает **одно значение** — одну строку и один столбец. Его можно использовать там, где ожидается одиночное выражение.

**Пример:**

```sql
SELECT name
FROM employees
WHERE salary = (
    SELECT MAX(salary)
    FROM employees
);
```

**Важно:** если скалярный подзапрос вернёт больше одной строки, PostgreSQL выдаст ошибку; если ни одной — результатом будет `NULL`.

---

## Коррелированный подзапрос (Correlated Subquery)

**Определение:**

Подзапрос, который использует значения из внешнего запроса и поэтому логически зависит от рассматриваемой строки внешней таблицы.

**Пример:** найти сотрудников, зарплата которых выше средней по их отделу.

```sql
SELECT e.name, e.salary, e.department_id
FROM employees AS e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM employees AS e2
    WHERE e2.department_id = e.department_id
);
```

**Уточнение:** это дополнительный термин, расширяющий тему презентации.

---

## IN и EXISTS в подзапросах

**Определение:**

`IN` проверяет, входит ли значение в набор результатов подзапроса. `EXISTS` проверяет, возвращает ли подзапрос хотя бы одну строку.

**Пример (`IN`):** найти сотрудников отделов с названием `IT`.

```sql
SELECT name
FROM employees
WHERE department_id IN (
    SELECT id
    FROM departments
    WHERE name = 'IT'
);
```

**Пример (`EXISTS`):** найти отделы, в которых есть сотрудники.

```sql
SELECT d.name
FROM departments AS d
WHERE EXISTS (
    SELECT 1
    FROM employees AS e
    WHERE e.department_id = d.id
);
```

**Уточнение:** это дополнительные распространённые конструкции. `EXISTS` проверяет наличие строк, а не значение `SELECT 1`.

---

## JOIN (соединение таблиц)

**Определение:**

`JOIN` — операция SQL для формирования результата из строк двух таблиц на основании условия соединения. Часто используется для связи данных по внешнему и первичному ключу.

**Пример:**

```sql
SELECT e.name, o.office_name
FROM employees AS e
JOIN offices AS o ON e.office_id = o.id;
```

`ON` задаёт условие соответствия строк, а `AS e` и `AS o` — псевдонимы таблиц.

**Важно:** совпадений может быть несколько, поэтому `JOIN` способен увеличить число строк результата.

---

## INNER JOIN (внутреннее соединение)

**Определение:**

Возвращает только пары строк, для которых выполняется условие соединения.

**Пример:** показать сотрудников, для которых найден кабинет.

```sql
SELECT e.name, o.office_name
FROM employees AS e
INNER JOIN offices AS o ON e.office_id = o.id;
```

`INNER JOIN` и просто `JOIN` в этом случае равнозначны.

---

## LEFT JOIN (левое внешнее соединение)

**Определение:**

Возвращает **все строки левой таблицы** и подходящие строки правой. Если соответствия нет, столбцы правой таблицы заполняются `NULL`.

**Пример:** показать всех сотрудников, включая удалённых без закреплённого кабинета.

```sql
SELECT e.name, o.office_name
FROM employees AS e
LEFT JOIN offices AS o ON e.office_id = o.id;
```

---

## RIGHT JOIN (правое внешнее соединение)

**Определение:**

Возвращает **все строки правой таблицы** и подходящие строки левой. Если соответствия нет, столбцы левой таблицы будут `NULL`.

**Пример:** показать все кабинеты, даже пустые.

```sql
SELECT e.name, o.office_name
FROM employees AS e
RIGHT JOIN offices AS o ON e.office_id = o.id;
```

**В продакшене:** часто предпочитают эквивалентный `LEFT JOIN` с переставленными таблицами ради удобства чтения.

---

## FULL OUTER JOIN (полное внешнее соединение)

**Определение:**

Возвращает все строки обеих таблиц: совпадающие объединяет, несовпадающие дополняет `NULL` с отсутствующей стороны.

**Пример:** показать всех сотрудников и все кабинеты, включая удалённых сотрудников и пустые кабинеты.

```sql
SELECT e.name, o.office_name
FROM employees AS e
FULL OUTER JOIN offices AS o ON e.office_id = o.id;
```

`FULL JOIN` — сокращённая запись.

---

## CROSS JOIN (декартово произведение)

**Определение:**

Соединение, при котором **каждая строка** первой таблицы комбинируется с **каждой строкой** второй.

**Пример:**

```sql
SELECT s.first_name, c.course_name
FROM students AS s
CROSS JOIN course_catalog AS c;
```

Если в `students` 10 строк, а в `course_catalog` 5, результат содержит **50 строк**.

**В продакшене:** неосторожное декартово произведение может дать огромный результат.

---

## Anti Join (поиск строк без соответствий)

**Определение:**

Шаблон запроса для получения строк одной таблицы, у которых **нет подходящих строк** в другой. В презентации показан как `LEFT/RIGHT JOIN` с фильтрацией по отсутствующему совпадению.

**Пример:** найти сотрудников без найденного кабинета.

```sql
SELECT e.name
FROM employees AS e
LEFT JOIN offices AS o ON e.office_id = o.id
WHERE o.id IS NULL;
```

**Уточнение:** `ANTI JOIN` не является обычным самостоятельным ключевым словом PostgreSQL SQL; ту же задачу часто решают с `NOT EXISTS`.

---

## ON и фильтрация при внешнем JOIN

**Определение:**

`ON` определяет, какие строки считаются совпадающими при соединении. `WHERE` фильтрует уже сформированный результат.

**Пример:** выбрать всех сотрудников, но присоединить только кабинеты с `id > 10`.

```sql
SELECT e.name, o.office_name
FROM employees AS e
LEFT JOIN offices AS o
    ON e.office_id = o.id AND o.id > 10;
```

**Важно:** если перенести `o.id > 10` из `ON` в `WHERE`, строки сотрудников без подходящего кабинета будут отфильтрованы. Это частая ошибка при `LEFT JOIN`.

**Уточнение:** дополнительный нюанс для практической работы.

---

## Агрегатная функция (Aggregate Function)

**Определение:**

Функция, вычисляющая **одно результирующее значение** по набору строк. Может работать по всей выборке или отдельно внутри каждой группы.

**Пример:**

```sql
SELECT AVG(salary) AS average_salary
FROM employees;
```

Основные функции из презентации: `COUNT()`, `SUM()`, `AVG()`, `MIN()`, `MAX()`.

---

## COUNT()

**Определение:**

Агрегатная функция для подсчёта количества строк или непустых (`NOT NULL`) значений.

**Пример:**

```sql
SELECT
    COUNT(*) AS all_rows,
    COUNT(office_id) AS rows_with_office
FROM employees;
```

`COUNT(*)` считает **все строки**, а `COUNT(office_id)` — только строки, где `office_id IS NOT NULL`.

---

## SUM()

**Определение:**

Агрегатная функция, вычисляющая сумму числовых значений.

**Пример:**

```sql
SELECT SUM(salary) AS total_salary
FROM employees;
```

`NULL`-значения не участвуют в сумме. При отсутствии подходящих значений `SUM()` возвращает `NULL`, а не `0`.

---

## AVG()

**Определение:**

Агрегатная функция, вычисляющая среднее арифметическое числовых значений.

**Пример:**

```sql
SELECT department_id, AVG(salary) AS average_salary
FROM employees
GROUP BY department_id;
```

`NULL`-значения не учитываются при вычислении среднего.

---

## MIN() и MAX()

**Определение:**

Агрегатные функции для поиска соответственно минимального и максимального значения среди подходящих строк.

**Пример:**

```sql
SELECT
    MIN(salary) AS min_salary,
    MAX(salary) AS max_salary
FROM employees;
```

---

## GROUP BY (группировка)

**Определение:**

Часть SQL-запроса, которая объединяет строки с одинаковыми значениями указанных выражений в группы. Обычно используется с агрегатными функциями.

**Пример:** посчитать сотрудников по отделам.

```sql
SELECT department_id, COUNT(*) AS employee_count
FROM employees
GROUP BY department_id;
```

**Важно:** при использовании `GROUP BY` обычные столбцы в `SELECT` должны быть включены в группировку или допустимы по правилам функциональной зависимости PostgreSQL; остальные значения обычно вычисляют агрегатными функциями.

---

## HAVING (фильтрация групп)

**Определение:**

Часть SQL-запроса, которая фильтрует группы **после группировки**. Обычно используется с агрегатными функциями.

**Пример:** найти отделы, где больше пяти сотрудников.

```sql
SELECT department_id, COUNT(*) AS employee_count
FROM employees
GROUP BY department_id
HAVING COUNT(*) > 5;
```

**Разница:** `WHERE` фильтрует отдельные строки **до** группировки; `HAVING` — группы **после** неё.

---

## Индекс (Database Index)

**Определение:**

Дополнительная структура данных, которая помогает СУБД быстрее находить строки по определённым столбцам; некоторые индексы также помогают сортировке и поддержанию уникальности.

**Пример:** создать индекс по зарплате.

```sql
CREATE INDEX idx_employees_salary
ON employees (salary);
```

**В продакшене:** индекс занимает место и требует обновления при изменении данных. Больше индексов **не всегда** означает быстрее: оптимизатор может предпочесть полное чтение таблицы.

---

## Составной индекс (Composite Index)

**Определение:**

Индекс, созданный по нескольким столбцам. Применяется, когда запросы часто используют эти столбцы совместно.

**Пример:**

```sql
CREATE INDEX idx_employees_department_salary
ON employees (department_id, salary);
```

**Уточнение:** это дополнительный термин. Порядок столбцов индекса важен: индекс `(department_id, salary)` не всегда заменяет индекс по одному `salary`.

---

## CREATE INDEX и DROP INDEX

**Определение:**

Команды для создания и удаления индексов в базе данных.

**Пример:**

```sql
CREATE INDEX idx_employees_department
ON employees (department_id);

DROP INDEX idx_employees_department;
```

**Уточнение:** `PRIMARY KEY` и `UNIQUE` в PostgreSQL автоматически создают уникальный индекс для обеспечения ограничения. Индекс на внешний ключ автоматически **не создаётся**.

---

## EXPLAIN (план выполнения запроса)

**Определение:**

Команда PostgreSQL, показывающая план, который СУБД предполагает использовать для выполнения SQL-запроса: чтение таблицы, работу с индексами, соединения и другие операции.

**Пример:**

```sql
EXPLAIN
SELECT *
FROM employees
WHERE salary > 50000;
```

Для измерения фактического выполнения используется `EXPLAIN ANALYZE`:

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT *
FROM employees
WHERE salary > 50000;
```

**Важно:** `EXPLAIN ANALYZE` действительно **выполняет** запрос. Не применяй его бездумно к `UPDATE`, `DELETE` и другим изменяющим данным операциям.

---

## Seq Scan и Index Scan

**Определение:**

`Seq Scan` — последовательное чтение строк таблицы. `Index Scan` — поиск строк через индекс (с возможным обращением к самой таблице).

**Пример:**

```sql
EXPLAIN SELECT * FROM employees WHERE salary > 50000;
```

В плане PostgreSQL можно увидеть `Seq Scan`, `Index Scan`, `Bitmap Index Scan` и другие способы доступа.

**Уточнение:** в презентации после создания индекса ожидается ускорение. На практике это **не гарантируется**: выбор зависит от размера таблицы, доли подходящих строк и статистики планировщика.
