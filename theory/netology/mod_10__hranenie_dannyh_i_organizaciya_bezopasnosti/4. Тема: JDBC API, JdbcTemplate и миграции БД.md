# Тема 4: JDBC API, Spring JDBC, транзакции и миграции

> Основано на презентации «JDBC API, JdbcTemplate, NamedParametersJdbcTemplate». Примеры ориентированы на PostgreSQL и Spring Boot. Дополнения и уточнения к материалу отмечены отдельно.

## JDBC API (Java Database Connectivity)

**Определение:**

JDBC — стандартный API Java для взаимодействия с базами данных через JDBC-драйверы: подключения, выполнения SQL-запросов и получения результатов.

JDBC предоставляет интерфейсы из пакетов `java.sql` и `javax.sql`. Реализация конкретного протокола зависит от драйвера СУБД.

**Пример:**

```java
try (Connection connection = DriverManager.getConnection(
        "jdbc:postgresql://localhost:5432/app_db", "app", "password")) {
    System.out.println(connection.isValid(2));
}
```

---

## JDBC-драйвер (JDBC Driver)

**Определение:**

Библиотека, реализующая JDBC-интерфейсы и обеспечивающая обмен данными между Java-приложением и конкретной СУБД.

Например, для PostgreSQL используется PostgreSQL JDBC Driver (pgJDBC).

---

## JDBC URL

**Определение:**

Строка адреса подключения, которая указывает JDBC-драйверу, к какому серверу и базе данных подключаться.

**Пример:**

```text
jdbc:postgresql://localhost:5432/app_db
```

Здесь `postgresql` — тип драйвера, `localhost` — хост, `5432` — порт, `app_db` — имя базы.

---

## DriverManager

**Определение:**

Класс JDBC, который выбирает подходящий зарегистрированный драйвер и позволяет получить соединение через `getConnection()`.

**Пример:**

```java
Connection connection = DriverManager.getConnection(url, username, password);
```

**В продакшене:** обычно вместо создания нового подключения на каждый запрос применяют `DataSource` с пулом соединений.

---

## Connection

**Определение:**

Интерфейс, представляющий сеанс соединения приложения с базой данных. Позволяет создавать SQL-команды, управлять транзакциями и закрывать соединение.

**Пример:**

```java
try (Connection connection = dataSource.getConnection()) {
    // Работа с БД
}
```

---

## Statement

**Определение:**

Интерфейс JDBC для выполнения SQL-команд, сформированных без привязки параметров.

**Пример:**

```java
try (Statement statement = connection.createStatement();
     ResultSet resultSet = statement.executeQuery("SELECT id, name FROM users")) {
    while (resultSet.next()) {
        System.out.println(resultSet.getString("name"));
    }
}
```

**Важно:** пользовательские значения не следует конкатенировать с SQL-текстом — это создаёт риск SQL-инъекций.

---

## PreparedStatement

**Определение:**

Интерфейс JDBC для выполнения параметризованных SQL-запросов. Вместо включения значений непосредственно в строку SQL используются плейсхолдеры `?`.

**Пример:**

```java
String sql = "SELECT id, name FROM users WHERE id = ?";
try (PreparedStatement statement = connection.prepareStatement(sql)) {
    statement.setLong(1, 42L);
    try (ResultSet resultSet = statement.executeQuery()) {
        while (resultSet.next()) {
            System.out.println(resultSet.getString("name"));
        }
    }
}
```

**В продакшене:** параметризация отделяет данные от SQL-кода и защищает от SQL-инъекций при корректном использовании.

---

## CallableStatement

**Определение:**

Интерфейс JDBC для вызова хранимых процедур базы данных с поддержкой входных и выходных параметров.

**Пример:**

```java
try (CallableStatement statement = connection.prepareCall("{call refresh_statistics()}");) {
    statement.execute();
}
```

Пример предполагает, что процедура `refresh_statistics()` создана в БД.

---

## ResultSet

**Определение:**

Интерфейс JDBC для чтения табличного результата запроса. Обычно курсор первоначально расположен перед первой строкой; метод `next()` перемещает его дальше.

**Пример:**

```java
while (resultSet.next()) {
    long id = resultSet.getLong("id");
    String name = resultSet.getString("name");
}
```

**Нюанс:** не каждый `ResultSet` поддерживает перемещение назад или изменение строк — это зависит от его типа и настроек.

---

## executeQuery(), executeUpdate(), execute() и executeBatch()

**Определение:**

Основные методы выполнения JDBC-команд:

- `executeQuery()` — возвращает `ResultSet`, обычно для `SELECT`;
- `executeUpdate()` — возвращает число затронутых строк (или `0` для некоторых DDL-команд);
- `execute()` — позволяет выполнять SQL с разными видами результата;
- `executeBatch()` — выполняет набор ранее добавленных команд пакетно.

**Пример:**

```java
int changedRows = statement.executeUpdate(
        "UPDATE users SET active = false WHERE id = 42");
```

---

## Try-with-resources

**Определение:**

Конструкция Java, автоматически вызывающая `close()` у ресурсов, реализующих `AutoCloseable`, в том числе `Connection`, `Statement` и `ResultSet`.

**Пример:**

```java
try (Connection connection = dataSource.getConnection();
     PreparedStatement statement = connection.prepareStatement("SELECT 1");
     ResultSet rs = statement.executeQuery()) {
    if (rs.next()) {
        System.out.println(rs.getInt(1));
    }
}
```

**Уточнение к презентации:** закрытие `Statement` не заменяет явного закрытия `Connection`. Ресурсами нужно управлять корректно.

---

## DataSource

**Определение:**

Интерфейс `javax.sql.DataSource` — источник JDBC-соединений, который абстрагирует их получение и настройку. Может использовать пул соединений или выдавать новые соединения.

**Пример:**

```java
Connection connection = dataSource.getConnection();
```

**В продакшене:** Spring Boot обычно управляет `DataSource` как компонентом приложения.

---

## Пул соединений (Connection Pool)

**Определение:**

Механизм повторного использования заранее созданных соединений с базой данных, чтобы не устанавливать сетевое подключение для каждого запроса.

После `close()` соединение из обычного пула, как правило, возвращается в пул, а не уничтожается физически.

**Пример:**

```properties
spring.datasource.hikari.maximum-pool-size=10
```

**В продакшене:** слишком большой пул также вреден: соединения потребляют ресурсы СУБД.

---

## HikariCP и HikariDataSource

**Определение:**

HikariCP — библиотека для организации JDBC-пула соединений. `HikariDataSource` — её реализация `DataSource`.

Spring Boot часто выбирает HikariCP автоматически при наличии соответствующих зависимостей.

---

## Транзакция (Transaction)

**Определение:**

Логическая единица работы с БД, объединяющая несколько операций, которые должны выполняться согласованно: при успехе изменения фиксируются, при ошибке могут быть отменены.

**Пример:** перевод средств между счетами должен включать списание и зачисление в рамках одной транзакции.

---

## ACID

**Определение:**

Набор ключевых свойств транзакций:

- **Atomicity (атомарность)** — транзакция применяется целиком или не применяется вовсе;
- **Consistency (согласованность)** — транзакция должна сохранять установленные ограничения целостности БД;
- **Isolation (изолированность)** — параллельные транзакции взаимодействуют согласно выбранному уровню изоляции;
- **Durability (долговечность)** — зафиксированные изменения сохраняются при сбоях в пределах гарантий СУБД.

**Уточнение к презентации:** согласованность не тождественна откату, а изоляция не означает обязательную полную блокировку всех участвующих объектов.

---

## Auto-commit

**Определение:**

Режим JDBC, при котором каждое SQL-выражение выполняется как отдельная транзакция и автоматически фиксируется после завершения согласно JDBC-семантике.

По умолчанию новое JDBC-соединение обычно находится в режиме `autoCommit = true`.

**Пример:**

```java
connection.setAutoCommit(false); // ручное управление транзакцией
```

---

## COMMIT и ROLLBACK

**Определение:**

`COMMIT` фиксирует изменения транзакции, а `ROLLBACK` отменяет незавершённые изменения.

**Пример:**

```java
connection.setAutoCommit(false);
try {
    // Выполнение нескольких SQL-операций
    connection.commit();
} catch (SQLException e) {
    connection.rollback();
    throw e;
}
```

В реальном приложении необходимо также корректно управлять жизненным циклом соединения и состоянием `autoCommit`.

---

## Spring JDBC

**Определение:**

Модуль Spring, упрощающий работу с реляционными базами данных через JDBC. Берёт на себя типовые операции с соединениями, ресурсами, результатами и исключениями.

В отличие от ORM, Spring JDBC не скрывает SQL-запросы от разработчика.

---

## Автоконфигурация DataSource и JdbcTemplate

**Определение:**

Механизм Spring Boot, создающий и настраивающий компоненты работы с БД на основании зависимостей, конфигурации и уже существующих бинов.

Основные классы автоконфигурации: `DataSourceAutoConfiguration` и `JdbcTemplateAutoConfiguration`.

**Пример (`application.properties`):**

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/app_db
spring.datasource.username=app
spring.datasource.password=${DB_PASSWORD}
```

**В продакшене:** пароль не следует записывать непосредственно в Git-репозиторий.

---

## JdbcTemplate

**Определение:**

Центральный класс Spring JDBC, который выполняет SQL-запросы, управляет JDBC-ресурсами и преобразует `SQLException` в иерархию исключений Spring `DataAccessException`.

**Пример:**

```java
int updated = jdbcTemplate.update(
        "UPDATE users SET active = ? WHERE id = ?", true, 42L);
```

**В продакшене:** сокращает шаблонный JDBC-код; SQL и его производительность остаются ответственностью разработчика.

---

## RowMapper<T>

**Определение (дополнение):**

Функциональный интерфейс Spring JDBC для преобразования одной строки `ResultSet` в Java-объект.

**Пример:**

```java
record User(long id, String name) {}

List<User> users = jdbcTemplate.query(
        "SELECT id, name FROM users",
        (rs, rowNum) -> new User(rs.getLong("id"), rs.getString("name"))
);
```

---

## NamedParameterJdbcTemplate

**Определение:**

Класс Spring JDBC, позволяющий использовать в SQL именованные параметры (`:id`, `:name`) вместо позиционных `?`. Внутри делегирует выполнение JDBC-операций.

**Пример:**

```java
String sql = "SELECT name FROM users WHERE id = :id";
List<String> names = namedParameterJdbcTemplate.queryForList(
        sql, Map.of("id", 42L), String.class);
```

**Преимущество:** запросы с большим числом параметров легче читать и сопровождать.

---

## SQL-инициализация: schema.sql и data.sql

**Определение:**

Механизм Spring Boot для запуска SQL-скриптов создания структуры (`schema.sql`) и начального наполнения (`data.sql`) при инициализации приложения.

**Пример:**

```properties
spring.sql.init.mode=always
```

**Уточнение к презентации:** для внешних БД автоматический запуск этих скриптов зависит от настроек; не следует считать, что они всегда выполняются без дополнительной конфигурации. Для эволюции схемы обычно применяют миграции.

---

## Fail-fast при инициализации БД

**Определение:**

Поведение, при котором ошибка SQL-инициализации приводит к прекращению запуска приложения, чтобы оно не работало с некорректной схемой.

**Пример:**

```properties
spring.sql.init.continue-on-error=false
```

**Уточнение к презентации:** современное имя свойства — `spring.sql.init.continue-on-error`, а не `spring.datasource.continue-on-error`.

---

## @Transactional

**Определение:**

Аннотация Spring для декларативного управления транзакцией метода или класса через настроенный менеджер транзакций.

**Пример:**

```java
@Service
public class TransferService {
    private final JdbcTemplate jdbcTemplate;

    public TransferService(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }

    @Transactional
    public void transfer(long fromId, long toId, BigDecimal amount) {
        jdbcTemplate.update(
                "UPDATE accounts SET balance = balance - ? WHERE id = ?", amount, fromId);
        jdbcTemplate.update(
                "UPDATE accounts SET balance = balance + ? WHERE id = ?", amount, toId);
    }
}
```

**Важно:** это демонстрация общей транзакции, а не готовая безопасная реализация денежных переводов. Нужны проверки баланса, результата `UPDATE`, конкурентного доступа и бизнес-инвариантов.

**Уточнение:** по умолчанию откат выполняется для `RuntimeException` и `Error`; внутренний вызов `this.method()` в типичной proxy-конфигурации Spring не активирует транзакционный перехватчик.

---

## Миграция базы данных (Database Migration)

**Определение:**

Версионируемое изменение структуры или данных БД, применяемое управляемым инструментом, чтобы окружения получали согласованный набор изменений.

Миграции часто включают DDL и DML-команды. Выполненные изменения фиксируются в служебной истории инструмента.

---

## Flyway

**Определение:**

Инструмент миграций, который применяет SQL- или Java-миграции и отслеживает их состояние и контрольные суммы.

**Примеры файлов:**

```text
src/main/resources/db/migration/
  V1__create_users.sql
  V2__add_email_to_users.sql
  R__refresh_view.sql
```

- `V` — versioned migration: выполняется один раз на данную версию;
- `R` — repeatable migration: выполняется при первом обнаружении и повторно при изменении содержимого (контрольной суммы).

**Уточнение к презентации:** стандартная папка — `db/migration` (в единственном числе), а не `db/migrations`.

---

## Версионная миграция (Versioned Migration)

**Определение:**

Миграция с уникальной версией, которую Flyway применяет в установленном порядке и помечает выполненной.

**Пример (`V2__add_email_to_users.sql`):**

```sql
ALTER TABLE users ADD COLUMN email VARCHAR(255);
```

**В продакшене:** уже применённые миграции обычно не редактируют — создают новую версию.

---

## Повторяемая миграция (Repeatable Migration)

**Определение:**

Миграция Flyway без номера версии, которая повторно применяется при изменении контрольной суммы.

**Пример имени:** `R__recreate_reporting_view.sql`.

Подходит для обновления представлений и других объектов, определение которых нужно переустанавливать целиком.

---

## Liquibase

**Определение:**

Инструмент управления изменениями БД, поддерживающий миграции в SQL, XML, YAML и JSON, хранение истории изменений и механизмы отката.

**Пример конфигурации Spring Boot:**

```properties
spring.liquibase.change-log=classpath:/db/changelog/db.changelog-master.yaml
```

**Уточнение:** возможность автоматического отката зависит от типа изменения и описания rollback; не каждую миграцию можно безопасно обратить автоматически.

---

## ChangeSet (Liquibase)

**Определение (дополнение):**

Единица изменения в Liquibase, идентифицируемая сочетанием идентификатора, автора и пути к changelog (с учётом настроек). Содержит одну или несколько операций изменения БД.

**Пример YAML:**

```yaml
databaseChangeLog:
  - changeSet:
      id: 1
      author: developer
      changes:
        - addColumn:
            tableName: users
            columns:
              - column:
                  name: email
                  type: varchar(255)
```

---

## Контрольная сумма миграции (Checksum)

**Определение:**

Вычисляемое значение, позволяющее инструменту обнаружить изменение содержимого миграции по сравнению с сохранённой историей.

Используется для контроля целостности миграций и определения необходимости повторного выполнения repeatable-миграций.

---

## Flyway vs Liquibase

**Определение / сравнение:**

Оба инструмента управляют эволюцией схемы БД, но различаются подходом:

| Критерий | Flyway | Liquibase |
|---|---|---|
| Основной стиль | SQL-файлы с версиями | ChangeSet в SQL, XML, YAML, JSON |
| История изменений | `flyway_schema_history` | `DATABASECHANGELOG` |
| Повторное применение | Repeatable migrations | Настройки `runOnChange` / `runAlways` |
| Откат | Зависит от редакции и стратегии | Есть механизмы rollback, но не для всех случаев автоматически |

**В продакшене:** выбирают один основной инструмент для управления схемой конкретного сервиса, а миграции хранят вместе с кодом в системе контроля версий.

# Примечания к презентации

В исходных слайдах встречаются упрощения и версии настроек, которые важно не переносить в новый проект без проверки:

1. В обычном JDBC необходимо закрывать и `Connection`, а не только `Statement`.
2. `autoCommit` фиксирует отдельные SQL-выражения после их завершения по правилам JDBC; это не сводится только к вызовам `executeQuery()` и `executeUpdate()`.
3. Для Spring Boot актуальное свойство управления ошибками SQL-инициализации — `spring.sql.init.continue-on-error`.
4. Стандартный каталог Flyway — `classpath:db/migration`.
5. `@Transactional` зависит от менеджера транзакций и механизма вызова Spring; аннотация сама по себе не гарантирует транзакцию при любом вызове метода.
6. В реальных приложениях выбирайте и проверяйте версии зависимостей Flyway/Liquibase, совместимые с используемыми Spring Boot и СУБД.
