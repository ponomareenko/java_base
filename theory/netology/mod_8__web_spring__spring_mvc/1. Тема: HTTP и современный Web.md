# Тема 1: HTTP и современный Web

## Web

**Определение:**

Web (World Wide Web) — система связанных между собой веб-страниц и ресурсов, доступных через Интернет.

Основные технологии Web:

* HTTP — передача данных между клиентом и сервером;
* URL — адрес ресурса;
* HTML — структура веб-документа;
* CSS — оформление;
* JavaScript — поведение страницы.

---

## Клиент-серверная модель

**Определение:**

Клиент-серверная модель — архитектура, в которой **клиент отправляет запрос**, а **сервер принимает его, обрабатывает и возвращает ответ**.

Типичный пример:

```text
Браузер → HTTP-запрос → Java Backend
Браузер ← HTTP-ответ  ← Java Backend
```

Клиентом может быть не только браузер, но и:

* мобильное приложение;
* другое backend-приложение;
* Postman;
* консольная программа.

---

## Клиент

**Определение:**

Клиент — программа, которая обращается к серверу и инициирует взаимодействие.

Например, браузер может запросить:

```text
GET /users HTTP/1.1
```

В этом случае браузер является клиентом.

---

## Сервер

**Определение:**

Сервер — программа, которая принимает запросы клиентов, обрабатывает их и возвращает ответы.

Слово **server** может обозначать как само серверное приложение, так и физическую или виртуальную машину, на которой оно работает.

В Java роль HTTP-сервера обычно выполняет приложение на Spring Boot.

---

## Протокол

**Определение:**

Протокол — набор правил, по которым две стороны обмениваются информацией.

Он определяет:

* формат данных;
* порядок взаимодействия;
* структуру сообщений;
* допустимые действия.

Например, HTTP определяет правила общения клиента с HTTP-сервером.

---

## HTTP

**Определение:**

HTTP (HyperText Transfer Protocol) — протокол прикладного уровня, используемый для обмена данными между клиентом и сервером.

Через HTTP можно передавать:

* HTML;
* JSON;
* XML;
* изображения;
* CSS;
* JavaScript;
* аудио;
* видео;
* другие данные.

Общая схема:

```text
Client → HTTP Request → Server
Client ← HTTP Response ← Server
```

---

## Прикладной уровень

**Определение:**

Прикладной уровень — уровень сетевого взаимодействия, на котором работают протоколы, непосредственно используемые приложениями.

Например:

```text
HTTP
 ↓
TCP
 ↓
IP
```

HTTP отвечает за правила обмена данными приложения, а нижние уровни занимаются доставкой этих данных по сети.

---

## Стек протоколов

**Определение:**

Стек протоколов — набор сетевых протоколов разных уровней, которые совместно обеспечивают передачу данных.

Упрощённый пример:

```text
HTTP
 ↓
TCP
 ↓
IP
 ↓
Network
```

Каждый уровень решает свою задачу.

---

## RFC

**Определение:**

RFC (Request for Comments) — документ, описывающий стандарты, протоколы, форматы и другие технические правила Интернета.

RFC являются одним из основных первоисточников при изучении сетевых протоколов.

Например, спецификации HTTP описывают:

* формат HTTP-сообщений;
* методы;
* заголовки;
* статус-коды;
* правила обработки запросов и ответов.

---

## Stateless

**Определение:**

Stateless — принцип, при котором каждый запрос рассматривается сервером как самостоятельный и содержит необходимую для его обработки информацию.

HTTP по своей природе является stateless-протоколом.

Упрощённо:

```text
Request 1 → Server
Request 2 → Server
```

Сам HTTP не требует, чтобы сервер автоматически «помнил» первый запрос при обработке второго.

Состояние пользователя при необходимости реализуется дополнительными механизмами: например, cookies, sessions или tokens.

---

## HTTP-сообщение

**Определение:**

HTTP-сообщение — единица передачи информации в HTTP.

Существует два основных вида HTTP-сообщений:

```text
Request
Response
```

То есть:

```text
Client → Request → Server
Client ← Response ← Server
```

---

## HTTP Request

**Определение:**

HTTP Request — сообщение, которое клиент отправляет серверу.

Упрощённо запрос состоит из:

```text
Request Line
Headers

Body
```

Пример:

```http
POST /users HTTP/1.1
Content-Type: application/json

{
  "name": "Danil"
}
```

---

## Request Line

**Определение:**

Request Line — первая строка HTTP-запроса.

Она содержит:

```text
METHOD PATH HTTP_VERSION
```

Пример:

```http
GET /users HTTP/1.1
```

Где:

* `GET` — HTTP-метод;
* `/users` — путь к ресурсу;
* `HTTP/1.1` — версия протокола.

---

## HTTP Response

**Определение:**

HTTP Response — сообщение, которое сервер возвращает клиенту в ответ на HTTP-запрос.

Упрощённая структура:

```text
Status Line
Headers

Body
```

Пример:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "name": "Danil"
}
```

---

## Status Line

**Определение:**

Status Line — первая строка HTTP-ответа.

Она содержит версию HTTP, статус-код и текстовое описание результата.

Пример:

```http
HTTP/1.1 200 OK
```

---

## HTTP Header

**Определение:**

HTTP Header — дополнительная информация о запросе или ответе.

Заголовки передаются в формате:

```text
Name: Value
```

Например:

```http
Content-Type: application/json
Content-Length: 120
Authorization: Bearer token
```

Заголовки могут передавать информацию о:

* формате данных;
* авторизации;
* кэшировании;
* размере содержимого;
* поддерживаемых форматах;
* соединении.

---

## HTTP Body

**Определение:**

HTTP Body — тело HTTP-сообщения, содержащее передаваемые данные.

Например:

```json
{
  "name": "Danil",
  "age": 30
}
```

Тело есть не у каждого HTTP-запроса или ответа.

---

## CRLF

**Определение:**

CRLF — последовательность символов:

```text
\r\n
```

где:

* `\r` — Carriage Return;
* `\n` — Line Feed.

В текстовом формате HTTP/1.1 эта последовательность используется для разделения строк сообщения.

---

## HTTP Method

**Определение:**

HTTP Method — часть HTTP-запроса, определяющая назначение операции над ресурсом.

Основные методы:

* `GET` — получить данные;
* `POST` — отправить данные / создать ресурс;
* `PUT` — заменить или обновить ресурс;
* `DELETE` — удалить ресурс.

Пример:

```http
GET /users/10
```

означает запрос данных пользователя.

---

## GET

**Определение:**

GET — HTTP-метод, предназначенный для получения ресурса или данных.

Пример:

```http
GET /users/15 HTTP/1.1
```

На backend в дальнейшем это может выглядеть примерно так:

```java
@GetMapping("/users/{id}")
public User getUser(@PathVariable Long id) {
    return userService.getById(id);
}
```

---

## POST

**Определение:**

POST — HTTP-метод, обычно используемый для передачи данных серверу и создания нового ресурса.

Пример:

```http
POST /users HTTP/1.1
Content-Type: application/json

{
  "name": "Alex"
}
```

---

## PUT

**Определение:**

PUT — HTTP-метод, обычно используемый для полной замены или обновления ресурса по указанному адресу.

Пример:

```http
PUT /users/10
```

---

## DELETE

**Определение:**

DELETE — HTTP-метод, предназначенный для удаления ресурса.

Пример:

```http
DELETE /users/10
```

---

## HTTP Status Code

**Определение:**

HTTP Status Code — числовой код в HTTP-ответе, показывающий результат обработки запроса.

Основные группы:

```text
1xx — информационные ответы
2xx — успешное выполнение
3xx — перенаправление
4xx — ошибка со стороны клиента
5xx — ошибка со стороны сервера
```

Частые примеры:

```text
200 OK
201 Created
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
500 Internal Server Error
```

Для backend-разработчика правильный выбор статус-кода — часть контракта API.

---

## Content-Type

**Определение:**

`Content-Type` — HTTP-заголовок, сообщающий тип данных, находящихся в теле HTTP-сообщения.

Примеры:

```http
Content-Type: text/html
```

```http
Content-Type: application/json
```

```http
Content-Type: image/png
```

На основании `Content-Type` клиент понимает, как интерпретировать полученные данные.

---

## MIME Type

**Определение:**

MIME Type — строковое обозначение типа содержимого.

Обычно используется в `Content-Type`.

Примеры:

```text
text/html
text/plain
application/json
image/png
```

Общий формат:

```text
type/subtype
```

---

## Content Sniffing

**Определение:**

Content Sniffing — механизм, при котором браузер пытается самостоятельно определить настоящий тип содержимого по его данным.

Например, браузер может определить, что полученные байты являются PNG-изображением, даже если сервер указал неправильный `Content-Type`.

На практике сервер должен всё равно отправлять корректный `Content-Type`, а не надеяться, что браузер «сам догадается».

---

## Magic Numbers

**Определение:**

Magic Numbers — специальные последовательности байтов в начале некоторых файлов, позволяющие определить их формат.

Например, браузер может использовать первые байты файла, чтобы определить, что перед ним PNG.

Это один из механизмов, используемых при Content Sniffing.

---

## URL

**Определение:**

URL (Uniform Resource Locator) — адрес ресурса в сети.

Пример:

```text
https://example.com/users/10
```

Упрощённо:

```text
https://example.com/users/10
│       │           │
scheme  host        path
```

HTTP-сервер использует путь для определения того, какой ресурс или обработчик должен обработать запрос.

---

## Ресурс

**Определение:**

Ресурс — объект, доступный клиенту по определённому URL.

Например:

```text
/index.html
/styles.css
/app.js
/logo.png
/users/10
```

При загрузке HTML браузер может автоматически выполнять дополнительные HTTP-запросы для загрузки CSS, JavaScript, изображений и других ресурсов.

---

## HTML

**Определение:**

HTML (HyperText Markup Language) — язык разметки, описывающий структуру веб-документа.

Пример:

```html
<h1>Hello</h1>
<p>Java Developer</p>
```

HTML отвечает прежде всего за **структуру страницы**, а не за бизнес-логику backend-приложения.

---

## HTML-элемент

**Определение:**

HTML-элемент — структурная единица HTML-документа.

Пример:

```html
<div>Hello</div>
```

Здесь:

```text
<div>      — открывающий тег
Hello      — содержимое
</div>     — закрывающий тег
```

---

## HTML-атрибут

**Определение:**

HTML-атрибут — дополнительная характеристика HTML-элемента.

Пример:

```html
<div id="user" class="active">
    Danil
</div>
```

Здесь `id` и `class` являются атрибутами.

---

## DOM

**Определение:**

DOM (Document Object Model) — объектное представление HTML-документа внутри браузера.

HTML:

```html
<body>
    <h1>Hello</h1>
    <p>Java</p>
</body>
```

условно превращается в дерево:

```text
body
├── h1
│   └── Hello
└── p
    └── Java
```

JavaScript может работать с этим деревом: создавать, удалять и изменять элементы.

---

## CSS

**Определение:**

CSS (Cascading Style Sheets) — язык описания внешнего вида HTML-документа.

Например:

```css
button {
    font-size: 20px;
}
```

HTML определяет структуру, CSS — её визуальное оформление.

---

## JavaScript

**Определение:**

JavaScript — язык программирования, широко используемый для реализации клиентской логики веб-приложений.

JavaScript в браузере может:

* изменять DOM;
* реагировать на действия пользователя;
* отправлять HTTP-запросы;
* работать с Web API браузера.

---

## Web API

**Определение:**

Web API браузера — набор интерфейсов, предоставляемых браузером JavaScript-коду.

Примеры:

* DOM API;
* `fetch`;
* FileReader API;
* Media Capture API.

Например:

```javascript
fetch("/users")
```

позволяет JavaScript отправить HTTP-запрос серверу.

---

## Гиперссылка

**Определение:**

Гиперссылка — HTML-элемент, позволяющий перейти к другому URL.

Пример:

```html
<a href="/users">Users</a>
```

При переходе браузер выполняет HTTP-запрос по указанному адресу.

---

## HTML Form

**Определение:**

HTML Form — HTML-форма, предназначенная для ввода и отправки данных пользователя.

Пример:

```html
<form>
    <input name="login">
    <button type="submit">Send</button>
</form>
```

Элементы формы могут включать:

* `input`;
* `select`;
* `textarea`.

---

## Query Parameters

**Определение:**

Query Parameters — параметры, передаваемые внутри URL после символа `?`.

Пример:

```text
/users?name=Danil&age=30
```

Здесь:

```text
name=Danil
age=30
```

являются query-параметрами.

На Java/Spring это позже будет выглядеть примерно так:

```java
@GetMapping("/users")
public List<User> getUsers(
        @RequestParam String name
) {
    // ...
}
```

---

## Frontend

**Определение:**

Frontend — клиентская часть приложения, с которой непосредственно взаимодействует пользователь.

В веб-разработке frontend обычно включает:

```text
HTML
CSS
JavaScript
```

Frontend отвечает за:

* отображение данных;
* пользовательский интерфейс;
* взаимодействие с пользователем;
* отправку запросов backend-приложению.

---

## Backend

**Определение:**

Backend — серверная часть приложения.

Backend обычно отвечает за:

* бизнес-логику;
* работу с базой данных;
* авторизацию;
* обработку HTTP-запросов;
* формирование HTTP-ответов;
* предоставление API.

Для нас типичный backend:

```text
Java + Spring Boot + Database
```

---

## API

**Определение:**

API (Application Programming Interface) — интерфейс, определяющий правила взаимодействия между программами или компонентами системы.

В контексте backend-разработки API обычно определяет:

* доступные URL;
* HTTP-методы;
* формат запроса;
* формат ответа;
* статус-коды.

Например:

```text
GET /users
```

может означать:

> получить список пользователей.

Frontend и backend могут разрабатываться независимо друг от друга, если между ними заранее определён API-контракт.

---

## API-контракт

**Определение:**

API-контракт — договорённость между клиентом и сервером о том, как именно они взаимодействуют.

Например:

```text
GET /users/10
```

Ответ:

```json
{
  "id": 10,
  "name": "Danil"
}
```

Контракт определяет:

* URL;
* HTTP-метод;
* параметры;
* тело запроса;
* формат ответа;
* возможные статус-коды.

Для backend-разработчика нарушение API-контракта часто означает поломку frontend или других клиентов.

---

## JSON

**Определение:**

JSON (JavaScript Object Notation) — текстовый формат обмена структурированными данными.

Пример:

```json
{
  "id": 10,
  "name": "Danil",
  "active": true
}
```

JSON очень часто используется для обмена данными между frontend и backend.

Например:

```text
Frontend → JSON → Java Backend
Frontend ← JSON ← Java Backend
```

---

## Классическое веб-приложение

**Определение:**

Классическое веб-приложение — подход, при котором backend самостоятельно формирует готовые HTML-страницы и отправляет их браузеру.

Условно:

```text
Browser
   ↓
GET /profile
   ↓
Backend
   ↓
создание HTML
   ↓
Browser
```

В таком подходе backend занимается не только данными, но и формированием представления страницы.

---

## Современное разделение Frontend и Backend

**Определение:**

Современное веб-приложение часто разделяется на два независимых приложения:

```text
Frontend App
     ↓
   HTTP
     ↓
    API
     ↓
Backend App
```

Backend отдаёт в основном **данные**, например JSON:

```json
{
  "name": "Danil"
}
```

а frontend самостоятельно решает, как эти данные показать пользователю.

Это позволяет Java-разработчику концентрироваться на backend и API, не формируя HTML вручную.

---

## Sandbox браузера

**Определение:**

Sandbox — модель безопасности браузера, ограничивающая возможности выполняемого JavaScript-кода.

Код веб-страницы не получает полный доступ к компьютеру пользователя.

Например, JavaScript не может произвольно читать любые файлы пользователя.

Это необходимо учитывать backend-разработчику при проектировании API, потому что клиентское приложение работает внутри ограничений браузера.

---

## Developer Tools

**Определение:**

Developer Tools (DevTools) — встроенный в браузер набор инструментов для разработки и отладки веб-приложений.

Особенно важна вкладка `Network`, где можно посмотреть:

* URL запроса;
* HTTP-метод;
* Request Headers;
* Request Body;
* статус-код;
* Response Headers;
* Response Body;
* время выполнения запроса.

Для backend-разработчика Network — один из основных инструментов поиска проблем во взаимодействии frontend и backend.

---

# Что особенно важно запомнить

Для Java backend-разработчика из этой темы ключевая цепочка выглядит так:

```text
Client
   ↓
HTTP Request
   ↓
URL + Method + Headers + Body
   ↓
Java Backend
   ↓
business logic
   ↓
HTTP Response
   ↓
Status Code + Headers + Body
   ↓
Client
```

А современная архитектура обычно выглядит так:

```text
Frontend
   ↓
HTTP + JSON
   ↓
API
   ↓
Java / Spring Backend
   ↓
Database
```

Разбери HTTP-запрос по частям:

```http
POST /users HTTP/1.1
Content-Type: application/json

{
  "name": "Alex"
}
```

Определи:

1. HTTP-метод;
2. URL/path;
3. версию HTTP;
4. заголовок;
5. тело запроса.

---

## Задание 2

Разбери HTTP-ответ:

```http
HTTP/1.1 404 Not Found
Content-Type: application/json

{
  "error": "User not found"
}
```
