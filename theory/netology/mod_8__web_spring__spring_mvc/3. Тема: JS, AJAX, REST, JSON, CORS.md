# Тема 3: JS, AJAX, REST, JSON, CORS

## JavaScript Engine

**Определение:**

JavaScript Engine — механизм внутри браузера, который выполняет JavaScript-код.

По смыслу это похоже на JVM для Java:

```text
Java → JVM
JavaScript → JS Engine
```

Браузер содержит собственную реализацию JS-движка.

---

## ECMAScript

**Определение:**

ECMAScript — спецификация языка JavaScript.

JavaScript является реализацией языка, соответствующего стандарту ECMAScript.

То есть:

```text
ECMAScript = спецификация
JavaScript = язык, работающий по этой спецификации
```

---

## Web API

**Определение:**

Web API — набор объектов и интерфейсов, которые браузер предоставляет JavaScript-коду.

Например:

```text
document
console
XMLHttpRequest
FormData
```

Эти объекты создаются не самим JavaScript-кодом, а браузером.

---

## `document`

**Определение:**

`document` — объект браузера, через который JavaScript получает доступ к текущему HTML-документу.

Через него можно:

* находить элементы;
* менять их;
* создавать новые;
* подписываться на события.

Пример:

```javascript
const button = document.querySelector("button");
```

---

## Event

**Определение:**

Event — событие, происходящее в браузере.

Примеры:

```text
click
submit
input
change
load
```

Когда событие происходит, браузер может вызвать заранее зарегистрированную функцию.

---

## Event-Driven Model

**Определение:**

Event-Driven Model — событийно-ориентированная модель, при которой код выполняется в ответ на события.

Пример:

```javascript
button.addEventListener("click", () => {
    console.log("clicked");
});
```

Здесь код не выполняется постоянно.

Он выполнится только тогда, когда произойдёт событие `click`.

---

## Event Handler

**Определение:**

Event Handler — функция, которая вызывается при наступлении определённого события.

Пример:

```javascript
button.addEventListener("click", event => {
    console.log("button clicked");
});
```

Функция:

```javascript
event => {
    console.log("button clicked");
}
```

является обработчиком события.

---

## Default Behaviour

**Определение:**

Default Behaviour — стандартное поведение браузера для определённого действия.

Например:

при отправке обычной HTML-формы браузер по умолчанию:

```text
submit
   ↓
HTTP request
   ↓
загрузка новой страницы
```

JavaScript может отменить такое поведение.

---

## `preventDefault()`

**Определение:**

`preventDefault()` — метод объекта события, отменяющий стандартное поведение браузера.

Пример:

```javascript
form.addEventListener("submit", event => {
    event.preventDefault();
});
```

Теперь браузер не будет автоматически отправлять форму с перезагрузкой страницы.

Это позволяет отправить HTTP-запрос самостоятельно через JavaScript.

---

## AJAX

**Определение:**

AJAX (Asynchronous JavaScript and XML) — подход, позволяющий JavaScript отправлять HTTP-запросы и получать ответы **без полной перезагрузки страницы**.

Название историческое: XML использовать необязательно.

В современном приложении чаще передаётся JSON.

Схема:

```text
Page
 ↓
JavaScript
 ↓
HTTP Request
 ↓
Backend
 ↓
HTTP Response
 ↓
JavaScript обновляет только нужную часть страницы
```

---

## XHR

**Определение:**

XHR — сокращение от `XMLHttpRequest`.

`XMLHttpRequest` — Web API браузера для выполнения HTTP-запросов из JavaScript без перезагрузки страницы.

Пример:

```javascript
const xhr = new XMLHttpRequest();

xhr.open("GET", "/api/users");
xhr.send();
```

Несмотря на название, XHR может передавать не только XML, но и:

* JSON;
* текст;
* form data;
* бинарные данные;
* multipart.

---

## `XMLHttpRequest`

**Определение:**

`XMLHttpRequest` — объект браузера для программной отправки HTTP-запросов из JavaScript.

Базовая схема:

```javascript
const xhr = new XMLHttpRequest();

xhr.open("POST", "/api");
xhr.send(data);
```

---

## `open()`

**Определение:**

`open()` — метод `XMLHttpRequest`, задающий параметры будущего HTTP-запроса.

Пример:

```javascript
xhr.open("POST", "/api");
```

Здесь:

```text
POST → HTTP method
/api → URL
```

Сам запрос в этот момент ещё не отправляется.

---

## `send()`

**Определение:**

`send()` — метод `XMLHttpRequest`, который фактически отправляет HTTP-запрос.

Пример:

```javascript
xhr.send();
```

или:

```javascript
xhr.send(data);
```

---

## `setRequestHeader()`

**Определение:**

`setRequestHeader()` — метод XHR, позволяющий установить HTTP-заголовок запроса.

Пример:

```javascript
xhr.setRequestHeader(
    "Content-Type",
    "application/json"
);
```

---

## JSON Serialization

**Определение:**

JSON Serialization — преобразование объекта программы в JSON-строку.

В JavaScript:

```javascript
const user = {
    name: "Danil",
    age: 30
};

const json = JSON.stringify(user);
```

Результат:

```json
{
  "name": "Danil",
  "age": 30
}
```

точнее, фактически строка:

```text
{"name":"Danil","age":30}
```

---

## `JSON.stringify()`

**Определение:**

`JSON.stringify()` — JavaScript-функция, преобразующая объект в JSON-строку.

Пример:

```javascript
const data = JSON.stringify({
    key: "value"
});
```

Такую строку можно отправить backend-приложению:

```javascript
xhr.setRequestHeader(
    "Content-Type",
    "application/json"
);

xhr.send(data);
```

---

## Binary Data

**Определение:**

Binary Data — данные, представленные как последовательность байтов, а не как текст.

Примеры:

* изображения;
* видео;
* архивы;
* PDF;
* произвольные файлы.

XHR может отправлять бинарные данные напрямую.

---

## Blob

**Определение:**

Blob (Binary Large Object) — объект браузера, представляющий бинарные данные.

Пример:

```javascript
const data = new Blob(["some data"]);
```

После этого Blob можно отправить через HTTP:

```javascript
xhr.send(data);
```

---

## `FormData`

**Определение:**

`FormData` — Web API браузера для формирования данных в формате `multipart/form-data`.

Особенно удобно использовать для загрузки файлов.

Пример:

```javascript
const data = new FormData(form);
```

Затем:

```javascript
xhr.send(data);
```

Браузер сам сформирует:

```text
Content-Type: multipart/form-data; boundary=...
```

и корректно разделит части запроса.

---

## Mapping

**Определение:**

Mapping — привязка обработчика HTTP-запроса к определённому URL.

Например:

```text
/api
   ↓
HttpHandler
```

То есть запрос:

```text
GET /api
```

будет передан конкретному обработчику.

В Spring позже это будет встречаться постоянно:

```java
@GetMapping("/api")
```

---

## HTTP Handler

**Определение:**

HTTP Handler — код, который вызывается сервером для обработки входящего HTTP-запроса.

Упрощённо:

```java
public void service(
        Request request,
        Response response
) {
    // обработка запроса
}
```

Framework сам вызывает этот метод, когда приходит подходящий запрос.

---

## Grizzly

**Определение:**

Grizzly — Java HTTP-сервер/framework, позволяющий принимать и обрабатывать HTTP-запросы без написания низкоуровневого сервера вручную.

В лекции Grizzly используется как промежуточный этап между самописным сервером и Spring.

Основная идея:

```text
HTTP Request
     ↓
Grizzly
     ↓
Handler
     ↓
Java code
```

---

## DocRoot

**Определение:**

DocRoot — корневая директория, из которой HTTP-сервер отдаёт статические файлы.

Например:

```text
public/
├── index.html
├── app.js
└── style.css
```

Если `public` настроен как DocRoot, сервер может отдавать эти файлы напрямую.

---

## Shutdown Hook

**Определение:**

Shutdown Hook — код, который JVM выполняет при завершении работы приложения.

Регистрируется через:

```java
Runtime.getRuntime()
       .addShutdownHook(thread);
```

Используется, например, чтобы корректно остановить HTTP-сервер:

```text
JVM завершает работу
       ↓
Shutdown Hook
       ↓
server.shutdown()
```

---

## REST

**Определение:**

REST (Representational State Transfer) — подход к организации взаимодействия между клиентом и сервером вокруг **ресурсов** и стандартных возможностей HTTP.

В современной практике REST обычно связывают с:

* HTTP;
* HTTP-методами;
* статус-кодами;
* ресурсами;
* stateless-взаимодействием;
* JSON/XML для передачи данных.

Пример:

```text
GET    /users
GET    /users/10
POST   /users
DELETE /users/10
```

---

## REST API

**Определение:**

REST API — API, организованное вокруг ресурсов и HTTP-операций.

Например, ресурс:

```text
/users
```

Операции:

```text
GET /users
```

получить пользователей.

```text
GET /users/10
```

получить пользователя `10`.

```text
POST /users
```

создать пользователя.

```text
DELETE /users/10
```

удалить пользователя `10`.

---

## Resource-Oriented API

**Определение:**

Resource-Oriented API — подход, при котором API организуется вокруг сущностей или ресурсов системы.

Плохой условный вариант:

```text
/getUsers
/createUser
/deleteUser
```

REST-подобный вариант:

```text
GET    /users
POST   /users
DELETE /users/10
```

URL описывает **ресурс**, а HTTP-метод — действие.

---

## Representation

**Определение:**

Representation — представление состояния ресурса в формате, пригодном для передачи клиенту.

Например, ресурс:

```text
/users/10
```

может быть представлен как JSON:

```json
{
  "id": 10,
  "name": "Danil"
}
```

Сам ресурс и его JSON-представление — не одно и то же.

JSON является только способом представить данные ресурса.

---

## Stateless REST

**Определение:**

Stateless в REST означает, что каждый запрос клиента должен содержать всю информацию, необходимую для его обработки.

Сервер не должен зависеть от скрытого контекста предыдущего запроса.

Условно:

```text
Request 1
Request 2
Request 3
```

каждый должен быть понятен серверу самостоятельно.

---

## SOP

**Определение:**

SOP (Same-Origin Policy) — механизм безопасности браузера, ограничивающий взаимодействие JavaScript-кода с ресурсами другого Origin.

Упрощённо:

```text
JS с origin A
     ↓
ресурс origin B
     ↓
браузер применяет ограничения
```

Это ограничение реализуется именно браузером.

---

## Origin

**Определение:**

Origin — комбинация трёх компонентов:

```text
scheme + host + port
```

Например:

```text
http://localhost:8080
```

состоит из:

```text
scheme = http
host   = localhost
port   = 8080
```

Если хотя бы один компонент отличается, Origin считается другим.

Например:

```text
http://localhost:8080
http://localhost:9999
```

— разные Origin из-за разных портов.

---

## Same-Origin

**Определение:**

Same-Origin — ситуация, когда два ресурса имеют одинаковые:

```text
scheme
host
port
```

Например:

```text
https://example.com:443/page
https://example.com:443/api
```

имеют одинаковый Origin.

---

## Cross-Origin

**Определение:**

Cross-Origin — взаимодействие между ресурсами с разными Origin.

Например:

```text
Frontend:
http://localhost:3000
```

Backend:

```text
http://localhost:8080
```

Порты разные, значит запрос является Cross-Origin.

---

## CORS

**Определение:**

CORS (Cross-Origin Resource Sharing) — механизм, позволяющий серверу явно сообщить браузеру, каким другим Origin разрешено получать доступ к его ресурсам.

CORS реализуется через HTTP-заголовки.

Например:

```http
Access-Control-Allow-Origin: http://localhost:3000
```

Условно:

```text
Frontend
http://localhost:3000
        ↓
     request
        ↓
Backend
http://localhost:8080
        ↓
Access-Control-Allow-Origin
        ↓
Browser разрешает доступ JS к ответу
```

---

## `Access-Control-Allow-Origin`

**Определение:**

`Access-Control-Allow-Origin` — CORS-заголовок ответа, указывающий, какому Origin разрешено обращаться к ресурсу.

Например:

```http
Access-Control-Allow-Origin: http://localhost:3000
```

или:

```http
Access-Control-Allow-Origin: *
```

---

## Simple Request

**Определение:**

Simple Request — Cross-Origin HTTP-запрос, удовлетворяющий определённым ограничениям CORS и не требующий предварительного OPTIONS-запроса.

В упрощённом виде используются методы:

```text
GET
POST
HEAD
```

и ограниченный набор заголовков и Content-Type.

Например:

```text
application/x-www-form-urlencoded
multipart/form-data
text/plain
```

---

## Preflight Request

**Определение:**

Preflight Request — предварительный запрос, который браузер отправляет перед некоторыми Cross-Origin запросами, чтобы проверить, разрешает ли сервер такое взаимодействие.

Для preflight используется метод:

```text
OPTIONS
```

Схема:

```text
Browser
   ↓
OPTIONS /api
   ↓
Backend
   ↓
Access-Control-Allow-*
   ↓
Browser
   ↓
POST /api
```

---

## OPTIONS

**Определение:**

OPTIONS — HTTP-метод, который в CORS используется браузером для предварительной проверки разрешённых действий.

Пример:

```http
OPTIONS /api HTTP/1.1
```

После этого сервер должен ответить CORS-заголовками.

---

## `Access-Control-Allow-*`

**Определение:**

`Access-Control-Allow-*` — семейство HTTP-заголовков, которыми сервер сообщает браузеру разрешения CORS.

Например:

```http
Access-Control-Allow-Origin: http://localhost:3000
```

```http
Access-Control-Allow-Methods: GET, POST
```

```http
Access-Control-Allow-Headers: Content-Type
```

---

## CORS Error

**Определение:**

CORS Error — ошибка браузера, возникающая, когда JavaScript пытается выполнить Cross-Origin взаимодействие, которое сервер не разрешил нужными CORS-заголовками.

Важно:

CORS — не обязательно означает, что запрос вообще не дошёл до сервера.

В некоторых случаях:

```text
Browser → Server
```

запрос приходит,

но:

```text
Server → Browser
```

ответ не предоставляется JavaScript-коду.

---

## Browser Security Boundary

**Определение:**

Browser Security Boundary — ограничения безопасности, которые браузер накладывает на JavaScript.

SOP и CORS относятся именно к этим ограничениям.

Backend-разработчик должен понимать их, потому что API может технически работать, но frontend не сможет его использовать из-за политики браузера.

---

# Главное из темы

Для этой темы лучше запомнить три ключевые цепочки.

### AJAX

```text
User action
    ↓
JavaScript
    ↓
preventDefault()
    ↓
XHR
    ↓
HTTP Request
    ↓
Backend
    ↓
HTTP Response
    ↓
JavaScript
    ↓
изменение страницы без reload
```

### REST

```text
Resource
   ↓
/users
   ↓
HTTP Method
   ↓
GET / POST / DELETE
   ↓
HTTP Status
   ↓
JSON
```

### CORS

```text
Frontend Origin
http://localhost:3000

        ↓ request

Backend Origin
http://localhost:8080

        ↓

браузер проверяет CORS

        ↓

Access-Control-Allow-*
```

Если запрос требует Preflight:

```text
OPTIONS
   ↓
CORS headers
   ↓
original request
```
