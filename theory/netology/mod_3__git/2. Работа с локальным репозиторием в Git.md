# Работа с локальным репозиторием в Git

## 1. Локальный репозиторий

**Определение**
Локальный репозиторий — это Git-репозиторий, который находится на твоём компьютере.

**Пример**

```text
Папка test на рабочем столе может стать локальным репозиторием,
если внутри неё выполнить команду git init.
```

---

## 2. Удалённый репозиторий

**Определение**
Удалённый репозиторий — это репозиторий, который находится в интернете, например на GitHub.

**Пример**

```text
Локальный репозиторий лежит у тебя на компьютере.
Удалённый репозиторий лежит на GitHub.
```

---

## 3. Repository / репозиторий

**Определение**
Репозиторий — это папка проекта, за которой следит Git.

**Пример**

```text
Папка learning-java может быть репозиторием,
если Git отслеживает изменения внутри неё.
```

---

## 4. `git init`

**Определение**
`git init` — команда, которая создаёт новый локальный Git-репозиторий в текущей папке.

**Пример**

```bash
git init
```

После выполнения команды Git создаёт скрытую папку `.git`.

---

## 5. `.git`

**Определение**
`.git` — скрытая служебная папка, в которой Git хранит всю информацию о репозитории: историю, коммиты, настройки и служебные данные.

**Пример**

```text
test/
  .git/
  README.md
```

Если удалить `.git`, папка перестанет быть Git-репозиторием.

---

## 6. Рабочая папка проекта

**Определение**
Рабочая папка проекта — это обычная папка на компьютере, где лежат файлы проекта, с которыми ты работаешь.

**Пример**

```text
test/
  README.md
  errors.md
```

---

## 7. Рабочее дерево / Working Tree

**Определение**
Working Tree — это текущее состояние файлов проекта в рабочей папке.

**Пример**

```text
Ты открыл README.md и добавил новую строку.
Это изменение появилось в рабочем дереве.
```

---

## 8. Состояние файла

**Определение**
Состояние файла — это то, как Git сейчас видит файл: новый, изменённый, подготовленный к коммиту или уже сохранённый в истории.

**Пример**

```bash
git status
```

Команда показывает состояние файлов в репозитории.

---

## 9. `git status`

**Определение**
`git status` — команда, которая показывает текущее состояние репозитория и файлов.

**Пример**

```bash
git status
```

Git может показать:

```text
Untracked files
Changes to be committed
Changes not staged for commit
working tree clean
```

---

## 10. Неотслеживаемый файл / Untracked file

**Определение**
Неотслеживаемый файл — это файл, который есть в папке проекта, но Git пока за ним не следит.

**Пример**

```text
Ты создал README.md.
Git видит файл, но ещё не отслеживает его.
```

В `git status` такой файл может отображаться как:

```text
Untracked files:
  README.md
```

---

## 11. Отслеживаемый файл / Tracked file

**Определение**
Отслеживаемый файл — это файл, который Git уже взял под контроль и изменения которого может фиксировать.

**Пример**

```bash
git add README.md
```

После этой команды файл становится подготовленным к коммиту.

---

## 12. `git add`

**Определение**
`git add` — команда, которая добавляет файл в индекс, то есть подготавливает его к будущему коммиту.

**Пример**

```bash
git add README.md
```

Важно: `git add` ещё не сохраняет изменения в историю. Он только готовит их к сохранению.

---

## 13. Индекс / Staging Area

**Определение**
Индекс, или Staging Area, — это промежуточная зона между рабочей папкой и коммитом. В неё попадают файлы, которые будут включены в следующий коммит.

**Пример**

```text
1. Изменил README.md
2. Выполнил git add README.md
3. README.md попал в индекс
4. Теперь его можно закоммитить
```

---

## 14. Staged file

**Определение**
Staged file — это файл, который уже добавлен в индекс и готов попасть в следующий коммит.

**Пример**

```bash
git add README.md
git status
```

Git может показать:

```text
Changes to be committed:
  new file: README.md
```

---

## 15. Commit / коммит

**Определение**
Коммит — это сохранённый снимок состояния проекта в определённый момент времени.

**Пример**

```bash
git commit -m "add README"
```

Эта команда создаёт коммит с сообщением `add README`.

---

## 16. Снимок проекта

**Определение**
Снимок проекта — это сохранённое состояние файлов проекта на момент коммита.

**Пример**

```text
Коммит №1: README.md содержит только заголовок.
Коммит №2: README.md содержит заголовок и новый текст.
```

Можно вернуться к старому снимку и посмотреть, как проект выглядел раньше.

---

## 17. `git commit`

**Определение**
`git commit` — команда, которая сохраняет подготовленные изменения в историю Git.

**Пример**

```bash
git commit -m "add README"
```

---

## 18. `-m`

**Определение**
`-m` — флаг команды `git commit`, который позволяет сразу написать сообщение коммита.

**Пример**

```bash
git commit -m "change README"
```

Без `-m` Git может открыть редактор для ввода сообщения.

---

## 19. Сообщение коммита

**Определение**
Сообщение коммита — это короткое описание того, что изменилось в проекте.

**Пример**

```bash
git commit -m "add README"
```

Хорошее сообщение:

```text
add README
```

Плохое сообщение:

```text
fix
```

Почему плохо: непонятно, что именно было исправлено.

---

## 20. `working tree clean`

**Определение**
`working tree clean` — сообщение Git, которое означает, что в проекте нет несохранённых изменений.

**Пример**

```bash
git status
```

Результат:

```text
nothing to commit, working tree clean
```

Это значит: всё, что нужно, уже сохранено в коммитах.

---

## 21. Modified

**Определение**
`modified` — состояние файла, которое означает, что файл был изменён после последнего коммита.

**Пример**

```text
Ты изменил README.md.
Git status показывает:
modified: README.md
```

---

## 22. История проекта

**Определение**
История проекта — это список всех коммитов, которые были сделаны в репозитории.

**Пример**

```bash
git log
```

Git покажет коммиты, авторов, даты и сообщения.

---

## 23. `git log`

**Определение**
`git log` — команда для просмотра истории коммитов.

**Пример**

```bash
git log
```

Результат может содержать:

```text
commit 2199e0e8...
Author: Danil Ponomarenko
Date: ...
change README
```

---

## 24. `git log --oneline`

**Определение**
`git log --oneline` — команда для просмотра истории коммитов в коротком формате: один коммит — одна строка.

**Пример**

```bash
git log --oneline
```

Пример результата:

```text
2199e0e change README
9b7bb91 add README
```

---

## 25. Флаг

**Определение**
Флаг — это дополнительный параметр команды, который меняет её поведение. В Git флаги обычно начинаются с одного `-` или двух `--`.

**Пример**

```bash
git log --oneline
```

Здесь `--oneline` — флаг.

---

## 26. Хеш коммита

**Определение**
Хеш коммита — это уникальный идентификатор коммита.

**Пример**

```text
2199e0e
9b7bb91
```

По хешу Git понимает, к какому именно коммиту нужно обратиться.

---

## 27. ID коммита

**Определение**
ID коммита — это другое название хеша коммита.

**Пример**

```bash
git checkout 9b7bb91
```

Здесь `9b7bb91` — ID коммита.

---

## 28. HEAD

**Определение**
`HEAD` — это указатель на коммит, в котором ты сейчас находишься.

**Пример**

```text
2199e0e (HEAD -> main) change README
```

Это значит, что сейчас ты находишься на последнем коммите ветки `main`.

---

## 29. Указатель

**Определение**
Указатель — это ссылка Git на определённый коммит.

**Пример**

```text
HEAD -> main
```

`HEAD` показывает, где ты сейчас находишься в истории проекта.

---

## 30. `--all`

**Определение**
`--all` — флаг команды `git log`, который показывает всю историю, включая коммиты из разных веток и состояний.

**Пример**

```bash
git log --all --oneline
```

---

## 31. `git commit --amend`

**Определение**
`git commit --amend` — команда, которая позволяет изменить последний коммит.

**Пример**

```bash
git commit --amend -m "error"
```

Важно: Git не редактирует старый коммит напрямую, а создаёт новый коммит вместо старого.

---

## 32. `--amend`

**Определение**
`--amend` — флаг, который используется для исправления последнего коммита.

**Пример**

```bash
git commit --amend -m "fix typo in README"
```

Так можно исправить сообщение последнего коммита или добавить в него забытые файлы.

---

## 33. Перезапись коммита

**Определение**
Перезапись коммита — это замена последнего коммита новым исправленным коммитом.

**Пример**

```bash
git commit --amend -m "correct message"
```

После такой команды у коммита изменится хеш, потому что Git создал новый коммит.

---

## 34. `git add -A`

**Определение**
`git add -A` — команда, которая добавляет в индекс все изменения в текущем репозитории.

**Пример**

```bash
git add -A
```

В индекс попадут:

```text
новые файлы
изменённые файлы
удалённые файлы
```

---

## 35. Исправление последнего коммита

**Определение**
Исправление последнего коммита — это добавление небольших правок в последний коммит, чтобы не создавать лишние коммиты в истории.

**Пример**

```bash
git add errors.md
git commit --amend -m "add errors file"
```

---

## 36. Чистая история коммитов

**Определение**
Чистая история коммитов — это история, в которой коммиты имеют понятные названия и не засорены мелкими правками вроде `fix typo`, `oops`, `again`.

**Пример плохо**

```text
add README
fix
fix again
oops
final fix
```

**Пример лучше**

```text
add README
add errors documentation
```

---

## 37. Перемещение по истории

**Определение**
Перемещение по истории — это переход к одному из старых коммитов, чтобы посмотреть прошлое состояние проекта.

**Пример**

```bash
git checkout 9b7bb91
```

---

## 38. `git checkout`

**Определение**
`git checkout` — команда, которая позволяет переключаться между коммитами или ветками.

**Пример**

```bash
git checkout 9b7bb91
```

Эта команда переключит проект на состояние конкретного коммита.

---

## 39. `git checkout хеш`

**Определение**
`git checkout хеш` — команда для перехода к конкретному коммиту по его хешу.

**Пример**

```bash
git checkout 9b7bb91
```

После этого файлы проекта будут выглядеть так, как они выглядели в этом коммите.

---

## 40. Detached HEAD

**Определение**
Detached HEAD — это состояние Git, когда ты находишься не на ветке, а на конкретном коммите.

**Пример**

```bash
git checkout 9b7bb91
```

Git может показать:

```text
You are in 'detached HEAD' state
```

Это значит: ты смотришь старую точку истории, но не находишься на обычной ветке.

---

## 41. `git checkout -`

**Определение**
`git checkout -` — команда, которая возвращает тебя туда, где ты был до последнего переключения.

**Пример**

```bash
git checkout -
```

Например, если ты ушёл на старый коммит, эта команда может вернуть тебя обратно на `main`.

---

## 42. `git checkout main`

**Определение**
`git checkout main` — команда, которая переключает тебя обратно на основную ветку `main`.

**Пример**

```bash
git checkout main
```

---

## 43. `main`

**Определение**
`main` — основная ветка проекта, в которой обычно хранится актуальная стабильная версия.

**Пример**

```text
HEAD -> main
```

Это значит, что сейчас ты находишься на ветке `main`.

---

## 50. Последовательность работы с Git

**Определение**
Базовая последовательность работы с Git — это стандартный порядок действий: изменить файл, добавить изменения в индекс, создать коммит.

**Пример**

```bash
git status
git add README.md
git commit -m "change README"
git status
```

---

# Коротко: что нужно запомнить

```text
git init — создать локальный репозиторий.
.git — служебная папка Git.
git status — проверить состояние файлов.
git add — добавить изменения в индекс.
git commit — сохранить изменения в историю.
git log — посмотреть историю коммитов.
git log --oneline — короткая история.
git commit --amend — исправить последний коммит.
git add -A — добавить все изменения.
git checkout хеш — перейти к старому коммиту.
git checkout main — вернуться на основную ветку.
HEAD — указатель на текущее место в истории.
Detached HEAD — состояние, когда ты находишься на конкретном коммите, а не на ветке.
```

---

# Мини-шпаргалка команд

```bash
# Создать локальный репозиторий
git init

# Проверить состояние репозитория
git status

# Добавить один файл в индекс
git add README.md

# Добавить все изменения
git add -A

# Создать коммит
git commit -m "add README"

# Посмотреть историю
git log

# Посмотреть короткую историю
git log --oneline

# Посмотреть всю историю
git log --all --oneline

# Исправить последний коммит
git commit --amend -m "new message"

# Перейти к старому коммиту
git checkout хеш_коммита

# Вернуться обратно
git checkout -

# Вернуться на основную ветку
git checkout main
```
