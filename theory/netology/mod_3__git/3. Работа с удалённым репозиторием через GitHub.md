# Работа с удалённым репозиторием через GitHub

## 1. GitHub

GitHub — это онлайн-платформа для хранения Git-репозиториев, совместной разработки и демонстрации кода.

**Пример**

```text
Локально проект лежит у тебя на компьютере.
На GitHub этот же проект можно хранить в интернете.
```

---

## 2. Git ≠ GitHub

Git и GitHub — это разные вещи. Git — это система контроля версий, а GitHub — сервис для хранения Git-репозиториев в интернете.

**Пример**

```text
Git работает даже без GitHub.
GitHub использует Git, но не является самим Git.
```

---

## 3. Удалённый репозиторий

Удалённый репозиторий — это репозиторий, который хранится не на твоём компьютере, а в сети, например на GitHub.

**Пример**

```text
Локальный репозиторий: папка проекта на компьютере.
Удалённый репозиторий: копия проекта на GitHub.
```

---

## 4. Локальный репозиторий

Локальный репозиторий — это Git-репозиторий, который находится на твоём компьютере.

**Пример**

```text
Папка test на рабочем столе после git init — это локальный репозиторий.
```

---

## 5. Public repository

Public repository — это публичный репозиторий, который могут видеть другие пользователи.

**Пример**

```text
Учебные проекты часто делают публичными,
чтобы преподаватель или работодатель мог посмотреть код.
```

---

## 6. Private repository

Private repository — это приватный репозиторий, доступный только владельцу и приглашённым пользователям.

**Пример**

```text
Коммерческий проект компании обычно хранится в приватном репозитории.
```

---

## 7. SSH-ключ

SSH-ключ — это способ безопасно связать твой компьютер с GitHub, чтобы GitHub понимал, что команды отправляешь именно ты.

**Пример**

```text
Ты отправляешь код из терминала.
GitHub проверяет SSH-ключ и понимает:
"Да, это владелец аккаунта".
```

---

## 8. Публичный SSH-ключ

Публичный SSH-ключ — это часть SSH-ключа, которую можно добавить в настройки GitHub.

**Пример**

```bash
cat ~/.ssh/id_rsa.pub
```

Команда показывает публичный ключ, который можно скопировать в GitHub.

---

## 9. Приватный SSH-ключ

Приватный SSH-ключ — это секретная часть ключа, которая хранится только на твоём компьютере.

**Пример**

```text
Публичный ключ можно добавить на GitHub.
Приватный ключ нельзя никому отправлять.
```

---

## 10. `ssh-keygen`

`ssh-keygen` — команда для генерации SSH-ключа.

**Пример**

```bash
ssh-keygen
```

После выполнения команды создаётся пара ключей: приватный и публичный.

---

## 11. `cat`

`cat` — терминальная команда, которая выводит содержимое файла.

**Пример**

```bash
cat ~/.ssh/id_rsa.pub
```

Эта команда показывает содержимое публичного SSH-ключа.

---

## 12. `remote`

`remote` — это удалённая связь локального репозитория с репозиторием в интернете.

**Пример**

```text
Локальный проект связан с GitHub-репозиторием.
Эта связь называется remote.
```

---

## 13. `origin`

`origin` — стандартное имя удалённого репозитория, к которому привязан локальный проект.

**Пример**

```bash
git remote add origin git@github.com:user/test.git
```

Здесь `origin` — короткое имя для длинной ссылки на GitHub-репозиторий.

---

## 14. `git remote`

`git remote` — команда для работы со связями между локальным и удалённым репозиторием.

**Пример**

```bash
git remote -v
```

Показывает, к каким удалённым репозиториям привязан проект.

---

## 15. `git remote -v`

`git remote -v` — команда, которая показывает список удалённых репозиториев и их адреса.

**Пример**

```bash
git remote -v
```

Пример результата:

```text
origin  git@github.com:user/test.git (fetch)
origin  git@github.com:user/test.git (push)
```

---

## 16. `git remote add origin`

`git remote add origin` — команда, которая связывает локальный репозиторий с удалённым репозиторием.

**Пример**

```bash
git remote add origin git@github.com:user/test.git
```

После этого Git понимает, куда отправлять проект.

---

## 17. `git remote remove origin`

`git remote remove origin` — команда, которая удаляет связь с удалённым репозиторием.

**Пример**

```bash
git remote remove origin
```

---

## 18. `fetch`

`fetch` — направление связи, связанное с получением данных из удалённого репозитория.

**Пример**

```text
origin git@github.com:user/test.git (fetch)
```

Это значит: из этого адреса Git может получать изменения.

---

## 19. `push`

`push` — отправка локальных коммитов в удалённый репозиторий.

**Пример**

```bash
git push
```

---

## 20. `git push`

`git push` — команда, которая отправляет локальные коммиты в удалённый репозиторий.

**Пример**

```bash
git push -u origin main
```

Эта команда отправляет ветку `main` в удалённый репозиторий `origin`.

---

## 21. `git push -u origin main`

`git push -u origin main` — команда первой отправки локальной ветки `main` в удалённый репозиторий `origin`.

**Пример**

```bash
git push -u origin main
```

После этого Git запоминает связь, и в следующий раз часто достаточно написать:

```bash
git push
```

---

## 22. `-u`

`-u` — флаг, который устанавливает связь между локальной веткой и удалённой веткой.

**Пример**

```bash
git push -u origin main
```

После этого локальная `main` начинает отслеживать удалённую `origin/main`.

---

## 23. `origin/main`

`origin/main` — удалённая версия ветки `main`, которая находится в репозитории `origin`.

**Пример**

```text
main — локальная ветка.
origin/main — ветка main на GitHub.
```

---

## 24. Публикация проекта

Публикация проекта — это отправка локального проекта в удалённый репозиторий, например на GitHub.

**Пример**

```bash
git push -u origin main
```

---

## 25. Commit history на GitHub

Commit history на GitHub — это история коммитов проекта, которую можно посмотреть через интерфейс GitHub.

**Пример**

```text
На странице репозитория можно нажать "commits"
и увидеть список изменений: автора, дату, хеш и сообщение.
```

---

## 26. README.md на GitHub

`README.md` — файл с описанием проекта. GitHub автоматически показывает его содержимое на главной странице репозитория.

**Пример**

```markdown
# My Java Project

Учебный проект по Java.
```

---

## 27. Fork / форк

Fork — это копия чужого репозитория в твоём GitHub-аккаунте.

**Пример**

```text
Есть чужой репозиторий netology-code/git-2-fork.
Ты нажимаешь Fork.
В твоём аккаунте появляется своя копия этого проекта.
```

---

## 28. Исходный репозиторий

Исходный репозиторий — это оригинальный репозиторий, от которого был создан форк.

**Пример**

```text
forked from netology-code/git-2-fork
```

Это значит, что твой репозиторий является копией исходного проекта.

---

## 29. `clone`

Clone — это копирование удалённого репозитория на локальный компьютер.

**Пример**

```bash
git clone git@github.com:user/project.git
```

---

## 30. `git clone`

`git clone` — команда, которая копирует удалённый репозиторий на компьютер и создаёт локальный репозиторий.

**Пример**

```bash
git clone git@github.com:user/git-2-fork.git
```

После выполнения команды появится папка проекта.

---

## 31. Клонирование репозитория

Клонирование репозитория — это создание локальной копии удалённого репозитория.

**Пример**

```bash
git clone git@github.com:user/test.git
```

---

## 32. `Code` на GitHub

`Code` — кнопка на GitHub, через которую можно скопировать ссылку на репозиторий для клонирования.

**Пример**

```text
Нажал Code → выбрал SSH → скопировал ссылку → выполнил git clone.
```

---

## 33. `cd`

`cd` — команда терминала для перехода в другую папку.

**Пример**

```bash
cd git-2-fork
```

После этого терминал будет работать внутри папки `git-2-fork`.

---

## 34. Ветка

Ветка — это отдельная линия разработки проекта. Она позволяет работать над задачей отдельно от основной версии проекта.

**Пример**

```text
main — основная ветка.
new-branch — ветка для новой задачи.
```

---

## 35. Ветвление

Ветвление — это создание отдельных веток для независимой работы над разными задачами.

**Пример**

```text
Один разработчик делает авторизацию в ветке feature-login.
Другой делает корзину в ветке feature-cart.
Они не мешают друг другу.
```

---

## 36. `main`

`main` — основная ветка проекта, где обычно хранится стабильная версия.

**Пример**

```bash
git checkout main
```

---

## 37. `git branch`

`git branch` — команда для просмотра, создания и управления ветками.

**Пример просмотра веток**

```bash
git branch
```

**Пример создания ветки**

```bash
git branch new-branch
```

---

## 38. Текущая ветка

Текущая ветка — это ветка, в которой ты сейчас находишься и куда будут попадать новые коммиты.

**Пример**

```text
* main
  new-branch
```

Звёздочка показывает текущую ветку.

---

## 39. `git checkout имя-ветки`

`git checkout имя-ветки` — команда для переключения на другую ветку.

**Пример**

```bash
git checkout new-branch
```

---

## 40. `git checkout -b`

`git checkout -b` — команда, которая создаёт новую ветку и сразу переключается на неё.

**Пример**

```bash
git checkout -b fix
```

Это короче, чем две команды:

```bash
git branch fix
git checkout fix
```

---

## 43. Отправка ветки на GitHub

Отправка ветки на GitHub — это публикация локальной ветки в удалённом репозитории.

**Пример**

```bash
git push -u origin new-branch
```

---

## 44. `git log имя-ветки --graph --oneline`

Команда для просмотра истории конкретной ветки в компактном графическом виде.

**Пример**

```bash
git log new-branch --graph --oneline
```

---

## 45. `--graph`

`--graph` — флаг команды `git log`, который показывает историю коммитов в виде текстового графа.

**Пример**

```bash
git log --graph --oneline
```

---

## 46. `merge`

Merge — это слияние изменений из одной ветки в другую.

**Пример**

```text
Ты сделал задачу в ветке new-branch.
Потом влил изменения в main.
Это merge.
```

---

## 47. `git merge`

`git merge` — команда для слияния одной ветки с другой.

**Пример**

```bash
git checkout main
git merge new-branch
```

Важно: перед `merge` нужно находиться в той ветке, **куда** ты хочешь влить изменения.

---

## 48. Слияние веток

Слияние веток — это перенос изменений из одной ветки в другую.

**Пример**

```bash
git checkout main
git merge fix
```

Здесь изменения из `fix` вливаются в `main`.

---

## 49. Конфликт

Конфликт — это ситуация, когда Git не может автоматически объединить изменения, потому что в разных ветках изменили один и тот же участок файла по-разному.

**Пример**

```text
В main написали:
Я изучаю Git

В fix написали:
Я изучаю git

Git не знает, какой вариант оставить.
```

---

## 50. Merge conflict

Merge conflict — это конфликт, который возник во время слияния веток.

**Пример**

```text
CONFLICT (content): Merge conflict in README.md
Automatic merge failed; fix conflicts and then commit the result
```

---

## 51. `CONFLICT (content)`

`CONFLICT (content)` — сообщение Git, которое означает конфликт в содержимом файла.

**Пример**

```text
CONFLICT (content): Merge conflict in README.md
```

Это значит, что конфликт возник в файле `README.md`.

---

## 52. `HEAD` в конфликте

`HEAD` в конфликте — это версия изменений из текущей ветки, в которую выполняется слияние.

**Пример**

```text
<<<<<<< HEAD
- Я изучаю Git
=======
- Я изучаю git
>>>>>>> fix
```

Часть после `<<<<<<< HEAD` — это версия текущей ветки.

---

## 53. `=======` в конфликте

`=======` — служебный разделитель Git, который отделяет две конфликтующие версии кода или текста.

**Пример**

```text
<<<<<<< HEAD
первая версия
=======
вторая версия
>>>>>>> fix
```

---

## 54. `>>>>>>> имя-ветки`

`>>>>>>> имя-ветки` — служебная строка Git, которая показывает, из какой ветки пришла вторая версия изменений.

**Пример**

```text
>>>>>>> fix
```

---

## 55. Разрешение конфликта

Разрешение конфликта — это ручной выбор правильной версии изменений после неудачного автоматического слияния.

**Пример**

Было:

```text
<<<<<<< HEAD
- Я не люблю программировать
=======
- Я люблю программировать ♥️
>>>>>>> fix
```

Стало:

```text
- Я люблю программировать ♥️
```

После этого нужно удалить служебные символы и сделать коммит.

---

## 56. Служебные символы конфликта

Служебные символы конфликта — это строки, которые Git вставляет в файл, чтобы показать конфликтующие версии.

**Пример**

```text
<<<<<<< HEAD
=======
>>>>>>> fix
```

Их обязательно нужно удалить перед коммитом.

---

## 57. Коммит разрешения конфликта

Коммит разрешения конфликта — это коммит, который фиксирует результат ручного решения конфликта.

**Пример**

```bash
git add -A
git commit -m "conflict resolved"
```

---

# Коротко: что нужно запомнить

```text
Git — система контроля версий.
GitHub — онлайн-платформа для хранения Git-репозиториев.

SSH-ключ нужен, чтобы безопасно связать компьютер с GitHub.

origin — стандартное имя удалённого репозитория.
git remote -v — посмотреть связи с удалёнными репозиториями.
git remote add origin ссылка — привязать локальный репозиторий к GitHub.

git push -u origin main — первый раз отправить main на GitHub.
git push — отправить изменения после первой настройки.

Fork — сделать копию чужого репозитория в свой GitHub.
git clone ссылка — скачать удалённый репозиторий на компьютер.

git branch — посмотреть или создать ветки.
git checkout ветка — переключиться на ветку.
git checkout -b ветка — создать ветку и сразу перейти в неё.

git merge ветка — влить указанную ветку в текущую.
Конфликт — ситуация, когда Git не может сам объединить изменения.
При конфликте нужно удалить <<<<<<<, =======, >>>>>>> и оставить правильный вариант.
```

# Мини-шпаргалка команд

```bash
# Сгенерировать SSH-ключ
ssh-keygen

# Показать публичный SSH-ключ
cat ~/.ssh/id_rsa.pub

# Посмотреть удалённые связи
git remote -v

# Добавить удалённый репозиторий
git remote add origin git@github.com:user/project.git

# Удалить связь с origin
git remote remove origin

# Первый раз отправить main на GitHub
git push -u origin main

# Обычная отправка изменений
git push

# Скопировать репозиторий на компьютер
git clone git@github.com:user/project.git

# Перейти в папку
cd project

# Посмотреть ветки
git branch

# Создать ветку
git branch new-branch

# Переключиться на ветку
git checkout new-branch

# Создать ветку и сразу перейти в неё
git checkout -b fix

# Отправить новую ветку на GitHub
git push -u origin new-branch

# Посмотреть историю ветки
git log new-branch --graph --oneline

# Перейти в main
git checkout main

# Слить ветку в текущую
git merge new-branch

# После решения конфликта
git add -A
git commit -m "conflict resolved"
```
