# Тема 5: Generics в коллекциях и методах

## Generics

**Определение:**

`Generics` — это механизм Java, который позволяет создавать классы, интерфейсы, методы и конструкторы, работающие с разными типами данных без дублирования кода.

Generics позволяют заранее указать, с каким типом данных будет работать объект или метод.

Главная польза generics — типобезопасность: Java проверяет правильность типов ещё на этапе компиляции.

**Пример:**

```java
public class Memory<T> {
    private T value;

    public void save(T value) {
        this.value = value;
    }

    public T getLast() {
        return value;
    }
}
```

---

## Обобщения

**Определение:**

Обобщения — это русское название механизма `generics`.

С помощью обобщений можно написать один универсальный класс или метод, который будет работать с разными типами данных.

Например, один класс `Memory<T>` может хранить `String`, `Integer`, `Double` или любой другой ссылочный тип.

**Пример:**

```java
Memory<String> stringMemory = new Memory<>();
stringMemory.save("Petya");

Memory<Integer> intMemory = new Memory<>();
intMemory.save(100);
```

---

## Дженерики

**Определение:**

Дженерики — разговорное название `generics`.

Они позволяют не писать отдельные классы под каждый тип данных.

Без дженериков пришлось бы создавать отдельные классы вроде:

```java
StringMemory
IntegerMemory
UserMemory
```

С дженериками достаточно одного класса:

```java
Memory<T>
```

**Пример:**

```java
Memory<String> names = new Memory<>();
Memory<Double> prices = new Memory<>();
Memory<User> users = new Memory<>();
```

---

## Типизированный класс

**Определение:**

Типизированный класс — это класс, у которого есть параметр типа в угловых скобках.

Параметр типа указывается после имени класса.

Такой класс можно использовать с разными типами данных, но внутри конкретного объекта тип будет фиксирован.

**Пример:**

```java
public class Memory<T> {
    private T value;

    public void save(T value) {
        this.value = value;
    }

    public T getLast() {
        return value;
    }
}
```

Использование:

```java
Memory<String> memory = new Memory<>();

memory.save("Tanya");

String value = memory.getLast();
```

---

## Параметр типа

**Определение:**

Параметр типа — это условное имя типа, которое указывается в угловых скобках.

Чаще всего используют букву `T`.

На этапе написания класса мы ещё не знаем конкретный тип, поэтому используем параметр типа как временное обозначение.

Когда создаётся объект, вместо `T` подставляется конкретный тип.

**Пример:**

```java
public class Memory<T> {
    private T value;
}
```

Здесь `T` — параметр типа.

При создании объекта:

```java
Memory<String> memory = new Memory<>();
```

`T` становится `String`.

---

## T

**Определение:**

`T` — это распространённое имя параметра типа в generics.

Буква `T` обычно означает `Type`.

Само имя параметра ни на что технически не влияет. Можно написать не `T`, а, например, `E`, `K`, `V` или даже `Item`.

Но в Java принято использовать короткие стандартные имена.

**Пример:**

```java
public class Box<T> {
    private T value;
}
```

То же самое технически можно написать так:

```java
public class Box<Item> {
    private Item value;
}
```

Но так обычно не делают.

---

## Угловые скобки

**Определение:**

Угловые скобки `< >` используются в Java для указания параметров типа.

Через них Java понимает, что класс, интерфейс или метод является обобщённым.

Внутри угловых скобок можно указать один или несколько параметров типа.

**Пример:**

```java
Memory<String> memory = new Memory<>();
```

В этом примере `<String>` указывает, что объект `memory` работает со строками.

---

## Конкретный тип generic-класса

**Определение:**

Конкретный тип generic-класса — это тип, который подставляется вместо параметра типа при создании объекта.

Например, в `Memory<String>` конкретным типом будет `String`.

После этого объект `Memory<String>` сможет сохранять только строки.

**Пример:**

```java
Memory<String> memory = new Memory<>();

memory.save("Petya");
memory.save("Olya");

String last = memory.getLast();
```

Так нельзя:

```java
memory.save(100);
```

Потому что `memory` ожидает `String`.

---

## Diamond operator

**Определение:**

`Diamond operator` — это запись `<>` справа при создании generic-объекта.

Он позволяет не повторять тип справа, если Java уже может вывести его из левой части выражения.

Такой синтаксис делает код короче и чище.

**Пример:**

Полная запись:

```java
Memory<String> memory = new Memory<String>();
```

С diamond operator:

```java
Memory<String> memory = new Memory<>();
```

---

## Типобезопасность

**Определение:**

Типобезопасность — это свойство кода, при котором Java контролирует, чтобы в объект попадали только значения правильного типа.

Generics повышают типобезопасность, потому что ошибка с неправильным типом обнаруживается на этапе компиляции, а не во время работы программы.

**Пример:**

```java
Memory<String> memory = new Memory<>();

memory.save("Petya");
```

Так Java разрешит.

```java
memory.save(100);
```

Так Java не разрешит, потому что `100` — это `int`, а `memory` работает со `String`.

---

## Проверка типов на этапе компиляции

**Определение:**

Проверка типов на этапе компиляции — это ситуация, когда Java находит ошибку ещё до запуска программы.

Generics позволяют компилятору заранее понять, какие типы допустимы.

Это лучше, чем получить ошибку уже во время выполнения программы.

**Пример:**

```java
Memory<String> memory = new Memory<>();

memory.save(123);
```

Такой код не скомпилируется, потому что `Memory<String>` ожидает строку.

---

## Явное приведение типа

**Определение:**

Явное приведение типа — это ручное указание Java, к какому типу нужно привести объект.

Без generics часто приходится писать приведение типа вручную.

Это опасно: если внутри лежит объект другого типа, программа может упасть с `ClassCastException`.

**Пример без generics:**

```java
Memory memory = new Memory();

memory.save("Petya");

String value = (String) memory.getLast();
```

Здесь `(String)` — явное приведение типа.

С generics оно не нужно:

```java
Memory<String> memory = new Memory<>();

memory.save("Petya");

String value = memory.getLast();
```

---

## Object как универсальный тип

**Определение:**

`Object` можно использовать как универсальный тип, потому что все классы в Java наследуются от `Object`.

Но если хранить значения как `Object`, Java теряет информацию о конкретном типе.

Из-за этого приходится вручную приводить типы, а ошибки могут проявиться только во время выполнения программы.

**Пример:**

```java
public class Memory {
    private Object value;

    public void save(Object value) {
        this.value = value;
    }

    public Object getLast() {
        return value;
    }
}
```

Минус:

```java
String value = (String) memory.getLast();
```

---

## Класс-обёртка

**Определение:**

Класс-обёртка — это ссылочный класс, который соответствует примитивному типу.

В generics нельзя использовать примитивные типы вроде `int`, `double`, `boolean`.

Вместо них используют классы-обёртки:

`Integer` вместо `int`

`Double` вместо `double`

`Boolean` вместо `boolean`

`Character` вместо `char`

**Пример:**

Так нельзя:

```java
Memory<int> memory = new Memory<>();
```

Так правильно:

```java
Memory<Integer> memory = new Memory<>();
```

---

## Integer

**Определение:**

`Integer` — это класс-обёртка для примитивного типа `int`.

Его используют там, где нужен объект, а не примитив.

Например, в generics:

```java
Memory<Integer>
List<Integer>
```

**Пример:**

```java
Memory<Integer> memory = new Memory<>();

memory.save(100);

Integer value = memory.getLast();
```

---

## Double

**Определение:**

`Double` — это класс-обёртка для примитивного типа `double`.

Его используют в generics вместо `double`.

**Пример:**

```java
Memory<Double> memory = new Memory<>();

memory.save(99.5);

Double value = memory.getLast();
```

---

## Generic-метод

**Определение:**

Generic-метод — это метод, у которого есть собственный параметр типа.

Параметр типа указывается перед возвращаемым типом метода.

Generic-метод удобен, когда тип нужен только внутри конкретного метода, а не на уровне всего класса.

**Пример:**

```java
public static <T> T choose(boolean flag, T first, T second) {
    if (flag) {
        return first;
    }

    return second;
}
```

Использование:

```java
String result = choose(true, "Petya", "Olya");

Integer number = choose(false, 10, 20);
```

---

## Вывод типа

**Определение:**

Вывод типа — это способность Java самостоятельно определить generic-тип по переданным значениям.

При вызове generic-метода тип часто не нужно указывать вручную.

Java сама понимает, какой тип использовать вместо `T`.

**Пример:**

```java
String result = choose(true, "Petya", "Olya");
```

Java понимает, что `T` — это `String`.

```java
Integer number = choose(false, 10, 20);
```

Java понимает, что `T` — это `Integer`.

---

## Явное указание типа generic-метода

**Определение:**

Явное указание типа generic-метода — это способ вручную сообщить Java, какой тип использовать при вызове метода.

Обычно Java умеет определить тип сама, но иногда тип можно указать явно.

Тип указывается перед именем метода.

**Пример:**

```java
String result = Main.<String>choose(true, "Petya", "Olya");
```

---

## Generic-конструктор

**Определение:**

Generic-конструктор — это конструктор, у которого есть собственный параметр типа.

Такой параметр типа относится только к конструктору, а не обязательно ко всему классу.

Generic-конструкторы встречаются реже, чем generic-классы и generic-методы.

**Пример:**

```java
public class Printer {

    public <T> Printer(T value) {
        System.out.println(value);
    }
}
```

Использование:

```java
Printer printer = new Printer("Hello");
Printer printer2 = new Printer(123);
```

---

## Generic-интерфейс

**Определение:**

Generic-интерфейс — это интерфейс с параметром типа.

Он позволяет описать общее поведение, но оставить тип данных на выбор конкретному классу.

Например, интерфейс `Savable<T>` говорит: объект умеет сохранять значение типа `T`.

**Пример:**

```java
public interface Savable<T> {
    void save(T obj);
}
```

---

## Реализация generic-интерфейса с конкретным типом

**Определение:**

Реализация generic-интерфейса с конкретным типом — это ситуация, когда класс заранее фиксирует тип интерфейса.

Например, класс реализует `Savable<String>`, значит его метод `save()` будет принимать только `String`.

**Пример:**

```java
public class StringMemory implements Savable<String> {

    @Override
    public void save(String obj) {
        System.out.println(obj);
    }
}
```

---

## Реализация generic-интерфейса с параметром типа

**Определение:**

Реализация generic-интерфейса с параметром типа — это ситуация, когда класс сам остаётся generic-классом и передаёт свой параметр типа в интерфейс.

Такой вариант гибче, потому что один класс может работать с разными типами данных.

**Пример:**

```java
public class Memory<T> implements Savable<T> {
    private T value;

    @Override
    public void save(T obj) {
        this.value = obj;
    }
}
```

---

## Generic и наследование

**Определение:**

Generic и наследование работают не так, как обычное наследование классов.

Даже если `Integer` наследуется от `Number`, это не значит, что `Memory<Integer>` является наследником `Memory<Number>`.

Java запрещает такое присваивание, чтобы сохранить типобезопасность.

**Пример:**

```java
Integer integer = 100;

Number number = integer;
```

Так можно, потому что `Integer` является `Number`.

Но так нельзя:

```java
Memory<Number> memory = new Memory<Integer>();
```

Проблема в том, что тогда можно было бы сделать так:

```java
memory.save(3.5);
```

А `3.5` — это `Double`, не `Integer`.

---

## Инвариантность generics

**Определение:**

Инвариантность generics означает, что `Generic<Child>` не является наследником `Generic<Parent>`, даже если `Child` наследуется от `Parent`.

Например, `Integer` является наследником `Number`, но `Memory<Integer>` не является наследником `Memory<Number>`.

Это сделано для защиты типов.

**Пример:**

```java
List<Integer> integers = new ArrayList<>();

List<Number> numbers = integers;
```

Такой код не скомпилируется.

---

## Ограничение типа

**Определение:**

Ограничение типа — это указание, какие типы можно использовать в generics.

Для этого используется конструкция `extends`.

Например, запись `<T extends Number>` означает, что вместо `T` можно использовать только `Number` или его наследников.

Ограничение типа даёт доступ к методам указанного родительского класса.

**Пример:**

```java
public static <T extends Number> T choose(boolean flag, T first, T second) {
    if (flag) {
        return first;
    }

    return second;
}
```

Так можно:

```java
Integer result = choose(true, 10, 20);
Double price = choose(false, 10.5, 20.5);
```

Так нельзя:

```java
String text = choose(true, "A", "B");
```

Потому что `String` не наследуется от `Number`.

---

## Bounded type parameter

**Определение:**

`Bounded type parameter` — это параметр типа с ограничением.

В Java он записывается через `extends`.

Такой параметр говорит: использовать можно не любой тип, а только тип из указанной иерархии.

**Пример:**

```java
public class NumberMemory<T extends Number> {
    private T value;

    public void save(T value) {
        this.value = value;
    }

    public T getLast() {
        return value;
    }
}
```

---

## Несколько параметров типа

**Определение:**

Generic-класс, интерфейс или метод может иметь несколько параметров типа.

Они перечисляются через запятую внутри угловых скобок.

Обычно больше двух-трёх параметров типа стараются не использовать, потому что код становится сложнее читать.

**Пример:**

```java
public class Box<K, V> {
    private K key;
    private V value;

    public Box(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() {
        return key;
    }

    public V getValue() {
        return value;
    }
}
```

---

## K

**Определение:**

`K` — стандартное имя параметра типа, которое обычно означает `Key`.

Часто используется в классах, где есть пара «ключ — значение».

Например:

```java
Map<K, V>
Box<K, V>
```

**Пример:**

```java
public class Box<K, V> {
    private K key;
    private V value;
}
```

---

## V

**Определение:**

`V` — стандартное имя параметра типа, которое обычно означает `Value`.

Часто используется вместе с `K`.

Например, в структуре, где есть ключ и значение.

**Пример:**

```java
public class Box<K, V> {
    private K key;
    private V value;
}
```

---

## E

**Определение:**

`E` — стандартное имя параметра типа, которое обычно означает `Element`.

Часто используется в коллекциях.

Например, `List<E>` означает список элементов типа `E`.

**Пример:**

```java
public class Storage<E> {
    private E element;

    public void save(E element) {
        this.element = element;
    }
}
```

---

## Raw type

**Определение:**

`Raw type` — это использование generic-класса без указания конкретного типа.

Например, `Box` вместо `Box<String>`.

Raw type отключает нормальную проверку типов на этапе компиляции и заставляет программиста вручную приводить типы.

В новом коде raw type лучше не использовать.

**Пример:**

```java
Box box = new Box("key", "value");
```

Лучше так:

```java
Box<String, String> box = new Box<>("key", "value");
```

---

## Сырая коллекция

**Определение:**

Сырая коллекция — это коллекция без указания generic-типа.

Например, `List` вместо `List<String>`.

Такая коллекция может хранить объекты разных типов, из-за чего повышается риск ошибок во время выполнения программы.

**Пример:**

```java
List list = new ArrayList();

list.add("Petya");
list.add(100);

String name = (String) list.get(0);
```

Лучше так:

```java
List<String> names = new ArrayList<>();

names.add("Petya");

String name = names.get(0);
```

---

## Типизированная коллекция

**Определение:**

Типизированная коллекция — это коллекция с явно указанным generic-типом.

Например, `List<String>`.

Такая коллекция принимает только элементы указанного типа и не требует ручного приведения при получении элемента.

**Пример:**

```java
List<String> names = new ArrayList<>();

names.add("Petya");
names.add("Olya");

String firstName = names.get(0);
```

---

## Компиляция

**Определение:**

Компиляция — это этап, на котором Java проверяет исходный код и преобразует его в байт-код.

Для generics важно, что многие ошибки типов обнаруживаются именно на этапе компиляции.

Это лучше, чем узнать об ошибке уже после запуска программы.

**Пример:**

```java
List<String> names = new ArrayList<>();

names.add(100);
```

Такой код не пройдёт компиляцию.

---

## Время выполнения

**Определение:**

Время выполнения — это этап, когда программа уже запущена и выполняется JVM.

Ошибки, которые не были обнаружены на этапе компиляции, могут проявиться во время выполнения.

Raw type и ручные приведения типов повышают риск ошибок именно во время выполнения.

**Пример:**

```java
List list = new ArrayList();

list.add(100);

String value = (String) list.get(0);
```

Такой код может скомпилироваться, но упадёт во время выполнения с `ClassCastException`.

