# Тема 3: Абстракции и интерфейсы

## Абстракция

**Определение:**

Абстракция — это принцип ООП, при котором мы выделяем только важные свойства и поведение объекта, скрывая лишние детали реализации.

В Java абстракция помогает описать общий смысл объекта, не создавая конкретную реализацию сразу.

Например, `Transport` — это общее понятие транспорта. Мы понимаем, что транспорт может перевозить пассажиров, но конкретно машина едет, корабль плывёт, а велосипед катится.

**Пример:**

```java
public abstract class Transport {
    public abstract void transfer(String passengerName, String from, String to);
}
```

---

## Абстрактный класс

**Определение:**

Абстрактный класс — это класс, от которого можно наследоваться, но нельзя создать его объект напрямую.

Он объявляется с помощью ключевого слова `abstract`.

Абстрактный класс используют, когда нужно создать общую основу для нескольких похожих классов.

Абстрактный класс может содержать:

* поля;
* конструкторы;
* обычные методы;
* абстрактные методы.

**Пример:**

```java
public abstract class Transport {
    private int fuel;

    public Transport(int fuel) {
        this.fuel = fuel;
    }

    public void spendFuel(int fuel) {
        this.fuel -= fuel;
    }

    public abstract void transfer(String passengerName, String from, String to);
}
```

---

## abstract

**Определение:**

`abstract` — это ключевое слово Java, которое используется для объявления абстрактного класса или абстрактного метода.

Если класс объявлен как `abstract`, объект этого класса нельзя создать через `new`.

Если метод объявлен как `abstract`, у него нет тела, и дочерний класс обязан реализовать этот метод.

**Пример:**

```java
public abstract class Transport {
    public abstract void transfer(String passengerName, String from, String to);
}
```

---

## Абстрактный метод

**Определение:**

Абстрактный метод — это метод без тела, который объявлен в абстрактном классе или интерфейсе.

Он описывает, что объект должен уметь делать, но не описывает, как именно он должен это делать.

Реализацию абстрактного метода должен дать дочерний класс.

**Пример:**

```java
public abstract class Transport {
    public abstract void transfer(String passengerName, String from, String to);
}
```

Метод `transfer()` есть, но реализации нет.

---

## Реализация метода

**Определение:**

Реализация метода — это конкретный код внутри метода, который выполняет действие.

Если в абстрактном классе метод только объявлен, то в дочернем классе этот метод должен получить реализацию.

**Пример:**

```java
public class Car extends Transport {

    public Car() {
        super(100);
    }

    @Override
    public void transfer(String passengerName, String from, String to) {
        System.out.println(passengerName + " поехал на машине из " + from + " в " + to);
        spendFuel(10);
    }
}
```

---

## Нереализованный метод

**Определение:**

Нереализованный метод — это метод, который объявлен, но не содержит конкретной логики выполнения.

В обычном классе такой метод сделать нельзя.

В абстрактном классе нереализованный метод объявляют через `abstract`.

Так Java заставляет дочерние классы реализовать нужное поведение.

**Пример:**

```java
public abstract class Transport {
    public abstract void transfer(String passengerName, String from, String to);
}
```

---

## Запрет создания объекта

**Определение:**

Запрет создания объекта — это свойство абстрактного класса, из-за которого нельзя создать экземпляр этого класса через `new`.

Это нужно, когда класс существует только как общая основа для наследников.

Например, объект `Transport` сам по себе слишком общий. В реальности мы создаём конкретный транспорт: `Car`, `Ship`, `Velo`.

**Пример:**

```java
public abstract class Transport {
}
```

Так нельзя:

```java
Transport transport = new Transport();
```

Так можно:

```java
Transport transport = new Car();
```

---

## Обязательная реализация метода

**Определение:**

Обязательная реализация метода — это правило, при котором дочерний класс должен реализовать абстрактные методы родителя.

Если дочерний класс не реализует абстрактный метод, он тоже должен быть объявлен как `abstract`.

Это защищает программу от ситуации, когда метод вроде бы есть, но при вызове ничего полезного не делает.

**Пример:**

```java
public abstract class Transport {
    public abstract void transfer(String passengerName, String from, String to);
}

public class Ship extends Transport {

    public Ship() {
        super(500);
    }

    @Override
    public void transfer(String passengerName, String from, String to) {
        System.out.println(passengerName + " поплыл на корабле из " + from + " в " + to);
        spendFuel(50);
    }
}
```

---

## Интерфейс

**Определение:**

Интерфейс — это тип в Java, который описывает набор действий, которые класс должен уметь выполнять.

Интерфейс отвечает на вопрос: **что объект умеет делать?**

Класс, который реализует интерфейс, обязан реализовать его абстрактные методы.

Интерфейс удобен, когда разные по природе классы должны иметь общее поведение.

Например, машину, корабль и велосипед можно объединить не по наличию топлива, а по способности перевозить пассажира.

**Пример:**

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}
```

---

## interface

**Определение:**

`interface` — это ключевое слово Java, которое используется для объявления интерфейса.

Интерфейс не создаёт объект напрямую, а задаёт контракт для классов, которые его реализуют.

Методы интерфейса без тела по умолчанию являются `public abstract`.

**Пример:**

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}
```

---

## Контракт

**Определение:**

Контракт — это набор правил, которые класс обязуется выполнить.

В Java интерфейс часто называют контрактом, потому что он говорит: если класс реализует этот интерфейс, значит в нём точно будут определённые методы.

Например, если класс реализует `Transferer`, значит у него точно есть метод `transfer()`.

**Пример:**

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}

public class Velo implements Transferer {
    @Override
    public void transfer(String passengerName, String from, String to) {
        System.out.println(passengerName + " прокатился на велосипеде из " + from + " в " + to);
    }
}
```

---

## implements

**Определение:**

`implements` — это ключевое слово Java, которое используется, когда класс реализует интерфейс.

После `implements` указывается имя интерфейса.

Если класс реализует интерфейс, он обязан реализовать его методы, если только сам класс не является абстрактным.

**Пример:**

```java
public class Velo implements Transferer {

    @Override
    public void transfer(String passengerName, String from, String to) {
        System.out.println(passengerName + " прокатился на велосипеде");
    }
}
```

---

## Реализация интерфейса

**Определение:**

Реализация интерфейса — это создание класса, который подключает интерфейс через `implements` и пишет код для всех обязательных методов.

Интерфейс задаёт правило, а класс показывает конкретное поведение.

**Пример:**

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}

public class Car implements Transferer {

    @Override
    public void transfer(String passengerName, String from, String to) {
        System.out.println(passengerName + " поехал на машине из " + from + " в " + to);
    }
}
```

---

## Множественная реализация интерфейсов

**Определение:**

Множественная реализация интерфейсов — это возможность класса реализовать сразу несколько интерфейсов.

В Java класс может наследоваться только от одного класса, но может реализовывать много интерфейсов.

Это позволяет добавить классу несколько разных «способностей».

**Пример:**

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}

public interface Billable {
    void pay(int amount);
}

public class Taxi implements Transferer, Billable {

    @Override
    public void transfer(String passengerName, String from, String to) {
        System.out.println(passengerName + " едет на такси");
    }

    @Override
    public void pay(int amount) {
        System.out.println("Оплачено: " + amount);
    }
}
```

---

## Поведение

**Определение:**

Поведение — это то, что объект умеет делать.

В Java поведение обычно выражается через методы.

Интерфейсы чаще всего описывают именно поведение, а не внутреннее состояние объекта.

Например, интерфейс `Transferer` говорит, что объект умеет перевозить, но не говорит, есть ли у него топливо, колёса или двигатель.

**Пример:**

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}
```

---

## Состояние объекта

**Определение:**

Состояние объекта — это данные, которые объект хранит внутри себя.

В Java состояние обычно хранится в полях класса.

Например, у транспорта может быть количество топлива.

Абстрактный класс может хранить состояние, а интерфейс в классическом смысле состояние объекта не хранит.

**Пример:**

```java
public abstract class Transport {
    private int fuel;

    public Transport(int fuel) {
        this.fuel = fuel;
    }
}
```

---

## Абстрактный класс как основа иерархии

**Определение:**

Абстрактный класс как основа иерархии — это родительский класс, который содержит общую логику и состояние для похожих классов.

Например, `Transport` подходит как абстрактный класс для транспорта, которому нужно топливо.

Машина и корабль похожи по тому, что оба используют топливо, поэтому могут наследоваться от `Transport`.

**Пример:**

```java
public abstract class Transport {
    private int fuel;

    public Transport(int fuel) {
        this.fuel = fuel;
    }

    public void spendFuel(int fuel) {
        this.fuel -= fuel;
    }

    public abstract void transfer(String passengerName, String from, String to);
}
```

---

## Интерфейс как способность

**Определение:**

Интерфейс часто используют для описания способности объекта.

Например, `Transferer` можно понимать как «тот, кто умеет перевозить».

Такой интерфейс может реализовать и машина, и корабль, и велосипед, даже если внутри они устроены совершенно по-разному.

**Пример:**

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}

public class Velo implements Transferer {
    @Override
    public void transfer(String passengerName, String from, String to) {
        System.out.println(passengerName + " едет на велосипеде");
    }
}
```

---

## Проблема ромбовидного наследования

**Определение:**

Проблема ромбовидного наследования — это ситуация, когда класс наследуется от двух классов, у которых есть общий родитель.

Если оба родителя по-разному переопределили один и тот же метод, становится непонятно, какую версию метода должен получить дочерний класс.

Java запрещает наследоваться от нескольких классов, чтобы избежать такой неоднозначности.

Если нужно похожее поведение от разных источников, обычно используют интерфейсы.

**Пример:**

```java
class A {
    public void print() {
        System.out.println("A");
    }
}

class B extends A {
    @Override
    public void print() {
        System.out.println("B");
    }
}

class C extends A {
    @Override
    public void print() {
        System.out.println("C");
    }
}
```

Если бы Java разрешила такое:

```java
class D extends B, C {
}
```

Было бы непонятно, какой метод `print()` использовать: из `B` или из `C`.

---

## Множественное наследование

**Определение:**

Множественное наследование — это возможность класса наследоваться сразу от нескольких классов.

В Java множественное наследование классов запрещено.

Один класс может иметь только одного родителя через `extends`.

Но класс может реализовать несколько интерфейсов через `implements`.

**Пример:**

Так нельзя:

```java
public class Taxi extends Car, PaymentMachine {
}
```

Так можно:

```java
public class Taxi implements Transferer, Billable {
}
```

---

## Отличие абстрактного класса от интерфейса

**Определение:**

Абстрактный класс используют, когда нужно описать общую основу для похожих классов: общее состояние, общие методы и обязательные методы для наследников.

Интерфейс используют, когда нужно описать способность или контракт, который могут выполнять разные классы, даже если они не похожи друг на друга.

Главное отличие:

* абстрактный класс отвечает на вопрос: **что это такое?**
* интерфейс отвечает на вопрос: **что это умеет делать?**

**Пример:**

```java
public abstract class Transport {
    private int fuel;

    public Transport(int fuel) {
        this.fuel = fuel;
    }

    public void spendFuel(int fuel) {
        this.fuel -= fuel;
    }
}
```

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}
```

---

## Абстрактный класс с интерфейсом

**Определение:**

Абстрактный класс может реализовывать интерфейс.

Это удобно, когда нужно объединить контракт интерфейса с общей логикой и состоянием родительского класса.

Например, `Transport` может быть абстрактным классом и одновременно реализовывать интерфейс `Transferer`.

**Пример:**

```java
public interface Transferer {
    void transfer(String passengerName, String from, String to);
}

public abstract class Transport implements Transferer {
    private int fuel;

    public Transport(int fuel) {
        this.fuel = fuel;
    }

    public void spendFuel(int fuel) {
        this.fuel -= fuel;
    }
}
```
